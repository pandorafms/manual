    Autenticación externa y centralización de accesos¶

    Pandora FMS trae su propia autenticación, pero casi nadie la usa en producción: lo normal es delegarla en el directorio de la empresa. El capítulo cuenta los métodos disponibles, campo por campo, y qué cambia cuando por encima hay un Command Center.

    Todo se configura en Gestión → Ajustes → Configuración del sistema → Autentificación (Management → Settings → System Settings → Authentication). Hay cuatro métodos, y una regla que se repite en todos ellos: los administradores (superadmin) se autentican siempre contra la base de datos local. Es el seguro que evita quedarse fuera si el directorio se cae.

    Autenticación local y externa¶

    El método de autenticación (Authentication method) se elige en un desplegable:

    Método Qué es
    Local Pandora FMS La autenticación por defecto, contra la base de datos interna
    LDAP Delegada en un servidor LDAP
    Directorio activo (Active directory) Delegada en Active Directory. Enterprise
    SAML Delegada en un proveedor de identidades SAML. Enterprise

    Dos campos valen para casi todos los métodos externos:

    • Alternativa si falla la autentificación (Fallback to local authentication). Si se activa, cuando el sistema externo no valida al usuario se intenta la autenticación local. Los administradores lo tienen siempre activo, quieran o no.
    • Crear usuarios remotos automáticamente (Autocreate remote users). Si se activa, Pandora FMS da de alta al usuario la primera vez que inicia sesión contra el directorio, sin crearlo a mano.

    Autenticación local¶

    Es la de fábrica: usuario y contraseña contra la base de datos interna de Pandora FMS. No hay nada que configurar salvo elegirla como método. Es la que usan los administradores y la que sirve de respaldo cuando el directorio no responde.

    LDAP¶

    Antes de nada, la dependencia: hacen falta las utilidades de OpenLDAP en el servidor, que se instalan con el paquete de la distribución (ldap-utils en Debian/Ubuntu, openldap* en RHEL).

    Los campos de la conexión:

    Campo Para qué
    Servidor LDAP y Servidor LDAP secundario Dirección del servidor, directa (x.x.x.x) o por URL (ldap://…, ldaps://…)
    Puerto LDAP Puerto del servidor (389 por defecto)
    Versión LDAP Versión del protocolo
    Start TLS Cifra la comunicación entre cliente y servidor
    DN base Punto de partida de las búsquedas
    Atributo de acceso (Login attribute) Atributo por el que se identifica al usuario. Distingue mayúsculas de minúsculas
    Inicio de sesión de administrador LDAP y Contraseña de administrador LDAP Credenciales de una cuenta con permiso para consultar el directorio
    Tiempo de espera de búsqueda LDAP (segundos) Cuánto espera la búsqueda antes de rendirse
    Habilitar LDAP secundario Activa un segundo servidor, con sus propios servidor, puerto, versión, Start TLS, DN base, atributo de acceso y credenciales de administrador

    Dos decisiones que cambian el comportamiento:

    • Función LDAP (LDAP function). Elige cómo se hacen las búsquedas: Local command, que usa el comando ldapsearch del sistema, o PHP function, el motor propio de la consola. Para directorios con muchos elementos, la consola recomienda el comando local.
    • Identificar atributo de usuario (Login user attribute). Qué atributo del directorio se toma como identificador del usuario (por ejemplo, el correo).

    Y para la creación automática de usuarios:

    • Guardar contraseña (Save Password). Guarda la contraseña del directorio en la base local. Si el fallback local estaba activado, esto viene activado también.
    • Forzar creación automática de perfil de usuario y, debajo, Autocreación de perfil, de grupo y de etiquetas, para decidir con qué permisos nace el usuario recién creado, y Jerarquía no asignada automáticamente (Automatically assigned no hierarchy).
    • Crear una lista negra automáticamente (Autocreate blacklist). Una lista de usuarios separados por comas que no se crearán solos.
    • Búsqueda recursiva de grupos (Recursive group search).

    Si se activa Configuración LDAP avanzada (Advanced Config LDAP) aparecen Permisos LDAP avanzados, donde se añaden reglas con perfil, grupos y etiquetas ligadas a un filtro de atributos. Los atributos se escriben con el formato Nombre_atributo = Valor_atributo: si el usuario cumple alguno, se crea con ese perfil.

    Active Directory¶

    Es la variante de LDAP para Active Directory, y es Enterprise. Comparte concepto, pero con sus campos propios:

    • Servidor de directorio activo, Puerto del directorio activo (389 por defecto), Start TLS y Dominio (Domain). Si usas la configuración avanzada, en el dominio hay que poner la ruta LDAP completa, del estilo ldap://addc.midominio.
    • Habilitar directorio activo secundario, con su servidor, puerto, Start TLS, dominio y Tiempo de espera de búsqueda AD (segundos) (5 por defecto).
    • Guardar contraseña, Configuración avanzada AD y Permisos avanzados de AD, con la misma idea de reglas por atributos que en LDAP.
    • Auto-habilitar acceso al nodo (Auto enable node access): «los usuarios nuevos podrán conectarse en los nodos».
    • Búsqueda recursiva de grupos y Crear una lista negra automáticamente.

    Un detalle que no es de Pandora FMS, pero explica muchas llamadas: Windows permite usar la contraseña antigua durante 60 minutos tras un cambio en Active Directory. Eso lo controla Windows, no la consola.

    Doble autenticación (2FA)¶

    La doble autenticación añade un segundo factor además de la contraseña. En la configuración global de autenticación hay tres ajustes:

    • Doble autentificación (Double authentication). Habilita la opción para que los usuarios puedan activarla.
    • Forzar 2FA para todos los usuarios (Force 2FA for all users is enabled). Obliga a todo el mundo a usarla.
    • Nombre para mostrar en la autenticación de la aplicación. El nombre que verá el usuario en su app de códigos, para no confundir Pandora FMS con otros servicios. Merece la pena ponerlo.

    Cada usuario la activa en Operación → Área de trabajo → Editar mi usuario.

    Necesita una app generadora de códigos (Google Authenticator y similares) en su propio móvil, y que el servidor y el móvil tengan la hora sincronizada; sin eso, los códigos no cuadran.

    Para desactivarla a un usuario concreto sin pasar por la consola está el CLI:

    /usr/share/pandora_server/util/pandora_manage.pl /etc/pandora/pandora_server.conf \
    --disable_double_auth '<usuario>'

    SAML¶

    SAML es un estándar abierto de autenticación basado en XML: Pandora FMS actúa como proveedor de servicios y delega en un proveedor de identidades. Aquí también los administradores se autentican siempre contra la base local.

    Para usarlo hacen falta tres piezas: un servidor SAML operativo (SimpleSAMLphp), la configuración de Pandora FMS y, si el proveedor es Azure, la configuración del lado de Azure. El anexo técnico de SimpleSAMLphp cubre la instalación paso a paso; aquí van los campos de la parte de Pandora.

    Campo Para qué
    Ruta de SimpleSAML (SimpleSAML path) Directorio donde está instalado simplesamlphp
    SAML de origen (SAML source) Nombre del authsource configurado
    Atributo de ID de usuario SAML Atributo que se toma como identificador. El ID no puede llevar los caracteres > < " \ & / * ( ) º °` ni espacios
    Atributo de correo SAML Atributo con la dirección de correo (para la creación automática)
    Atributo de nombre de grupo SAML Atributo con el grupo (para la creación automática)
    Atributo simple/atributo con valores múltiples Si los atributos vienen como valor único o como lista
    Atributo de perfil y Atributo de etiqueta De dónde saca el perfil y la etiqueta del usuario
    Prefijo de perfiles y etiquetas SAML Prefijo para casar el valor del atributo con el perfil o la etiqueta

    Con SAML de configuración avanzada (Advanced Config SAML) aparecen SAML de permisos avanzados, con la misma mecánica de reglas por atributos que LDAP y AD.

    Sesiones y tokens de API¶

    Dos ajustes gobiernan cuándo se cierra una sesión:

    • Fin de la sesión (minutos) (Session timeout (mins)). Cuánto dura la sesión.
    • Sesión expirada (Session timeout based on). Sobre qué se cuenta el tiempo: el último inicio de sesión (se reinicia en cada login) o la inactividad del usuario (se reinicia con cada acción). Una pantalla abierta con autorrefresco no cuenta como inactividad.

    Aparte de la sesión, cada usuario tiene su API token, que se genera y se usa como bearer token en la cabecera HTTP para llamar a la API sin usuario y contraseña.

    Autenticación en un Command Center¶

    Cuando hay un Command Center, la administración de usuarios se lleva de forma centralizada, y eso afecta al login. Un usuario cuya autenticación no es local (AD, LDAP o SAML) necesita, para entrar en los nodos, o bien que se guarde su contraseña (Save Password) o bien que el nodo tenga activado Auto-habilitar acceso al nodo. Si no, el usuario existe en el nodo pero no puede entrar.

    La primera vez que un usuario centralizado accede a un nodo, la consola avisa de que hay que esperar a que el Command Center sincronice y volver a iniciar sesión con las mismas credenciales. Es el comportamiento normal, no un error.
