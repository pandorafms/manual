# Cloud environment monitoring

In the cloud there is no server on which to install an EndPoint: there is an
API. Pandora FMS queries it from Discovery with a read-only account and turns
what it finds into agents and modules, so each provider's instances,
databases, storage and costs appear in the web console like any other
monitored element.

| Provider | Services covered | Integration guides |
|---|---|---|
| Amazon Web Services | EC2 instances, RDS databases, S3 storage, CloudWatch metrics and pricing and costs. | [EC2](https://pandorafms.com/docs/integrations/latest/discovery/amazon-ec2/), [RDS](https://pandorafms.com/docs/integrations/latest/discovery/amazon-rds/), [S3](https://pandorafms.com/docs/integrations/latest/discovery/amazon-s3/), [CloudWatch](https://pandorafms.com/docs/integrations/latest/discovery/amazon-cloudwatch/), [Pricing](https://pandorafms.com/docs/integrations/latest/discovery/aws-pricing/) |
| Microsoft Azure | Virtual machines, SQL, storage, Application Gateway, Load Balancer and backups. | [Compute](https://pandorafms.com/docs/integrations/latest/discovery/azure-microsoft-compute/), [SQL](https://pandorafms.com/docs/integrations/latest/discovery/azure-sql/), [Storage](https://pandorafms.com/docs/integrations/latest/discovery/azure-storage/), [Application Gateway](https://pandorafms.com/docs/integrations/latest/discovery/azure-application-gateway/), [Load Balancer](https://pandorafms.com/docs/integrations/latest/discovery/azure-load-balancer/), [Backup](https://pandorafms.com/docs/integrations/latest/discovery/azure-backup/) |
| Google Cloud | Compute Engine instances. | [Compute Engine](https://pandorafms.com/docs/integrations/latest/discovery/google-cloud-compute-engine/) |
| OVHcloud | Public Cloud instances and volumes, dedicated servers and costs. | [OVH](https://pandorafms.com/docs/integrations/latest/discovery/ovh/) |
| DigitalOcean | Droplets and account usage. | [DigitalOcean](https://pandorafms.com/docs/integrations/latest/discovery/digital-ocean/) |

Each provider's service catalog grows and changes often, so this chapter does
not list it in detail: the guides in the table are the current reference for
what is monitored, the permissions each service needs and its parameters.
Installing a .disco package and the shared task lifecycle are covered in
[How a .disco package task works](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#how-a-disco-package-task-works).

Before creating a task, prepare a dedicated identity at the provider with
read-only permissions, limited to the services that will be queried. Store its
credentials in the [credential manager](2.2-gestor-de-credenciales.md) and do
not copy them into files or internal documentation. Check in each guide whether API
queries carry a cost or a quota at the provider.

## Amazon Web Services

Each AWS service has its own integration: EC2 for instances, RDS for
databases, S3 for buckets, CloudWatch for user-defined metric queries and
Pricing for public prices and billed costs. They authenticate with an AWS
access key tied to a user with read permissions. In general, each task
generates one agent per region and, optionally, a global agent with
statistics. Exact permissions and options for each service are in their
guides.

## Microsoft Azure

Azure is monitored by service: virtual machines, SQL databases, storage
accounts, Application Gateway, Load Balancer and backups. The integrations read
a subscription through a registered application with read access and obtain
metrics from Azure Monitor. You can choose between one agent per resource and
a consolidated agent, depending on each service's guide.

## Google Cloud

The Google Cloud integration monitors the Compute Engine instances of a project
and the zones that contain them, querying the Compute Engine and Cloud
Monitoring APIs with a service account. Requirements and parameters are in the
[Compute Engine guide](https://pandorafms.com/docs/integrations/latest/discovery/google-cloud-compute-engine/).

## OVHcloud and DigitalOcean

Both providers have their own integration that connects to their API. OVHcloud
covers Public Cloud instances and volumes, dedicated servers and, if desired,
costs. DigitalOcean covers droplets and account usage. Each guide explains how
to obtain the required API credentials and which agents the task generates.

## Results and first checks

After running the task:

1. Review execution errors and confirm that the read-only identity has enough
   permissions. A missing permission usually shows up as agents without
   modules, not as an obvious error.
2. Look for the expected agents: one global agent and several per region,
   resource or service, depending on the integration.
3. Check that modules receive recent data and compare a sample with the
   provider's own console.
4. Check, per the guide, whether API queries carry a cost or quota.

Service-specific diagnosis belongs to each service's guide. For task lifecycle
errors, see
[When it fails](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#when-it-fails).
