# User experience (UX) monitoring

Checking that a port responds does not tell you whether a user can log in,
search for a product or complete an order. User experience monitoring walks
through that flow as a person would, times it phase by phase and raises an
alert when it breaks or slows down. Pandora FMS does this with synthetic
transactions: a recorded or scripted journey that repeats on a schedule and
whose result is turned into agents and modules.

| Tool | What it automates | How it runs | Integration guide |
|---|---|---|---|
| **Playwright** (recommended for web) | A Playwright test that walks through a web application. | Discovery task; the test runs in a Docker container. | [Playwright](https://pandorafms.com/docs/integrations/latest/discovery/playwright/) |
| Selenium 4 | Web tests recorded with Selenium IDE. | Discovery task. | [Selenium 4](https://pandorafms.com/docs/integrations/latest/discovery/selenium-4/) |
| Oculix | Desktop applications or any interface, using screen images. | Server plugin. | [Oculix](https://pandorafms.com/docs/integrations/latest/plugins/oculix/) |

To monitor a web application, Playwright is the recommended option. Web
transactions are viewed in the **WUX Transactions** console extension,
described below. Selenium 4 remains available for those who already have
Selenium IDE recordings, and Oculix covers whatever is not web.

Installing a .disco package and the shared task lifecycle are covered in
[How a .disco package task works](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#how-a-disco-package-task-works).
The guides in the table provide each tool's requirements, installation,
parameters, modules, limitations and troubleshooting. This chapter only
explains which one to choose and where to look at the results.

## Playwright

Playwright is the preferred tool for web monitoring. The Discovery task runs a
single Playwright test inside a Docker container, and each phase of the test
becomes information that Pandora FMS times and displays. The test can be
recorded with Playwright's own tools, written by hand or generated with the
help of an AI agent; the
[Playwright guide](https://pandorafms.com/docs/integrations/latest/discovery/playwright/)
explains each route, how to split the test into phases and how to tune timeouts.

Results are viewed in the **WUX Transactions** console extension, available in
the operation menu of the web console. It gathers the discovered transactions
in a single view, with a summary of how many are passing, failing or without
data, the average time and, when the task has debugging enabled, the evidence
for each transaction. It is the best starting point to find out in which phase
a journey broke; its detailed behavior is covered in the guide.

## Selenium 4

The Selenium 4 integration runs web tests recorded with the Selenium IDE
browser extension against a real browser. It is set up through a Discovery task
and supports several execution modes, from a local driver to containers or a
remote Selenium server. It is a good option if a Selenium IDE test project
already exists and you want to reuse it. The
[Selenium 4 guide](https://pandorafms.com/docs/integrations/latest/discovery/selenium-4/)
covers the modes, requirements and parameters.

## Oculix

Oculix automates what a browser cannot reach: desktop applications, thick
clients or any interface that exists only on screen. It works through visual
image recognition and script execution, and generates monitoring modules. It is
not a Discovery task but a server plugin. Its preparation, compatibility and
setup are in the
[Oculix guide](https://pandorafms.com/docs/integrations/latest/plugins/oculix/).

## Results and first checks

A transaction is useful only if you can trust it. After the first run:

1. Confirm that the task ran without errors and that its agents and modules
   exist in the web console.
2. Check that the data is recent. With Playwright, open **WUX Transactions** and
   confirm that each transaction appears with its phases.
3. Repeat the journey by hand and compare your timings with the measured ones.
4. When something fails, tell apart a failing application from a failing
   transaction (a selector that changed, a timeout that is too short or an
   execution environment without access to the site). Failure evidence helps
   decide.

Tool-specific diagnosis lives in each tool's guide. For task lifecycle errors,
see [When it fails](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#when-it-fails).
