# Virtualized environment monitoring

In a virtualized environment, monitoring only the guest machines leaves the
layer that supports them in the dark: the hypervisor, the cluster, the storage
and the manager that coordinates them. Pandora FMS queries that layer through each
platform's APIs and generates agents
and modules for both the hosts and the virtual machines they run.

| Platform | Mechanism | Integration guide |
|---|---|---|
| VMware | Discovery task against vCenter. | [VMware](https://pandorafms.com/docs/integrations/latest/discovery/vmware/) |
| Proxmox | Discovery task against the cluster API. | [Proxmox](https://pandorafms.com/docs/integrations/latest/discovery/proxmox/) |
| Oracle VM | Plugin against the Oracle VM Manager REST API. | [Oracle VM](https://pandorafms.com/docs/integrations/latest/plugins/oracle-vm/) |
| KVM | Discovery task or agent plugin. | [KVM Discovery](https://pandorafms.com/docs/integrations/latest/discovery/kvm/), [KVM plugin](https://pandorafms.com/docs/integrations/latest/plugins/kvm/) |
| Hyper-V | Discovery task against the host through WinRM. | [Hyper-V](https://pandorafms.com/docs/integrations/latest/discovery/hyper-v/) |
| XenServer | Discovery task against XenServer. | [XenServer](https://pandorafms.com/docs/integrations/latest/discovery/xenserver/) |

The guides in the table are the current reference for which resources each
integration generates, the permissions it needs and its parameters; they change
with the product, so this chapter does not repeat them. Installing a .disco
package and the shared task lifecycle are covered in
[How a .disco package task works](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#how-a-disco-package-task-works).

Before configuring, prepare a dedicated account on the platform with the read
permissions the guide specifies, check that the machine running the task can
reach the manager or hypervisor, and store the credentials in the
[credential manager](2.2-gestor-de-credenciales.md).

## VMware

The integration connects to a vCenter server and discovers the resources of a
datacenter: the datacenter itself, its ESXi hosts and the virtual machines,
with availability, capacity, configuration and performance modules. Selection
options and the detail of what is generated are in the
[VMware guide](https://pandorafms.com/docs/integrations/latest/discovery/vmware/).

## Proxmox

Discovery connects to a Proxmox VE cluster through its API and generates one
agent per discovered resource: nodes, virtual machines and the other resources
detailed in the [Proxmox guide](https://pandorafms.com/docs/integrations/latest/discovery/proxmox/).

## Oracle VM

Unlike the previous ones, Oracle VM is monitored with a plugin that reads the
Oracle VM Manager REST API. Each run turns the state of the manager and of what
it manages (pools, servers, virtual machines and storage) into agents and
modules. Installation and setup are in the
[Oracle VM guide](https://pandorafms.com/docs/integrations/latest/plugins/oracle-vm/).

## KVM, Hyper-V and XenServer

KVM can be monitored with a Discovery task, which reads the hypervisors over SSH
or locally, or with an agent plugin; the two guides say when each fits. Hyper-V
is queried remotely through WinRM with read-only queries. XenServer is queried
through its API. In all three cases, the host and its virtual machines appear
as agents; see each platform's guide for requirements and options.

## Results and first checks

After running the task or plugin:

1. Review execution errors and confirm that the platform account can read what
   you want to monitor.
2. Look for the manager or host agents and the virtual machine agents, and check
   that they receive recent data.
3. Compare a sample of values with the platform's own console.
4. Remember that the agent of a discovered virtual machine does not replace an
   EndPoint inside the guest operating system: it measures what the hypervisor
   sees, not what happens inside the machine.

Platform-specific diagnosis belongs to each platform's guide. For task
lifecycle errors, see
[When it fails](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#when-it-fails).
