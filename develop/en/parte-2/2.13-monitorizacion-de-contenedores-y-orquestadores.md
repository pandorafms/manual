# Container and orchestrator monitoring

Docker is monitored through a plugin executed by an EndPoint. Kubernetes and
OpenShift are queried by Discovery through the cluster API. The collection
method determines where to configure the integration and where to look for its
results in the Pandora FMS web console.

| Target | Collection and results | Integration guide |
|---|---|---|
| Docker | The EndPoint executes the plugin and adds modules to its existing agent. | [Docker](https://pandorafms.com/docs/integrations/latest/plugins/docker/) |
| Kubernetes | Discovery queries the API and generates agents and modules according to the task. | [Kubernetes](https://pandorafms.com/docs/integrations/latest/discovery/kubernetes/) |
| OpenShift | Discovery queries the API and generates agents and modules according to the task. | [OpenShift](https://pandorafms.com/docs/integrations/latest/discovery/openshift/) |

Installing a .disco package and the shared task lifecycle are covered in
[How a .disco package task works](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#how-a-disco-package-task-works).
The guides in the table provide each integration's specific requirements,
permissions, setup, parameters, modules, limitations and troubleshooting.

Before configuration, check target access from the machine that will collect
the data and authorize only the necessary queries. Protect credentials. Review
the connection and security conditions in the relevant guide: HTTPS alone does
not establish that server identity is verified or requests are authenticated.

## Docker

The Docker plugin collects container usage and performance statistics, such as
CPU, memory, network and block I/O. It is a conventional EndPoint plugin, not a
Discovery task. Its modules are included in the EndPoint's existing agent.
It does not create a separate agent per container.

Follow the [Docker guide](https://pandorafms.com/docs/integrations/latest/plugins/docker/)
to prepare the plugin and integrate it with the EndPoint. Check daemon access
under the account and environment running the EndPoint, not only from an
administrator's interactive session. Then check in the web console that its
agent receives data from the integration.

## Kubernetes

Discovery queries the Kubernetes API to monitor cluster infrastructure and
workloads. The task generates agents and modules according to its scope and
the available data, without installing an EndPoint on every node.

Prepare the access and metrics required by the integration, configure the task
and check its first run. The
[Kubernetes guide](https://pandorafms.com/docs/integrations/latest/discovery/kubernetes/)
details that preparation, resource selection, results and limitations.
Shared Discovery operation is covered in 2.3. Plugin-specific fields and options
belong in its guide.

## OpenShift

The OpenShift integration also uses Discovery and the cluster API to collect
information about infrastructure and workloads. The agents and modules generated
depend on the task and the information obtained.

Prepare access and configure the integration according to the
[OpenShift guide](https://pandorafms.com/docs/integrations/latest/discovery/openshift/).
Do not transfer Kubernetes wizard fields and controls to this integration.
Each has its own configuration and limitations. After running the task, review
its results and the data received in the web console.

## Results and first checks

For Docker, check the EndPoint's agent. For Kubernetes and OpenShift, look for
the agents and modules generated by the task. The first check should cover both
collection and data reception:

1. Inspect execution errors and confirm that access uses the authorized
   identity and originates from the machine running the integration.
2. Find the expected results and check that they receive recent data.
   A summary reporting generated agents or manual plugin output alone does not
   prove that the data has reached Pandora FMS.
3. Compare representative values with the target. A missing module does not
   prove that the resource is absent, nor does a single indicator establish
   the health of the entire environment.

For missing information, use the integration's guide for specific troubleshooting.
For task lifecycle errors, see
[When it fails](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#when-it-fails).
Perform these checks in the environment that will be monitored.
