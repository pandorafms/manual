    Installation¶

    Installing Pandora FMS is the easy part of the project. The hard part is deciding what it runs on, what is left out and who remembers all this in two years. This chapter covers the installation of the product, its requirements and the decisions worth making before running the first command, not after.

    What will be installed¶

    The Pandora FMS online installer sets up the server, the Web console, the database and, optionally, a local EndPoint to monitor the server itself, all on a single machine. It is the monolith environment and it covers most cases.

    The components do not have to live together, and each piece is installed separately afterwards to adapt the architecture: a database on a dedicated server, OpenSearch aside, one or several satellites for remote networks, or several nodes coordinated from the Command Center. This section explains the standard installation, and the variants are in Personalisation of the automatic installation.

    The installable components of Pandora FMS are:

    • Server (pandora_server), with its database and the Tentacle server.
    • Web console (pandora_console).
    • EndPoint (pandora_agent and associated agents), on the machine to be monitored.
    • Satellite Server, a standalone server for remote networks.
    • OpenSearch, a log storage engine, optional.
    • Command Center (mf_server) and Cloud Server (cloud_server), for distributed environments.

    The full requirements for each component are further down, in Minimum requirements. Read them before you start, because they are the difference between an installation that lasts for years and one that gives its first scare after three months.

    Prerequisites¶

    Before launching the online installation:

    Requirement Detail
    Internet Access to the internet and to the official repositories of the distribution (RHEL / Rocky Linux / Ubuntu Server).
    curl Installed (it comes by default in almost every distribution).
    User root (or the equivalent with sudo).
    Operating system RHEL, Rocky Linux and AlmaLinux 9 or 10, or Ubuntu Server 22.04 or 24.04. More detail in Server requirements.
    Hardware Meet the minimum hardware requirements.
    RHEL 8 Licensed machine, subscribed to the standard repositories.

    Online installation of the server¶

    If the machine has internet, this is the recommended path, and the online installer sets up the full server environment in a single step.

    curl -SsL https://pfms.me/deploy_pandora_one | PANDORA_LTS=1 bash

    The tool is requested through the Pandora FMS website and it works with RHEL, Rocky Linux, AlmaLinux and Ubuntu Server. Red Hat is the recommended option, and the rest are supported with the versions given in the operating system table.

    The command above performs a full installation, and the installer also accepts environment variables to customise it (database passwords, MySQL and PHP version, LTS or Feature Release channel, specific packages, and so on). They are all listed further down, in Personalisation of the automatic installation.

    Online installation of the EndPoint¶

    The EndPoint is the program that lives inside the monitored machine and it is not mandatory (remote monitoring exists), but it is the only way to obtain maximum detail: processes, inventory, local logs.

    Linux¶

    The online installer works with Red Hat distributions (RHEL, Fedora, Rocky), SUSE/OpenSUSE and Debian/Ubuntu. It always installs from a TAR, never from an RPM, and it verifies that the downloaded package is an authentic EndPoint before configuring it against your server.

    Minimum installation (GO EndPoint, LTS version):

    export PANDORA_SERVER_IP='10.0.0.1'
curl -sSL https://pfms.me/agent-deploy | bash

    The installer accepts environment variables to automate the installation or choose the package. They are all listed further down, in Personalisation of the automatic installation.

    Supported architectures: x86_64 with binaries, while on x86, armv7l and aarch64 the script switches automatically to building from sources (PERL_SOURCES). On other architectures the process stops.

    MS Windows¶

    The EndPoint is delivered as a .exe self-installer, so for the online installation, run PowerShell as administrator:

    Invoke-WebRequest -Uri https://marketplace.pandorafms.com/pandorafms/LTS/PandoraFMS_One_Agent_Windows-lts.x86_64.exe -OutFile ${env:tmp}\pandora-agent-windows.exe; & ${env:tmp}\pandora-agent-windows.exe /S --ip [SERVER_IP] --group [GROUP] --remote_config 1

    And start the service:

    NET START PandoraFMSAgent

    The details of the manual and unattended installation are in Offline installation of the EndPoint.

    Installation of the satellite¶

    The Satellite Server is a headless server (no web interface) designed to discover and monitor remote networks that the Pandora FMS server cannot reach and where EndPoints cannot be installed either: network elements through SNMP/ICMP, Windows servers through WMI and Linux through SNMP. It runs up to 500 checks per second, it does not need a connection to the Pandora FMS database, and it sends the data as XML.

    Online installation¶

    Supported operating systems: EL10 (RHEL 10 / Rocky Linux 10, recommended option), Ubuntu Server 22.04 and Raspberry Pi OS (Debian 12+, with the specific package for Raspberry).

    export PANDORA_SERVER_IP='<IP or FQDN of the Pandora FMS Server>'
curl -Ls https://pfms.me/satellite-ent-deploy | bash

    The installer accepts environment variables (release channel, default group, remote configuration, agent installation, and so on), listed further down in Personalisation of the automatic installation.

    Compatibility

    Satellite Server 785 is not compatible with earlier versions of Pandora FMS, so install it alongside a 785 or later environment, or you will have features that appear but do not operate.

    Installation of OpenSearch¶

    Log collection is optional, and activating it requires an OpenSearch instance. It is not installed by default with the server: it is a separate deployment, and the recommendation is that it lives on a server independent from the Pandora FMS one.

    curl -SsL https://pfms.me/pandorafms-opensearch-el | bash

    The installer creates a node ready to use, with HTTPS and password authentication, and it is compatible with EL8, EL9 and Ubuntu 22.04 Server, and it accepts environment variables for the cluster name and the password, listed further down in Personalisation of the automatic installation.

    Check that the node responds:

    curl -X GET https://127.0.0.1:9200 -ku 'admin:<password>'

    Change this password too, and apply the same rule as with the database: what is published protects nothing.

    Minimum requirements¶

    Server requirements¶

    Hardware. The values are minimums, calculated assuming that 80% of the modules store historical data and an average sampling of five minutes, with server, console and database on the same machine:

    Hardware Small (≤ 1,000 modules) Medium (≤ 10,000) Large (≤ 30,000) Extra large (≤ 80,000)
    CPU 2 cores at 2 GHz 4 cores at 2.5 GHz 6 cores at 3 GHz 10 cores at 3 GHz
    RAM 4 GB 8 GB 16 GB 32 GB
    Storage 15K rpm or SSD ≥ 300 MB/s 15K rpm or SSD ≥ 300 MB/s SSD ≥ 300 MB/s SSD ≥ 300 MB/s
    Disk 40 / 60 GB 60 / 150 GB 120 / 250 GB 250 / 400 GB

    If information is stored for more than one month, a historical database has to be deployed.

    Virtualisation

    In virtual environments, assign the machine an independent disk with reserved space and high speed. Putting the database on a shared, thin volume is the most reliable way to get a bottleneck that nobody will locate for weeks.

    Above 80,000 metrics, a single node stops making sense, and it is time for distributed monitoring with multiple nodes (Command Center).

    Software.

    Software Requirements
    Operating system RHEL 10, Rocky Linux 10, RHEL 9 (recommended), Rocky Linux 9 (recommended), Ubuntu Server 22.04 and 24.04.
    Console PHP 8.4 from version 785, PHP 8.2 from 776 to 784, PHP 8 from 760 to 775, PHP 7.4 from 759 to 767 and PHP 7.2 from 729 to 758.
    Database Percona Server for MySQL 8 (recommended, especially above 4,000 agents), MySQL 8 or MySQL 8.4 from version 785.
    Browsers Chrome, Firefox, Opera and Edge. For interactive graphs and network maps, Firefox or Chrome.
    systemd Required since version 779. It comes installed and enabled on the supported OSs.

    EL10 and Ubuntu

    EL10 denotes the set of recommended systems: Rocky Linux 10, AlmaLinux 10 and Red Hat 10. Offline installation is not supported on Ubuntu Server, so do not choose it for a server without a connection, and for Command Center, avoiding Ubuntu is recommended.

    Each LTS version of Pandora FMS supports specific operating system versions, so consult the OS version support policy before deciding.

    Permissions.

    Requirement Detail
    Installation user The server is installed as root. During the installation a pandora user is created and assigned to the root group, and it can be changed afterwards, bearing in mind that the Tentacle server will have to be reconfigured. There is also the installation with an unprivileged user, with a separate procedure.
    Console Apache needs read and execute permissions on the console files. config.php must have 600 permissions.
    Server Write permissions on /var/spool/pandora/.

    EndPoint requirements¶

    The EndPoint can run on any machine with the minimum required operating system:

    Component Operating system
    Pandora EndPoint 4.0 or later RHEL 10 / Rocky Linux 10, RHEL 6.x, 8 and 9, Fedora 34, CentOS 6.x, 7 and 8, AlmaLinux, SLES 11 SP1 or later, OpenSUSE 11.x or later, Debian 5.x or later, Ubuntu Server or Desktop 11 or later, Linux Mint, Elementary OS, Manjaro, HPUX B.11.11 or later with Perl 5.8, AIX 4.3.3 or later with Perl 5.8, AIX 7.1 and 7.2, BSD (NetBSD, OpenBSD, FreeBSD) with Perl 5.8, MacOS X 10.6 or later, Solaris 8 or later with Perl 5.8, Windows NT4, XP, 2000, 2003, 2008, 7, 8, 10, 11, 2012, Server 2016 and Server 2019.
    Pandora Android EndPoint 2.0 or later Android 6 or later.
    Pandora Embedded EndPoint 4.0 or later Embedded devices, requires compilation.

    On *nix-type systems, systemd must be installed and started, and on UNIX environments, in addition:

    Requirement Detail
    Perl 5.8 or later.
    Dependencies perl-YAML-Tiny-1.73-2, perl-Sys-Syslog and unzip.
    logrotate Configured for the EndPoint (next block). 
    cat> /etc/logrotate.d/pandora_agent <<EO_LRA
/var/log/pandora/pandora_agent.log {
        su root apache
        weekly
        missingok
        size 300000
        rotate 3
        maxage 90
        compress
        notifempty
        copytruncate
}
EO_LRA
chmod 0644 /etc/logrotate.d/pandora_agent

    On Linux, the EndPoint runs as root to have all the features, and on Windows it runs with administrator permissions.

    Satellite requirements¶

    Satellite Details
    Hardware (Windows) x64, minimum 2 cores at 2 GHz (4 recommended), minimum 6 GB of RAM (8 recommended), minimum disk 5 GB (10 recommended).
    Hardware (Linux) x64, minimum 2 cores at 2 GHz (4 recommended), minimum 4 GB of RAM (6 recommended), minimum disk 5 GB (10 recommended).
    Operating systems 64-bit Linux, 64-bit MS Windows.
    Dependencies fping, nmap, perl, pandorawmic (version NG 762 or later) and libnsl, plus snmp for SNMP.

    On Rocky Linux 8 or later the EPEL repository has to be configured first, and on Windows, depending on the system version, Microsoft Visual C++ Redistributable has to be installed.

    OpenSearch requirements¶

    Requirement Detail
    Operating system Rocky Linux 8 / RHEL 8 / Ubuntu 22.04 (recommended).
    RAM Minimum 4 GB (dev/testing), 8 GB per instance recommended, although it has to be estimated according to the volume of data.
    CPU Minimum 4 cores.
    SWAP Disabled on the OpenSearch node or nodes.
    Storage 50 GB of system disk and 100 GB for OpenSearch.
    Connectivity From the Pandora FMS server and console to the OpenSearch API (9200/TCP) and between cluster nodes (9300/TCP).

    A single node with these characteristics stores up to 1 GB of daily data for 30 days. For greater redundancy and capacity, a cluster is configured (minimum 3 nodes to guarantee data integrity) and the load is spread with a load balancer such as Keepalived.

    SIEM requirements¶

    Requirement Detail
    OpenSearch OpenSearch database on a dedicated instance.
    Log collection Activated.
    Node resources Minimum 4 cores, 8 GB of RAM and 100 GB of SSD disk.
    SIEM instance A dedicated server is recommended for siemserver and siemevents.
    Licence With the SIEM feature enabled.

    Once the requirements are met, SIEM is activated from the console in Management → Settings → System Settings → SIEM → Activate SIEM. On saving, the normalisation templates are created in OpenSearch and siemserver and siemevents are enabled on the corresponding servers.

    Ports. The complete table. When the network team asks what to open, this is the list:

    Port Protocol Service Description Direction
    80 TCP Console Web administration and API Browser → Console
    80 TCP Console (API) API/CLI use Client → Console
    80 TCP Command Center Command Center ↔ Nodes communication Command Center ↔ Node
    162 UDP Server Trap reception Device → Server
    443 TCP Console (API) API/CLI use Client → Console
    443 TCP Command Center Command Center ↔ Nodes communication Command Center ↔ Node
    3306 TCP Console and Server Database connection Server → DB
    3306 TCP Command Center Node DB Command Center ↔ DB

    For standard monitoring, the server also needs outbound access to what it monitors: 80/TCP and 443/TCP for web monitoring (WUX), 161/UDP for SNMP polling and ICMP for network checks.

    Personalisation of the automatic installation¶

    Server and console¶

    Values for the online installer¶

    The basic run installs the full environment, and these environment variables customise it (values for RHEL and Rocky Linux):

    Variable Function Default
    TZ Machine time zone Europe/Madrid
    DBHOST Database host 127.0.0.1
    DBNAME Name of the database to create pandora
    DBUSER Database user pandora
    DBPASS User password Pandor4!
    DBPORT Database port 3306
    DBROOTPASS Database root password Pandor4!
    SKIP_PRECHECK Skip the previous installation check 0
    SKIP_DATABASE_INSTALL Do not install the database (use an external one) 0
    SKIP_KERNEL_OPTIMIZATIONS Skip kernel optimisation 0
    MYVER MySQL version (80 or 84) 80
    PHPVER PHP version (82 or 84) 84
    PANDORA_SERVER_PACKAGE URL of the server RPM latest available
    PANDORA_CONSOLE_PACKAGE URL of the console RPM latest available
    PANDORA_AGENT_PACKAGE URL of the agent RPM latest available
    PANDORA_BETA Install beta (1) 0
    PANDORA_LTS Install the LTS branch instead of Feature Release 1

    On Ubuntu Server the list is similar but does not include the package variables for the server, the console and the agent, and it adds POOL_SIZE to set the MySQL memory (by default it is calculated automatically).

    Example on EL10 with explicit values:

    env TZ='Europe/Madrid' \
    DBHOST='127.0.0.1' \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='ChangeThisPassword' \
    DBPORT='3306' \
    DBROOTPASS='ChangeThisRootPassword' \
    MYVER=84 \
    PHPVER=84 \
    SKIP_PRECHECK=0 \
    SKIP_DATABASE_INSTALL=0 \
    SKIP_KERNEL_OPTIMIZATIONS=0 \
    PANDORA_BETA=0 \
    PANDORA_LTS=1 \
    bash -c "$(curl -fsSL https://pfms.me/deploy_pandora_one)"

    Change the default passwords

    Pandor4! is written in the public documentation. It is the first one anyone who knows the way in will try. Leaving it in place is not an oversight. It is leaving the door open and putting out the doormat.

    Kernel optimisation values¶

    The online installer adjusts some kernel parameters. With SKIP_KERNEL_OPTIMIZATIONS=1 it does not touch them, but it is worth knowing what is lost: they are settings designed to let the server withstand many simultaneous connections without the operating system becoming the bottleneck.

    Parameter Default Set by Pandora What it does
    net.ipv4.tcp_syn_retries 5 3 Retries when sending a TCP connection request before giving it up as failed.
    net.ipv4.tcp_synack_retries 5 3 Retries when receiving the acknowledgement of a TCP connection.
    net.ipv4.tcp_max_syn_backlog 1024 65536 Maximum size of the queue of TCP connections pending acceptance.
    net.core.wmem_max 124928 8388608 Maximum send buffer for data per network connection.
    net.core.rmem_max 131071 8388608 Maximum receive buffer for data per network connection.
    net.core.somaxconn 128 1024 Pending connections in the socket listening queue.
    net.core.optmem_max 20480 81920 Maximum buffer for socket options.

    Do not touch them by hand unless you know exactly what you are doing, and leave SKIP_KERNEL_OPTIMIZATIONS=0 so the installer does its work.

    Installation on an external database¶

    If there is a dedicated server for the database, the path is: create the database and the user, give it all permissions on that database and install with SKIP_DATABASE_INSTALL=1 and the connection values. Before installing, test the connection from the future Pandora FMS server, because discovering the firewall at two in the morning is avoidable with five minutes of checking.

    env DBHOST='192.168.1.107' \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='ChangeThisPassword' \
    DBPORT='3306' \
    SKIP_DATABASE_INSTALL=1 \
    bash -c "$(curl -fsSL https://pfms.me/deploy_pandora_one)"

    Restrict the database user to the IP of the Pandora FMS server, so that if the password is compromised it does not work from anywhere else.

    External database installation for historical data¶

    To deploy a dedicated database (historical data included) there is an online installer of its own. It only requires curl and a compatible system:

    • EL9: Rocky Linux 9.x or RHEL 9.x.
    • EL10: Rocky Linux 10 or RHEL 10.
    • Ubuntu: 22.04.
    curl -fsSL https://pfms.me/db-deploy-el9 | bash

    On Ubuntu:

    curl -fsSL https://pfms.me/db-deploy-u2204 | bash

    Supported variables:

    Variable Description Default
    TZ Machine time zone Europe/Madrid
    MYVER MySQL version (8.0 or 8.4) 84
    DBNAME Name of the database to create pandora
    DBUSER Database user pandora
    DBPASS User password Pandor4!
    DBROOTPASS Root user password Pandor4!
    SKIP_KERNEL_OPTIMIZATIONS Skip kernel optimisations 0
    POOL_SIZE Memory for MySQL (buffer pool) Automatic 
    env TZ='Europe/Madrid' \
    MYVER=84 \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='ChangeThisPassword' \
    DBROOTPASS='ChangeThisRootPassword' \
    POOL_SIZE=4G \
    bash -c "$(curl -fsSL https://pfms.me/db-deploy-el9)"

    Installation in a different path¶

    To install the server in another path, the installer accepts --destdir:

    ./pandora_server_installer --install --destdir <destdir>

    Then automatic start-up and the pandora_db maintenance script have to be configured in cron:

    echo "\"<destdir>/usr/share/pandora_server/util/pandora_db\" \
 \"<destdir>/etc/pandora/pandora_server.conf\">/dev/null 2>&1"> /etc/cron.hourly/pandora_db

    Installation with an unprivileged user¶

    The installer can run with an unprivileged user:

    ./pandora_server_installer --install --no-root --destdir /opt/pandora

    That user must have write permissions on the path given in --destdir.

    EndPoint¶

    Values for the online installer¶

    Variable Function Default
    PANDORA_SERVER_IP IP or FQDN of the Pandora FMS server —
    PANDORA_AGENT_PACKAGE Package type: GO, PERL or PERL_SOURCES, or a direct URL GO
    PANDORA_AGENT_PACKAGE_TYPE Dependencies to install when the package is a URL GO
    PANDORA_AGENT_RELEASE Version: LTS (STABLE) or BETA STABLE
    PANDORA_SKIP_CONFIRMATION Unattended installation with no confirmations (1=yes) 0 
    export PANDORA_SERVER_IP='10.0.0.1' \
       PANDORA_AGENT_PACKAGE=GO \
       PANDORA_AGENT_RELEASE=STABLE \
       PANDORA_SKIP_CONFIRMATION=1
curl -sSL https://pfms.me/agent-deploy | bash

    Installation in a different path¶

    The EndPoint can be installed entirely in a defined directory: logs, configuration, binaries and man pages are left there.

    ./pandora_agent_installer --install /opt/pandora

    Installation with an unprivileged user¶

    It can also run with a user other than root, for example with the pandora user:

    ./pandora_agent_installer --install /home/pandora pandora

    When specifying a custom user, the installation must go to a location where that user has write permissions. The pandora user is disabled by default, so to use it, it has to be given a valid shell in /etc/passwd.

    Satellite¶

    Values for the online installer¶

    Variable Default Description
    PANDORA_SERVER_IP — Mandatory. IP or FQDN of the server the satellite points to.
    VERSION LATEST Installation channel: LATEST or LEGACY.
    TZ Europe/Madrid Time zone in IANA format.
    REMOTE_CONFIG 1 Configuration management from the console (1=yes).
    INSTALL_AGENT 1 Installs the EndPoint on the satellite itself (1=yes).
    PANDORA_GROUP Servers Default group of the satellite agents.
    SKIP_KERNEL_OPTIMIZATIONS 0 Omits the kernel performance settings (1=omit).
    RHEL_CHECK_SUBSCRIPTION 1 Verifies active subscriptions on RHEL (1=yes).
    PANDORA_SKIP_CONFIRMATION 0 Unattended installation with no confirmations (1=yes).
    PANDORA_BETA 0 Installs the development beta version (1=yes).
    SATELLITE_SERVER_PACKAGE Auto-selection Custom URL of the Satellite Server tarball. 
    env TZ='Europe/Madrid' \
    PANDORA_SERVER_IP='192.168.10.10' \
    VERSION='LATEST' \
    bash -c "$(curl -fsSL https://pfms.me/satellite-ent-deploy)"

    In addition, the manual installation requires setting the server_ip token in /etc/pandora/satellite_server.conf pointing to the Pandora FMS Server, and starting satellite_serverd. In Windows installations, the path must be given without quotes, because with quotes the installer does not interpret it correctly.

    Offline installation¶

    For environments without an internet connection, and it is not supported on Ubuntu.

    Offline installation of the server¶

    The compatible systems are RHEL 9 / Rocky Linux 9 and RHEL 10 / Rocky Linux 10.

    Steps:

    1. Have a clean instance with the hardware requirements and the supported operating system.
    2. Download the offline package for the operating system from the support portal (available for LTS and previous LTS versions).
    3. Upload the tarball to the server.
    4. Unpack it and run the installer:
    tar xvzf <offline_package>.tar.gz
cd pandora_packages/
./pandora_deploy_enterprise_local_el9.sh

    On EL10 the script is pandora_deploy_enterprise_local_el10.sh, and when the process finishes, the Web console is accessed with the admin user and the pandora password.

    Offline installation of the satellite¶

    Manual installation on Linux¶

    Once the dependencies are installed and the package downloaded, it is unpacked and the installer is run:

    tar -xvzf pandorafms_satellite_server_X.XNG.XXX_x86_64.tar.gz
cd satellite_server/
./satellite_server_installer --install

    Then /etc/pandora/satellite_server.conf has to be edited and the server_ip token set with the address of the Pandora FMS Server, and the service is started with:

    systemctl start satellite_serverd

    The log is in /var/log/satellite_server.log.

    Installation on MS Windows¶

    The installer (signed since version 762) includes Nmap and the Visual C++ Redistributable from MS Visual Studio 2015-2022. It is run with administrator rights, the licence is entered, the server address and the scanning rules are configured, and the machine is restarted. If WMI queries fail, the Satellite Server service has to be run with an Administrator account.

    Offline installation of the EndPoint¶

    The EndPoint is installed from the tarball package, valid for any Unix/Linux/macOS, and it does not require compilation.

    tar xvzf pandorafms_one_agent_linux-latest.tar.gz
cd unix
./pandora_agent_installer --install
systemctl start pandora_agent_daemon

    libnsl may have to be installed manually, and if the sources are used (.src.tar.gz), there are additional Perl dependencies, among them YAML::Tiny and Thread::Semaphore. On FreeBSD and NetBSD the file location and the start-up script change: the EndPoint stays in /usr/local/bin/pandora_agent, its script in /usr/local/etc/rc.d/pandora_agent, the configuration in /usr/local/etc/pandora/pandora_agent.conf, and pandora_agent_enable="YES" has to be added to /etc/rc.conf.

    After the installation, /etc/pandora/pandora_agent.conf has to be edited to point to the server and, as a recommendation, to activate remote configuration:

    sed -i "s/^remote_config.*$/remote_config 1/g" /etc/pandora/pandora_agent.conf
systemctl enable pandora_agent_daemon

    Unattended Windows¶

    The Windows installer supports unattended mode since EndPoint version 5.1:

    "PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S

    Custom path:

    "PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S /D=C:\PFMS_agent

    Parameters written to the EndPoint configuration: --ip (server_ip), --group (group), --alias (agent_alias) and --remote_config (remote_config). Example:

    "PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S --ip 192.168.0.59 --group Applications --alias Mifunne --remote_config 1

    Verification¶

    Once the installation is finished, open the console at http://<server>/pandora_console/ and confirm that it loads the login screen, where the initial user is admin with the pandora password.

    Warning

    Change the password on the first login, and if you installed with a custom user or a different path, check that the services start before you call it done. The fault that is not reviewed today turns into an incident on Monday.

    Uninstallation¶

    The installers are not copied during the installation, so their --uninstall cannot be used afterwards. Uninstallation has to be done by hand: these are the files and folders each component leaves behind and the commands to remove them (as root). If several components live together on the same machine, do not delete the shared directories until they have all been removed.

    Server¶

    • Binaries in /usr/bin: pandora_server, pandora_exec, pandora_supervisor, pandora_db, pandora_ha, pandora_manage, pandora_revent, pandora_encrypt_db, braa, pandorafsnmp, pandorawmic, pandora_iot_server, pandora_netflow_server, tentacle_server, tentacle_client, clean_pandora_server, clean_tentacle_serverd and clean_tentacle_rmm.
    • Libraries and utilities: /usr/share/pandora_server.
    • Services: /etc/systemd/system/pandora_server.service, pandora_ha.service, tentacle_serverd.service, tentacle_rmm.service, pandora_iot_server.service and pandora_netflow_server.service.
    • Tasks and rotation: /etc/cron.hourly/pandora_db and /etc/logrotate.d/pandora_server.
    • Configuration: /etc/pandora/pandora_server.conf, pandora_server.env, pandora_server_extra.env, /etc/pandora/conf.d and /etc/tentacle.
    • Data, logs and PID: /var/spool/pandora, /var/log/pandora and /var/run/pandora_supervisor.pid.
    systemctl stop pandora_server pandora_ha tentacle_serverd tentacle_rmm \
  pandora_iot_server pandora_netflow_server
systemctl disable pandora_server pandora_ha tentacle_serverd tentacle_rmm \
  pandora_iot_server pandora_netflow_server
rm -f /etc/systemd/system/{pandora_server,pandora_ha,tentacle_serverd,tentacle_rmm,pandora_iot_server,pandora_netflow_server}.service
systemctl daemon-reload
rm -f /usr/bin/{pandora_server,pandora_exec,pandora_supervisor,pandora_db,pandora_ha,pandora_manage,pandora_revent,pandora_encrypt_db,braa,pandorafsnmp,pandorawmic,pandora_iot_server,pandora_netflow_server,tentacle_server,tentacle_client,clean_pandora_server,clean_tentacle_serverd,clean_tentacle_rmm}
rm -Rf /usr/share/pandora_server
rm -f /etc/cron.hourly/pandora_db /etc/logrotate.d/pandora_server

    And, if no other component remains, the shared configuration and data:

    rm -Rf /etc/pandora /etc/tentacle /var/spool/pandora /var/log/pandora

    Console¶

    It depends on how it was installed:

    • RPM (RHEL / Rocky Linux): it is removed with the package manager.
    dnf remove pandorafms_console
    • Tarball (Ubuntu): it was copied to /var/www/html/pandora_console and it left its log rotation behind.
    rm -Rf /var/www/html/pandora_console
rm -f /etc/logrotate.d/pandora_console

    The console shares the /var/spool/pandora/data_in directory with the server (collections, conf, md5, netflow). Do not delete it if there is a server, and it does not touch the database, which goes separately.

    Database¶

    The installation creates the pandora database and the pandora user, and if MySQL or Percona only served Pandora FMS:

    systemctl stop mysqld
mysql -u root -p -e "DROP DATABASE pandora; DROP USER 'pandora'@'localhost';"
dnf remove 'Percona-Server*'        # RHEL/Rocky. On Ubuntu, apt remove percona-server-server or mysql-server
rm -Rf /var/lib/mysql /etc/my.cnf /etc/my.cnf.d

    If the database is on another server or holds data from other applications, limit the operation to DROP DATABASE and DROP USER.

    Satellite¶

    • Binaries in /usr/bin: satellite_server, tentacle_client, pandorafsnmp, wmic, pandorawmic and clean_satellite_serverd.
    • Configuration: /etc/pandora/satellite_server.conf, satellite_server.env, satellite_server_extra.env, /etc/pandora/satellite_plugins and the agents directory /etc/pandora/conf.
    • Start-up: /etc/init.d/satellite_serverd (with its link in /etc/rc.d) and /etc/systemd/system/satellite_serverd.service.
    • Rotation, logs and temporary files: /etc/logrotate.d/pandora_satellite, /var/log/satellite_server.log and /var/spool/pandora/tmp/satellite_server.
    systemctl stop satellite_serverd
systemctl disable satellite_serverd
rm -f /etc/systemd/system/satellite_serverd.service
systemctl daemon-reload
rm -f /etc/init.d/satellite_serverd
rm -f /etc/rc.d/rc?.d/S90satellite_server
rm -f /usr/bin/{satellite_server,tentacle_client,pandorafsnmp,wmic,pandorawmic,clean_satellite_serverd}
rm -Rf /etc/pandora/satellite_plugins /etc/pandora/conf /var/spool/pandora/tmp/satellite_server
rm -f /etc/pandora/satellite_server.conf /etc/pandora/satellite_server.env /etc/pandora/satellite_server_extra.env
rm -f /etc/logrotate.d/pandora_satellite /var/log/satellite_server.log

    The /opt/pandorafms/perl5 directory of the satellite is shared with other components, so delete it only if none remains installed.

    EndPoint¶

    On Linux and Unix it leaves:

    • Binaries in /usr/bin: pandora_agent, pandora_agent_exec, pandora_revent, tentacle_client and clean_pandora_agent_daemon.
    • EndPoint home: /usr/share/pandora_agent (plugins, collections, commands, ref).
    • Configuration: /etc/pandora/pandora_agent.conf and pandora_agent.env.
    • Start-up: /etc/systemd/system/pandora_agent_daemon.service (or the script in /etc/init.d).
    • Rotation, logs and man pages: /etc/logrotate.d/pandora_agent, /var/log/pandora/pandora_agent.log, /usr/share/man/man1/pandora_agent.1.gz and tentacle_client.1.gz.
    systemctl stop pandora_agent_daemon
systemctl disable pandora_agent_daemon
rm -f /etc/systemd/system/pandora_agent_daemon.service
systemctl daemon-reload
rm -f /usr/bin/{pandora_agent,pandora_agent_exec,pandora_revent,tentacle_client,clean_pandora_agent_daemon}
rm -Rf /usr/share/pandora_agent
rm -f /etc/pandora/pandora_agent.conf /etc/pandora/pandora_agent.env
rm -f /etc/logrotate.d/pandora_agent /var/log/pandora/pandora_agent.log
rm -f /usr/share/man/man1/pandora_agent.1.gz /usr/share/man/man1/tentacle_client.1.gz

    If there is a server or satellite on the same machine, do not delete /etc/pandora or /var/spool/pandora entirely.

    MS Windows does include an uninstaller, which in unattended mode runs like this:

    "%ProgramFiles%\pandora_agent\uninst.exe" /S

    Or from the EndPoint binary:

    pandoraagent.exe --uninstall
