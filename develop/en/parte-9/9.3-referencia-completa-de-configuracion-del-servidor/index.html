    Full server configuration reference¶

    Raw technical reference for pandora_server.conf: every token the server recognises, with its real default value. It is looked up, not read from cover to cover; any other chapter links here when it needs to refer to a server parameter.

    Introduction¶

    pandora_server.conf is the only configuration file of the Pandora FMS server. Its path is configurable at installation; by default, /etc/pandora/pandora_server.conf. The format is the usual one: one token per line, value after a space, and # to comment a whole line or to leave an example token disabled.

    A change in the file is not applied on the fly: the service has to be restarted.

    systemctl restart pandora_server

    The exception is remote configuration: with remote_config 1 (see "Remote configuration, Tentacle and synchronization", further down), the whole file can be edited from the web console. The server checks now and then whether there are changes; when it finds them, it generates a restart event, reloads the configuration and restarts itself.

    The tokens exclusive to the satellite servers (pandora_satellite.conf) are not in this reference: they have their own chapter, 6.2 · Satellite servers, which links here for what they share with the main server.

    The "default value" of each table is the one the server itself applies when the token does not appear in the file. The sample template shipped with the package (pandora_server.conf.new) does not always match that value: when it differs in a relevant way, the table says so explicitly, never as if it were "the" default value.

    2. Server activation and number of threads¶

    Each internal server has a switch (0/1) and, where it applies, a number of threads of its own. "Default" is, as in the rest of this chapter, the value the server itself assumes when the token does not appear in the file; the installation template (pandora_server.conf.new) may bring a different value for that same token. For example, discoveryserver comes enabled in the template although the internal default value is 0, and the other way round, snmpconsole comes disabled in the template although the internal default value is 1.

    Server Activation token Default Threads token Default
    Data (XML) dataserver 1 dataserver_threads 2
    Network (TCP, remote commands, WMI; ICMP and SNMP if the high-performance one is disabled) networkserver 1 network_threads 3
    High-performance network (ICMP with fping and SNMP with pandorafsnmp, in bulk) networkhpserver 1 networkhpserver_threads 4
    SNMP console snmpconsole 1 snmpconsole_threads 1
    SNMP (legacy: it no longer starts a server of its own; it only turns on the check that snmptrapd keeps receiving traps) snmpserver 0 snmp_threads 3
    ICMP (legacy: no effect; it is run by the high-performance network server) icmpserver 0 icmp_threads 3
    WMI (legacy: no effect; it is run by the network server) wmiserver 1 wmi_threads 2
    Plugin (legacy: no effect; it is run by the Heavy server) pluginserver 1 plugin_threads 2
    Discovery discoveryserver 0 discovery_threads 2
    Prediction (legacy: no effect; it is run by the network server) predictionserver 1 prediction_threads 1
    Export (legacy: no effect; it is run by the Heavy server) exportserver 1 export_threads 1
    Inventory (legacy: no effect; it is run by the Heavy server) inventoryserver 1 inventory_threads 2
    Web (legacy: no effect; it is run by the network server) webserver 1 web_threads 1

    Syslog syslogserver 0 syslog_threads 4

    RMM rmmserver 0 rmmserver_threads 1

    Netflow netflowserver 0 netflowserver_threads 1
    Recon (it is not a server of its own: alternative switch of the Discovery Server, it is enough that reconserver or discoveryserver are at 1; recon_threads does have an effect, the highest of this value and discovery_threads is used) reconserver no default value in the code (it behaves as disabled if it does not appear) recon_threads 2
    Provisioning provisioningserver 1 provisioningserver_threads 1
    MADE (anomaly detection) madeserver 0 madeserver_threads no value in the code; the template brings 2 (see "Additional server blocks")
    SIEM siemserver 0 siemserver_threads 4
    SIEM events siemevents 0 siemevents_threads 2
    Heavy (remote plugins, remote inventory, NCM and export) heavyserver 1 heavyserver_threads 4
    Synchronization (Tentacle/HA) syncserver 0 no threads of its own —

    The reason behind this distribution (why so many servers of their own disappeared and what each real server does today) is in Compatibility and migration to the new server architecture.

    12. Additional server blocks¶

    These servers have their switch and their threads in the table of the section "Server activation and number of threads"; the tokens in this table are those of each block, in addition to that switch:

    Block Own tokens Notes
    NCM ncm_ssh_utility SSH utility that avoids problems with Net::SSH::Expect in threaded environments.
    RMM rmmdir, agent_deployer_utility Exchange directory with the RMM agents; EndPoint deployment utility over SSH/WinRM.
    WUX (synthetic browsing) wux_host, wux_port, wux_browser, wux_webagent_timeout, clean_wux_sessions Uses Selenium Grid as engine; the default port is 4444.
    Netflow pandora_netflow_server_conf, pandora_netflow_server_address, pandora_netflow_server_port The rest of the Netflow configuration is managed from the web console, not in this file.
    SIEM / log collector siem_max_timeframe, siem_decoders, siem_events_rules, siem_max_hits_logs The rest (connection to the search engine) is managed from the web console.
    MADE (anomaly detection) madeserver_autofit, madeserver_backend, madeserver_interval, madeserver_max_history, madeserver_min_train, madeserver_path, madeserver_sensitivity, madeserver_threads They do not appear in the template as recognised by the general parser of the server: documented as the template describes them, pending verification by the team.
    Provisioning provisioning_cache_interval —
    Agent auto-provisioning autoconfigure_agents, autoconfigure_agents_threshold Used by the data server when processing the XML an EndPoint sends, not by Discovery; see Mecanismos de autoprovisión.
    GIS activate_gis, location_error, recon_location_scatter_radius, recon_reverse_geolocation_file, google_maps_description, openstreetmaps_description —

    13. Command Center¶

    pandora_server.conf does not have a block of tokens of its own for the Command Center: the relationship between a server and the Command Center is managed at console level (adding the node, synchronizing policies) and at database level, not in the server configuration file.

    Token What it does Default value
    node_metaconsole Marks whether the database this server points to is the one of a node managed by a Command Center. It is not an option edited by hand in the file. 0

    See 6.3 · Command Center for the procedure of adding and managing nodes.
