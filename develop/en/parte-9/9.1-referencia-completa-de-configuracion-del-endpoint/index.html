    Full EndPoint configuration reference¶

    Raw technical reference for pandora_agent.conf: every general token and every module token, with its compatibility by EndPoint (Go, Perl, Windows). It is looked up, not read from cover to cover. The explanations and the examples are in 2.1 · Monitoring with EndPoints, which this page links to.

    Introduction¶

    This reference gathers, table by table, every pandora_agent.conf token recognised by the three Pandora FMS EndPoints: the Go EndPoint, the Perl EndPoint (Linux/Unix) and the Windows EndPoint. For each token it states its description, its syntax or default value, and whether the Go EndPoint, the Perl EndPoint and the Windows EndPoint accept it.

    pandora_agent.conf is located in:

    EndPoint Path
    Go and Perl (Linux/Unix) /etc/pandora/pandora_agent.conf. Both use the same file at the same path. With an installation in a custom path, the configuration stays in <prefix>/etc/pandora/; on FreeBSD and NetBSD, the installer already uses /usr/local/etc/pandora.
    Windows C:\Program Files\pandora_agent\pandora_agent.conf

    The file syntax is the same in the three EndPoints: one token per line, comments with #, and module tokens grouped in module_begin / module_end blocks (except module_plugin, which can also go loose on a single line, outside any block). General tokens are valid anywhere in the file, outside a module block.

    For explanations, examples and the reason behind each token, see 2.1 · Monitoring with EndPoints.

    server_user Remote user for the FTP/SSH transfer modes. Text. pandora by default. Yes Yes No
    server_pwd Password for Tentacle (if the server requires it) or for FTP/SSH. Text. Empty by default. Yes Yes Yes
    server_ssl Turns on OpenSSL in the Tentacle client. yes/no or 1/0. 0/no by default (off). Yes Yes Yes
    server_opts Additional options added literally to the command line of the transfer client (for example -v -r 5 for Tentacle). Free text. Empty by default. Yes Yes Yes
    server_path Remote path (data_in) where the server waits for the data XML. Text. /var/spool/pandora/data_in by default. Yes Yes Yes
    server_path_conf Remote subdirectory used by remote configuration to drop the new .conf. Text. conf by default. Perl and Go only. Yes Yes No
    server_path_md5 Remote subdirectory used by remote configuration for the change control .md5. Text. md5 by default. Perl and Go only. Yes Yes No

    transfer_mode_user Owner user of the copied files when transfer_mode is local. Text. apache by default. Perl and Go only. Yes Yes No
    transfer_timeout Maximum time, in seconds, for the transfer program to complete the delivery before it is taken as failed. Integer. 30 by default. Yes Yes Yes

    Module structure¶

    Token Description Value / default Go Perl Windows
    module_begin Opens the definition of a module. Everything that follows up to module_end belongs to that module. No value. Yes Yes Yes
    module_end Closes the definition of a module started with module_begin. No value. Yes Yes Yes

    Token Description Value / default Go Perl Windows
    module_exec Runs a shell command; its standard output is the module datum. Shell command. Yes Yes Yes

    module_proc_cmd Redefines, for the whole file, the system command the proc/service module uses to list processes. Shell command. Perl and Go only. Yes Yes No
    module_freedisk_cmd Redefines, for the whole file, the system command the freedisk/freepercentdisk module uses to query the space. Shell command. Perl and Go only. Yes Yes No

    module_wmiquery WMI query whose result is the module datum (it is combined with module_wmicolumn). WMI query (SELECT … FROM …). Windows only. No No Yes
    module_wmicolumn Column of the module_wmiquery query taken as the value of the module. WMI column name. Windows only. No No Yes
    module_perfcounter Reads a Windows performance counter (the counter names are localised by the language of the system). Performance counter path (\object\counter). Windows only. No No Yes
    module_cooked Indicates that the value of module_perfcounter must be returned "cooked" (already calculated, not raw). 0/1. Windows only. No No Yes
    module_tcpcheck Checks whether a host accepts a TCP connection on the given port (module_port). Host or IP. Windows only. No No Yes
    module_port TCP port used by module_tcpcheck. Integer. Windows only. No No Yes
    module_ping Pings the given address. Host or IP. Windows only. No No Yes
    module_ping_count Number of ICMP packets to send in module_ping. Integer. 1 by default. Windows only. No No Yes
    module_ping_timeout Wait time, in milliseconds, of each packet of module_ping. Integer (ms). 1000 by default. Windows only. No No Yes
    module_snmpget SNMP GET query module. Turns the module on (it is combined with the module_snmp_* tokens). Windows only. No No Yes
    module_snmp_version SNMP version used by module_snmpget. Text/integer. 1 by default. Windows only. No No Yes
    module_snmp_community SNMP community used by module_snmpget. Text. public by default. Windows only. No No Yes
    module_snmp_agent Address of the SNMP agent queried by module_snmpget. Host or IP. localhost by default. Windows only. No No Yes
    module_snmp_oid OID queried by module_snmpget. OID. Windows only. No No Yes
    module_advanced_options Additional options passed literally to the internal executable of module_ping or module_snmpget. Free text. Windows only. No No Yes
    module_retries Number of retries before running module_start_command in a module_proc with watchdog. Integer. Windows only, and only with a process watchdog. No No Yes
    module_startdelay Wait, in seconds, before the first start attempt in the watchdog of a module_proc. Integer (seconds). Windows only, and only with a process watchdog. No No Yes
    module_retrydelay Wait, in seconds, between retries of the watchdog of a module_proc. Integer (seconds). Windows only, and only with a process watchdog. No No Yes
    module_user_session Runs module_start_command in the interactive session of the user, not in the service session. 0/1. Windows only, and only with a process watchdog. No No Yes
    module_wait_timeout Polling interval while a module_exec is still running: how often the EndPoint checks whether it has finished and reads its output. The total limit is set by module_timeout. Integer (milliseconds). 500 by default. Windows only. No No Yes

    Intervals and scheduling¶

    Token Description Value / default Go Perl Windows
    module_interval Multiplier of the agent interval: the module runs every module_interval cycles of interval (or of intensive_interval if it is intensive). Integer (number of cycles). 1 by default. Yes Yes Yes
    module_absoluteinterval Interval of the module in absolute time, independent of interval: it accepts the suffix s/m/h/d (seconds/minutes/hours/days), a number without suffix (multiples of interval) or once (a single time).     Conditions¶

    Token Description Value / default Go Perl Windows
    module_precondition Previous condition: it compares the output of a command of its own against the given operator and value; the module runs only if it is met.     Notable differences between EndPoints¶

    • Default XML encoding. Perl and Go use UTF-8; Windows uses ISO-8859-1 (see encoding).
    • A different name for the same concept. The start-up delay is called delayed_startup in Perl and Go, and startup_delay on Windows.
    • Token alias. module_service is an exact alias of module_proc on Unix (same process check); on Windows they are different built-ins (process vs. service), with watchdogs that behave differently.
    • Asymmetric watchdog. The Windows watchdog exists only for module_proc (it needs module_start_command, module_retries, module_startdelay, module_retrydelay, module_user_session) and for module_service (it restarts the service itself, without a recovery command). Neither Perl nor Go implements a watchdog.
    • Asynchronous module only on Windows. module_async exists only in the Windows EndPoint; Perl and Go derive the asynchronous type automatically when a module with module_absoluteinterval runs once.
    • Tokens with a variable name. module_macro<name> (module macros) and custom_field<n>_name / custom_field<n>_value are accepted by the three EndPoints; the general macros macro<name>, only by Perl and Go.
    • UDP server. It exists only in Perl and Windows (not in Go). The format of the orders differs: Perl accepts START PROCESS <name> / STOP PROCESS <name>; Windows requires exactly three words (<order> <action> <target>, for example REFRESH AGENT *, START PROCESS <name>, START SERVICE <name>), and it adds the control of services (service_<name>) that Perl does not have.
    • Remote configuration and transport. The Go EndPoint accepts only remote_config with transfer_mode tentacle or local; Perl accepts it with any transfer mode.
    • Windows-only tokens. All the built-in Windows query modules (module_wmiquery, module_perfcounter, module_snmpget, module_ping, module_tcpcheck, module_logevent/module_logchannel and their filters, module_inventory, module_exec_powershell), in addition to disable_logfile, default_native_encoding, startup_delay and udp_server_address.
    • Unix-only tokens (Perl and Go). module_cpuproc, module_memproc, module_occupiedpercentdisk, module_proc_cmd, module_freedisk_cmd, pandora_user, logfile/logsize/logrotate, cron_mode, agent_threads, cmd_file, include, timezone_offset, pandora_nice, transfer_mode_user and server_path_conf / server_path_md5 / server_path_zip.
    • Token only parsed, with no equivalent in the other two. server_path_ref exists only in the Perl EndPoint (reference directory of the remote configuration).
