# Full console configuration reference

This reference is not read from cover to cover: it is looked up by option name
or by tab, like a dictionary. It gathers the whole configuration of the Web
console (node and Command Center) and of `include/config.php`, so that any other
chapter can link here instead of repeating a table of options.

Where each thing lives:

- **Web console (Settings → System Settings).** Almost all the configuration of
  behavior, appearance and credentials of external services. It is stored in the
  database, not in a file: it changes on the fly, without restarting anything.
- **`include/config.php`.** A handful of values that are edited by hand only,
  before the console can connect to the database: database connection,
  installation path, encryption passphrase. See § 23.
- **Command Center.** A special console that centralizes several nodes. It has
  its own configuration pages (§ 22) and, in addition, it can set some settings
  of the nodes it manages centrally.

A node with "centralized management" active in a specific section stops
accepting local changes in that section: they are edited from the Command Center
and synchronized to the node.

### 1.7 Alerts configuration

Outgoing mail and Telegram used by the alerts.

| Option | What it does | Default value | Notes |
|---|---|---|---|
| OAuth2 (Microsoft/Google) | OAuth2 authentication of outgoing mail | Disabled | Fields: URL, Tenant ID, Client ID, Client Secret, Mail from, Client email, Token URI, Private Key |
| SMTP server / port / timeout | Connection to the outgoing mail server | Empty / `25` / depending on the installation | Encrypted password; see [9.5 · Database encryption](9.5-cifrado-de-la-base-de-datos.md) |
| Mail user and password | SMTP credentials | Empty | Encrypted password |
| Encryption | None, SSL or STARTTLS | None |  |
| SMTP authentication | Mechanism the server uses to authenticate against the mail server | `Default` (`DIGEST-MD5 CRAM-MD5 LOGIN`) | Values: `Default`, `LOGIN`, `PLAIN`, `CRAM-MD5` and `DIGEST-MD5`; hidden with OAuth2. It only affects mail sent by the server |
| From address and name | Sender of the emails | Empty |  |
| Telegram token | Replaces the alert macro that references the bot token | Empty |  |

The **SMTP authentication** option does not try the mechanisms one after
another. The Pandora FMS server uses the first one advertised by the mail
server and, if that one is rejected, delivery fails. A provider that
advertises `DIGEST-MD5` and then rejects it —Postmark is the case behind this
setting— requires choosing `LOGIN` by hand. `PLAIN` is left out of the default
because some servers answer with the error `451 4.5.0 SMTP protocol
violation`. The option only applies when mail is configured in the console;
if `pandora_server.conf` defines `mta_address`, the `mta_*` values in the file
take precedence and this setting does not apply.

### 1.8 Update

Email test form to validate the configuration of the previous tab without
leaving the page; it is not a configuration option. The test is sent by the
console, not by the server, and does not use the SMTP authentication mechanism
of § 1.7: a successful test does not guarantee that alerts will go out.

*See also:* [9.3 · Full server configuration
reference](9.3-referencia-completa-de-configuracion-del-servidor.md) § 11, for
the outgoing mail the server itself uses when running alerts.

### 22.3 What is synchronized from the node by the Command Center

"Centralized management" allows the Command Center to write the configuration
of a node, in addition to policies, advanced ACL and components, in a
synchronized way: the affected section of the node stops accepting local changes
while the centralized management is active (see the introduction to this
chapter). The exact detail of which sections are synchronizable is not verified
as of this writing; it will be expanded in a later revision of this chapter.
