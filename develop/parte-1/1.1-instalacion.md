# Instalación

Instalar Pandora FMS es la parte fácil del proyecto. Lo difícil es decidir sobre
qué se instala, qué se deja fuera y quién se acuerda de esto dentro de dos años.
Este capítulo cubre la instalación del producto, sus requisitos y las decisiones
que conviene tomar antes de ejecutar el primer comando, no después.

## Qué se va a instalar

El instalador en línea de Pandora FMS monta en una sola máquina el **servidor**,
la **consola web**, la **base de datos** y, opcionalmente, un **EndPoint local**
para monitorizar el propio servidor. Es el entorno *monolito* y cubre la mayoría
de los casos.

Los componentes no tienen por qué vivir juntos. La instalación individual de cada
pieza se hace a posteriori para adaptar la arquitectura: base de datos en un
servidor dedicado, OpenSearch aparte, uno o varios satélites para redes remotas o
varios nodos coordinados desde Command Center. Aquí se explica la instalación
estándar; las variantes están en la sección de [personalización de la instalación automática](#personalizacion-de-la-instalacion-automatica).

Los componentes instalables de Pandora FMS son:

- **Servidor** (`pandora_server`), con su base de datos y el servidor Tentacle.
- **Consola web** (`pandora_console`).
- **EndPoint** (`pandora_agent` y agentes asociados), en el equipo a monitorizar.
- **Satellite Server**, servidor autónomo para redes remotas.
- **OpenSearch**, motor de almacenamiento de logs, opcional.
- **Command Center**, para entornos distribuidos.

Los requisitos completos de cada componente están más abajo, en
[Requisitos mínimos](#requisitos-minimos). Léelos antes de empezar; son la
diferencia entre una instalación que aguanta años y una que da el primer susto a
los tres meses.

Antes de lanzar la instalación en línea:

| Requisito | Detalle |
|---|---|

| `curl` | Instalado (viene por defecto en casi todas las distribuciones). |
| Usuario | **root** (o equivalente con `sudo`). |

## Instalación online del servidor

Si la máquina tiene internet, este es el camino recomendado. El instalador en
línea monta el entorno completo del servidor en un solo paso.

```bash
curl -SsL https://pfms.me/deploy_pandora_one | PANDORA_LTS=1 bash
```

El script detecta la distribución, descarga el instalador que le corresponde y funciona con
**RHEL**, **Rocky Linux**, **AlmaLinux** y **Ubuntu Server**. Red Hat es la
opción recomendada; el resto está soportado con las versiones que marca la
[tabla de sistemas operativos](#requisitos-del-servidor).

La ejecución anterior hace una instalación completa. El instalador admite además
variables de entorno para personalizarla (contraseñas de base de datos, versión
de MySQL y PHP, canal LTS o Feature Release, paquetes concretos, etc.). Están
todas recogidas más abajo, en
[Personalización de la instalación automática](#personalizacion-de-la-instalacion-automatica).

## Instalación online del EndPoint

El EndPoint es el programa que vive dentro del equipo monitorizado. No es
obligatorio (existe monitorización remota), pero es la única forma de obtener el
máximo detalle: procesos, inventario, logs locales.

### Linux

El instalador en línea funciona con distribuciones Red Hat (RHEL, Fedora, Rocky),
SUSE/OpenSUSE y Debian/Ubuntu. **Siempre instala desde un TAR**, nunca desde un
RPM, y verifica que el paquete descargado sea un EndPoint auténtico antes de
configurarlo contra tu servidor.

Instalación mínima (agente GO, versión LTS):

```bash
export PANDORA_SERVER_IP='10.0.0.1'
curl -sSL https://pfms.me/agent-deploy | bash
```

El instalador admite variables de entorno para automatizar la instalación o
elegir el paquete. Están todas recogidas más abajo, en
[Personalización de la instalación automática](#personalizacion-de-la-instalacion-automatica).

Arquitecturas soportadas: `x86_64` con binarios. En `x86`, `armv7l` y `aarch64`
el script pasa automáticamente a compilación desde fuentes
(`PERL_SOURCES`). En otras arquitecturas el proceso se detiene.

### MS Windows

El EndPoint se entrega como autoinstalador `.exe`. Para la instalación en línea,
ejecuta PowerShell como administrador:

```powershell
Invoke-WebRequest -Uri https://marketplace.pandorafms.com/pandorafms/LTS/PandoraFMS_One_Agent_Windows-lts.x86_64.exe -OutFile ${env:tmp}\pandora-agent-windows.exe; & ${env:tmp}\pandora-agent-windows.exe /S --ip <IP_DEL_SERVIDOR> --group <GRUPO> --remote_config 1
```

Y arranca el servicio:

```powershell
NET START PandoraFMSAgent
```

Los detalles de la instalación manual y desatendida están en
[Instalación offline del EndPoint](#instalacion-offline-del-endpoint).

## Instalación del satélite

El **Satellite Server** es un servidor *headless* (sin interfaz web) pensado para
descubrir y monitorizar redes remotas a las que no llega el servidor de Pandora
FMS y donde tampoco se pueden instalar EndPoints: elementos de red por SNMP/ICMP,
servidores Windows por WMI y Linux por SNMP. Ejecuta hasta 500 chequeos por
segundo, no necesita conexión a la base de datos de Pandora FMS y envía los datos
como XML.

### Instalación en línea

Sistemas operativos soportados: **EL8, EL9 y EL10** (RHEL / Rocky Linux, con
EL10 como opción recomendada; hay paquete para x86_64 y ARM64), **Ubuntu Server
22.04** (Ubuntu 24.04 todavía no está soportado) y **Raspberry Pi OS** (Debian
12+, ARM64, con el paquete específico para Raspberry).

```bash
export PANDORA_SERVER_IP='<IP o FQDN del Pandora FMS Server>'
curl -Ls https://pfms.me/satellite-ent-deploy | bash
```

El instalador admite variables de entorno (canal de versión, grupo por defecto,
configuración remota, instalación del agente, etc.), recogidas más abajo en
[Personalización de la instalación automática](#personalizacion-de-la-instalacion-automatica).

!!! info "Compatibilidad"
    El Satellite Server 785 no es compatible con versiones anteriores de Pandora
    FMS. Instálalo junto a un entorno 785 o superior, o tendrás funciones que
    aparecen pero no operan.

## Instalación de OpenSearch

La recolección de logs es opcional, y para activarla se necesita una instancia de
**OpenSearch**. **No se instala por defecto** con el servidor: es un despliegue
aparte, y la recomendación es que viva en un servidor independiente del de Pandora
FMS.

```bash
curl -SsL https://pfms.me/pandorafms-opensearch-el | bash
```

El instalador crea un nodo listo para usar, con HTTPS y autenticación por
contraseña, y es compatible con **EL8 o posterior y Ubuntu 22.04 Server**. Admite
variables de entorno para el nombre del clúster y la contraseña, recogidas más
abajo en [Personalización de la instalación automática](#personalizacion-de-la-instalacion-automatica).

Comprobación de que el nodo responde:

```bash
curl -X GET https://127.0.0.1:9200 -ku 'admin:<contraseña>'
```

Cambia también esta contraseña. Aplica el mismo criterio que con la base de
datos: lo que está publicado no protege nada.

## Requisitos mínimos

### Requisitos del servidor

**Hardware.** Los valores son mínimos, calculados suponiendo que el 80 % de los
módulos guardan histórico y un muestreo medio de cinco minutos, con servidor,
consola y base de datos en la misma máquina:

| Hardware | Pequeño (≤ 1.000 módulos) | Mediano (≤ 10.000) | Grande (≤ 30.000) | Extra grande (≤ 80.000) |
|---|---|---|---|---|
| CPU | 2 núcleos a 2 GHz | 4 núcleos a 2,5 GHz | 6 núcleos a 3 GHz | 10 núcleos a 3 GHz |
| RAM | 4 GB | 8 GB | 16 GB | 32 GB |
| Almacenamiento | 15K rpm o SSD ≥ 300 MB/s | 15K rpm o SSD ≥ 300 MB/s | SSD ≥ 300 MB/s | SSD ≥ 300 MB/s |
| Disco (mínimo / recomendado) | 40 / 60 GB | 60 / 150 GB | 120 / 250 GB | 250 / 400 GB |

Si se guarda información de más de un mes, hay que desplegar una
[base de datos de histórico](#instalacion-de-base-de-datos-externa-para-historico).

!!! warning "Virtualización"
    En entornos virtuales, asigna a la máquina un disco independiente con espacio
    reservado y alta velocidad. Meter la base de datos en un volumen compartido y
    fino es la forma más fiable de conseguir un cuello de botella que nadie
    localizará hasta dentro de semanas.

Por encima de 80.000 módulos, un solo nodo deja de tener sentido: toca
monitorización distribuida con múltiples nodos (**Command Center**).

**Software.**

| Software | Requisitos |
|---|---|
| Sistema operativo | RHEL 10, Rocky Linux 10, AlmaLinux 10, RHEL 9 (recomendado), Rocky Linux 9 (recomendado), AlmaLinux 9 (recomendado), Ubuntu Server 22.04 y 24.04. |
| Consola | PHP 8.4 desde la versión 785; PHP 8.2 de la 776 a la 784; PHP 8 de la 760 a la 775; PHP 7.4 de la 759 a la 767; PHP 7.2 de la 729 a la 758. |
| Base de datos | Percona Server for MySQL 8 (recomendado, sobre todo por encima de 4.000 agentes), MySQL 8 o MySQL 8.4 desde la versión 785. |
| Navegadores | Chrome, Firefox, Opera y Edge. Para gráficas interactivas y mapas de red, Firefox o Chrome. |
| systemd | Necesario desde la versión 779. Viene instalado y habilitado en los SO soportados. |

!!! info "EL10 y Ubuntu"
    **EL10** denota el conjunto de sistemas recomendados: Rocky Linux 10,
    AlmaLinux 10 y Red Hat 10. En **Ubuntu Server no se soporta la instalación
    offline**, así que no lo elijas para un servidor sin conexión. Para Command
    Center se recomienda evitar Ubuntu.

Cada versión LTS de Pandora FMS soporta unas versiones concretas de sistema
operativo; consúltese la política de soporte de versiones de OS antes de decidir.

**Permisos.**

| Requisito | Detalle |
|---|---|
| Usuario de instalación | El servidor se instala como **root**. En la instalación se crea un usuario `pandora` asignado al grupo `root`; después puede cambiarse, teniendo en cuenta que habrá que reconfigurar el servidor Tentacle. También existe la instalación con usuario no privilegiado, con procedimiento aparte. |
| Consola | Apache necesita permisos de lectura y ejecución sobre los ficheros de la consola; `config.php` debe tener permisos `600`. |
| Servidor | Permisos de escritura en `/var/spool/pandora/`. |

### Requisitos de OpenSearch

| Requisito | Detalle |
|---|---|
| Sistema operativo | RHEL, Rocky Linux o AlmaLinux 8 o posterior; Ubuntu Server 22.04. |
| RAM | Mínimo 4 GB (dev/testing); recomendado 8 GB por instancia. Hay que estimar según el volumen de datos. |
| CPU | Mínimo 4 núcleos. |
| SWAP | Desactivado en el nodo o nodos de OpenSearch. |
| Almacenamiento | 50 GB de disco de sistema y 100 GB para OpenSearch. |

durante 30 días. Para más resiliencia y capacidad, se configura un **clúster**

con un balanceador tipo **Keepalived**.

### Requisitos de SIEM

| Requisito | Detalle |
|---|---|
| OpenSearch | Base de datos **OpenSearch en una instancia dedicada**. |
| Recolección de logs | Activada. |
| Recursos del nodo | Mínimo **4 núcleos, 8 GB de RAM y 100 GB de disco SSD**. |

`siemevents` en los servidores correspondientes.

## Personalización de la instalación automática

### Servidor y consola

#### Valores para el instalador online

La ejecución básica instala el entorno completo. Estas variables de entorno la
personalizan (valores de RHEL y Rocky Linux):

| Variable | Función | Por defecto |
|---|---|---|
| `TZ` | Zona horaria de la máquina; si no se define, no se modifica | Sin cambio |
| `DBHOST` | Host de la base de datos | `127.0.0.1` |
| `DBNAME` | Nombre de la base a crear | `pandora` |
| `DBUSER` | Usuario de la base | `pandora` |
| `DBPASS` | Contraseña del usuario | `Pandor4!` |
| `DBPORT` | Puerto de la base | `3306` |
| `DBROOTPASS` | Contraseña de root de la base | `Pandor4!` |
| `SKIP_PRECHECK` | Saltar el chequeo de instalación previa | `0` |
| `SKIP_DATABASE_INSTALL` | No instalar la base (usar una externa) | `0` |
| `SKIP_KERNEL_OPTIMIZATIONS` | Saltar la optimización de kernel | `0` |
| `SKIP_DOCKER_INSTALL` | No instalar Docker (se instala, y queda deshabilitado, para depuración) | `0` |
| `POOL_SIZE` | Memoria de MySQL (buffer pool) | Automático |
| `MYVER` | Versión de MySQL (`80` o `84`; en EL10, solo `84`) | `84` |
| `PHPVER` | Versión de PHP (`8.2` o `8.4`) | `8.4` |
| `PANDORA_SERVER_PACKAGE` | URL del tarball del servidor | última disponible |
| `PANDORA_CONSOLE_PACKAGE` | URL del paquete de la consola (RPM en EL, tarball de fuentes en Ubuntu) | última disponible |
| `PANDORA_AGENT_PACKAGE` | URL del tarball del agente | última disponible |
| `PANDORA_BETA` | Instalar beta (`1`) | `0` |
| `PANDORA_LTS` | Instalar rama LTS en lugar de Feature Release | `1` |

La lista es la misma en RHEL, Rocky Linux, AlmaLinux y Ubuntu Server. En EL10 el
instalador solo admite MySQL 8.4 (`MYVER=84`). `POOL_SIZE` se calcula solo a
partir de la memoria de la máquina (el 25 % por debajo de 7,5 GB y el 40 % por
encima); fíjalo solo si quieres otro reparto. Docker se instala, y se deja
deshabilitado, solo para tareas de depuración: con `SKIP_DOCKER_INSTALL=1` no se
instala.

Ejemplo en EL10 con valores explícitos:

```bash
env TZ='Europe/Madrid' \
    DBHOST='127.0.0.1' \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='CambieEstaClave' \
    DBPORT='3306' \
    DBROOTPASS='CambieEstaClaveRoot' \
    MYVER=84 \
    PHPVER=8.4 \
    SKIP_PRECHECK=0 \
    SKIP_DATABASE_INSTALL=0 \
    SKIP_KERNEL_OPTIMIZATIONS=0 \
    PANDORA_BETA=0 \
    PANDORA_LTS=1 \
    bash -c "$(curl -fsSL https://pfms.me/deploy_pandora_one)"
```

!!! warning "Cambia las contraseñas por defecto"
    `Pandor4!` está escrita en la documentación pública. Es la primera que
    prueba cualquiera que sepa por dónde entra. Dejarla puesta no es un descuido,
    es dejar la puerta abierta y poner el felpudo.

#### Valores de optimización del kernel

El instalador en línea ajusta algunos parámetros del kernel. Con
`SKIP_KERNEL_OPTIMIZATIONS=1` no los toca, pero conviene saber qué se pierde: son
ajustes pensados para que el servidor aguante muchas conexiones simultáneas sin
que el sistema operativo se convierta en el cuello de botella.

| Parámetro | Por defecto | Fija Pandora | Qué hace |
|---|---|---|---|
| `net.ipv4.tcp_syn_retries` | 5 | 3 | Reintentos al enviar una petición de conexión TCP antes de darla por fallida. |
| `net.ipv4.tcp_synack_retries` | 5 | 3 | Reintentos al recibir el acuse de recibo de una conexión TCP. |
| `net.ipv4.tcp_max_syn_backlog` | 1024 | 65536 | Tamaño máximo de la cola de conexiones TCP pendientes de aceptar. |
| `net.core.wmem_max` | 124928 | 8388608 | Buffer máximo de envío de datos por conexión de red. |
| `net.core.rmem_max` | 131071 | 8388608 | Buffer máximo de recepción de datos por conexión de red. |
| `net.core.somaxconn` | 128 | 1024 | Conexiones pendientes en la cola de escucha de sockets. |
| `net.core.optmem_max` | 20480 | 81920 | Buffer máximo para opciones de socket. |

No los toques a mano salvo que sepas exactamente lo que haces. Deja
`SKIP_KERNEL_OPTIMIZATIONS=0` y que el instalador haga su trabajo.

#### Instalación en una base de datos externa

Si hay un servidor dedicado para la base de datos, el camino es: crear la base y
el usuario, darle todos los permisos sobre esa base y instalar con
`SKIP_DATABASE_INSTALL=1` y los valores de conexión. Antes de instalar, prueba la
conexión desde el futuro servidor de Pandora FMS. Descubrir el firewall a las dos
de la mañana es evitable con cinco minutos de comprobación.

```bash
env DBHOST='192.168.1.107' \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='CambieEstaClave' \
    DBPORT='3306' \
    SKIP_DATABASE_INSTALL=1 \
    bash -c "$(curl -fsSL https://pfms.me/deploy_pandora_one)"
```

Restringe el usuario de la base de datos a la IP del servidor de Pandora FMS: si
la contraseña se ve comprometida, que no sirva desde otro sitio.

#### Instalación de base de datos externa para histórico

Para desplegar una base de datos dedicada (incluido el histórico) existe un
instalador en línea propio. Solo requiere `curl` y un sistema compatible:

- **EL9**: Rocky Linux 9.x o RHEL 9.x.
- **EL10**: Rocky Linux 10 o RHEL 10.
- **Ubuntu**: 22.04.

```bash
curl -fsSL https://pfms.me/db-deploy-el9 | bash
```

En Ubuntu:

```bash
curl -fsSL https://pfms.me/db-deploy-u2204 | bash
```

Variables soportadas:

| Variable | Descripción | Por defecto |
|---|---|---|
| `TZ` | Zona horaria de la máquina; si no se define, no se modifica | Sin cambio |
| `MYVER` | Versión de MySQL (8.0 o 8.4) | `84` |
| `DBNAME` | Nombre de la base a crear | `pandora` |
| `DBUSER` | Usuario de la base | `pandora` |
| `DBPASS` | Contraseña del usuario | `Pandor4!` |
| `DBROOTPASS` | Contraseña del usuario root | `Pandor4!` |
| `SKIP_KERNEL_OPTIMIZATIONS` | Saltar optimizaciones de kernel | `0` |
| `POOL_SIZE` | Memoria para MySQL (buffer pool) | Automático |

```bash
env TZ='Europe/Madrid' \
    MYVER=84 \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='CambieEstaClave' \
    DBROOTPASS='CambieEstaClaveRoot' \
    POOL_SIZE=4G \
    bash -c "$(curl -fsSL https://pfms.me/db-deploy-el9)"
```

#### Instalación en una ruta diferente

Para instalar el servidor en otra ruta, el instalador admite `--destdir`:

```bash
./pandora_server_installer --install --destdir <destdir>
```

Después hay que configurar el arranque automático y el script de mantenimiento
`pandora_db` en el cron:

```bash
echo "\"<destdir>/usr/share/pandora_server/util/pandora_db\" \
 \"<destdir>/etc/pandora/pandora_server.conf\">/dev/null 2>&1"> /etc/cron.hourly/pandora_db
```

#### Instalación con un usuario no privilegiado

El instalador admite ejecutarse con un usuario sin privilegios:

```bash
./pandora_server_installer --install --no-root --destdir /opt/pandora
```

Ese usuario debe tener permisos de escritura sobre la ruta indicada en
`--destdir`.

### EndPoint

#### Valores para el instalador online

La ejecución básica instala el agente y lo apunta al servidor. Estas variables de
entorno la personalizan.

```bash
export PANDORA_SERVER_IP='10.0.0.1' \
       PANDORA_AGENT_PACKAGE=GO \
       PANDORA_AGENT_RELEASE=STABLE \
       PANDORA_SKIP_CONFIRMATION=1
curl -sSL https://pfms.me/agent-deploy | bash
```

**Selección del paquete.**

| Variable | Función | Por defecto |
|---|---|---|
| `PANDORA_SERVER_IP` | IP o FQDN del servidor de Pandora FMS. Sin ella el script no sigue. | — |
| `PANDORA_AGENT_PACKAGE` | Paquete: `GO`, `PERL` o `PERL_SOURCES`, o la URL directa de un tarball | `GO` |
| `PANDORA_AGENT_PACKAGE_TYPE` | Dependencias que instala cuando `PANDORA_AGENT_PACKAGE` es una URL | `GO` |
| `PANDORA_AGENT_RELEASE` | Canal: `STABLE` (última versión) o `BETA` (`nightlies`) | `STABLE` |
| `PANDORA_SKIP_CONFIRMATION` | `1` quita las confirmaciones interactivas | `0` |

**Configuración del agente.** Se aplican sobre `/etc/pandora/pandora_agent.conf`
después de que el instalador termine. Si no se definen, la línea se queda como
está.

| Variable | Clave | Efecto |
|---|---|---|
| `PANDORA_REMOTE_CONFIG` | `remote_config` | Activa o desactiva la configuración remota |
| `PANDORA_GROUP` | `group` | Grupo del agente |
| `PANDORA_GROUP_PASSWORD` | `group_password` | Contraseña del grupo |
| `PANDORA_SERVER_PWD` | `server_pwd` | Contraseña del servidor para Tentacle o FTP |
| `PANDORA_DEBUG` | `debug` | Modo de depuración |
| `PANDORA_AGENT_NAME` | `agent_name` | Nombre del agente |
| `PANDORA_AGENT_ALIAS` | `agent_alias` | Alias del agente |
| `PANDORA_SECONDARY_GROUPS` | `secondary_groups` | Grupos secundarios |
| `PANDORA_AGENT_SSL` | `server_ssl` | Cifra la conexión con Tentacle |

**Opciones libres.** `PANDORA_INSTALLER_PARAMS` pasa cualquier opción de
`pandora_agent_installer` tal cual, incluidas las que el script no modela:

```bash
export PANDORA_SERVER_IP='10.0.0.1' \
       PANDORA_INSTALLER_PARAMS='--group-password MiClaveDeGrupo --server-pwd MiClaveTentacle --set "s/^interval .*/interval 240/"'
```

Se separa en argumentos respetando las comillas y nunca se evalúa como código.
Las variables `PANDORA_*` se aplican después, así que ganan si coinciden. Solo el
paquete GO entiende estas opciones: con `PERL` o `PERL_SOURCES` se ignoran con un
aviso, y una opción que la versión instalada no admita hace fallar la instalación
en lugar de quedarse callada.

**Sistema.** `TIMEZONE` ajusta la zona horaria de la máquina (el enlace de
`/etc/localtime`), por ejemplo `Europe/Madrid`. `RHEL_CHECK_SUBSCRIPTION` (`1` por
defecto) comprueba la suscripción de RHEL antes de instalar;
`PANDORA_SKIP_DEPENDENCIES=1` no instala las dependencias del sistema, para
cuando ya están puestas.

Si la máquina ya tiene un agente, el script lo actualiza en lugar de detenerse.
La salida completa queda en `/tmp/pandora-agent-deploy-AAAA-MM-DD.log`.

#### Instalación en una ruta diferente

El EndPoint puede instalarse íntegro en un directorio definido: en él quedan
logs, configuración, binarios y páginas `man`.

```bash
./pandora_agent_installer --install /opt/pandora
```

#### Instalación con un usuario no privilegiado

También puede ejecutarse con un usuario distinto de `root`. Por ejemplo, con el
usuario `pandora`:

```bash
./pandora_agent_installer --install /home/pandora pandora
```

Al especificar un usuario personalizado, la instalación debe ir a una ubicación
donde ese usuario tenga permisos de escritura. El usuario `pandora` viene
desactivado por defecto: para usarlo hay que darle una *shell* válida en
`/etc/passwd`.

## Instalación offline

Para entornos sin conexión a internet. **No está soportado en Ubuntu**. La
primera vía monta el sistema operativo y el producto en la misma máquina desde
una ISO; las demás dan por hecho un sistema ya instalado.

### Instalación del servidor desde la ISO desatendida de Rocky Linux 10

Hay una forma de instalar Pandora FMS que no hace ni una pregunta: una imagen
ISO arranca, instala Rocky Linux 10 y, en el primer arranque, monta el producto
completo. No es un instalador que se ejecuta dentro de un sistema ya montado; es
el sistema entero, con el paquete dentro. En la máquina de destino no hace falta
internet: la ISO lo lleva.

Sirve para desplegar varias máquinas iguales sin repetir el ritual y para
levantar un entorno de pruebas en lo que dura un café largo. A cambio hay que
aceptar la letra pequeña: la máquina es para la ISO y para nadie más.

!!! warning "Borra todos los discos"
    La entrada desatendida del menú vacía todos los discos que el instalador ve.
    No la arranques en un equipo con datos que te importen, ni con un disco
    conectado de más. Es una imagen para máquinas virtuales dedicadas.

#### Qué hace la imagen

La imagen trae tres cosas: un Rocky Linux 10 con el entorno mínimo, el paquete
de instalación offline de Pandora FMS y la marca del producto en las pantallas. Con eso trabaja
en dos fases separadas por un reinicio:

1. **Rocky Linux**, sin preguntas. El instalador particiona, formatea y deja el
   sistema mínimo en marcha.
2. **Pandora FMS**, en el primer arranque. Un servicio del sistema descomprime
   el paquete offline y ejecuta su instalador, el mismo de
   [Instalación offline del servidor](#instalacion-offline-del-servidor-paquete).

El resultado es el entorno monolito de siempre: servidor, consola, base de datos
y EndPoint local, con la consola respondiendo en
`http://<ip>/pandora_console/`.

El paquete viaja dentro de la ISO: no hay nada que descargar ni que elegir
durante la instalación. La imagen va atada a dos cosas concretas: una versión de
Rocky Linux y un paquete (la que se probó lleva la LTS 800 sobre Rocky 10.2).
Mezclar una ISO de una versión con un paquete de otra falla a mitad de la
instalación, sin arreglo desde el menú de arranque.

#### Requisitos

| Requisito | Detalle |
|---|---|
| Máquina | Dedicada. La instalación borra todos los discos. |
| CPU | 2 vCPU. |
| Memoria | 4 GB de RAM. |
| Disco | 60 GB. |
| Red | DHCP durante la instalación. La IP fija se pone después, con `nmtui`. |
| Vídeo | Dispositivo gráfico: el instalador de Rocky corre en modo gráfico. |
| Firmware | UEFI con el arranque seguro desactivado, o BIOS. |
| Internet en el destino | No hace falta. |

!!! note "Qué está probado"
    La instalación desatendida completa está probada en KVM (4 vCPU, 8 GB de RAM
    y un disco de 60 GB) con UEFI y arranque seguro desactivado: consola
    respondiendo y los servicios activos, además del acceso SSH y el mensaje
    final. No están probados el arranque por BIOS con
    este menú, el arranque seguro activado, el asistente gráfico de punta a
    punta ni las máquinas que solo tienen consola serie.

#### Arranque y menú

Arranca la máquina desde la ISO y espera el menú. Si el disco está vacío, el
menú **no tiene cuenta atrás**: se queda ahí hasta que elijas. Es deliberado,
porque la primera entrada borra todo lo que encuentre y no parece buen sitio
para un descuido de tres segundos.

![Menú de arranque de la ISO en una máquina sin sistema instalado, con la entrada de instalación desatendida seleccionada y el aviso de que borra todos los discos](../../assets/img/parte-01/iso-menu-instalacion-desatendida.png){ .captura }

| Entrada | Qué hace |
|---|---|
| `Pandora FMS unattended install on Rocky Linux 10.2 (ERASES ALL DISKS)` | La instalación desatendida completa. Solo hay que pulsar Intro. |
| Variantes con `media check` o `FIPS mode` | La misma instalación, con comprobación del medio o en modo FIPS. También borran los discos. |
| `Pandora FMS graphical install on Rocky Linux 10.2 (wizard, you pick the disks)` | Abre el asistente de Anaconda para elegir idioma, teclado, zona horaria, discos y contraseña de root. Pandora FMS se instala igual en el primer arranque. |
| `Troubleshooting -->` | Submenú con el sistema de rescate y la variante de instalación con gráficos básicos (esta última también borra los discos). El rescate no ejecuta el kickstart. |
| `Boot the installed system from disk (default when one is found)` | Arranca el sistema ya instalado. |

Las entradas que borran el disco llevan el aviso al final del nombre, para que se
lea primero lo que hacen y después el destrozo. La comprobación del medio
(`media check`) no se usa con esta imagen: al modificar su contenido, la suma de
control original ya no cuadra.

Cuando la máquina ya tiene una instalación, el kickstart deja una marca en
`/boot/pandora-installed`. Si la ISO sigue montada en el siguiente arranque, el
menú la encuentra y arranca el disco por defecto, con diez segundos de margen.
Así no se reinstala sola cuando el hipervisor no expulsa el DVD al reiniciar,
que pasa más de lo que gustaría.

![El mismo menú cuando ya hay un sistema instalado: la entrada de arranque del disco está seleccionada y el menú muestra la cuenta atrás](../../assets/img/parte-01/iso-menu-sistema-instalado.png){ .captura }

#### Fase 1: instalación de Rocky Linux

El kickstart contesta por ti todo lo que el instalador preguntaría:

- Borra todos los discos y crea las particiones con LVM.
- Instala el entorno mínimo, más `tar`, `gzip` y `nmtui`.
- Pone el nombre `pandorafms`, la zona `Europe/Madrid` y el teclado `us`.
- Deja la contraseña de root caducada: hay que cambiarla en el primer acceso.
- Desactiva SELinux y `firewalld`, y activa `sshd` y `chronyd`.
- Pide la dirección por DHCP.
- Copia el paquete offline y el script del primer arranque al disco, y reinicia
  pidiendo al hipervisor que expulse la ISO.

No hay nada que contestar: el único momento en que tocas el teclado es el Intro
del menú. Anaconda se ve en modo gráfico, con la barra lateral y la barra
superior con la marca de Pandora FMS; el resto de la pantalla es la suya.

![Progreso de la instalación de Rocky Linux 10.2, con la barra lateral y la barra superior de Pandora FMS](../../assets/img/parte-01/iso-instalacion-sistema-operativo.png){ .captura }

Estos valores salen de la imagen. Si la tuya trae otro nombre de máquina, otra
zona horaria, otro teclado u otra contraseña de root, son los que verás aquí.

#### Fase 2: instalación de Pandora FMS

El primer arranque no es un arranque normal. `pandora-firstboot.service` se
ejecuta antes que los servicios de login y no los deja pasar hasta que termina o
falla: no hay consola ni SSH durante la instalación. Tarda unos diez minutos.

Mientras trabaja, la pantalla muestra el logo, un indicador animado, el paso en
que va (`Step 2 of 2`) y el aviso de no apagar la máquina.

![Pantalla completa de la instalación de Pandora FMS en el primer arranque, con el logo, el indicador animado, el paso 2 de 2 y el aviso de no apagar la máquina](../../assets/img/parte-01/iso-instalacion-pandora-fms.png){ .captura }

Con `Esc` se cambian los mensajes de arranque por texto: se ve el arranque de los
servicios y la línea de estado del primer arranque, no la salida del instalador.
Esa salida va a `/var/log/pandora-firstboot.log`.

![Mensajes de arranque en texto tras pulsar Esc durante la instalación de Pandora FMS](../../assets/img/parte-01/iso-arranque-detalle-esc.png){ .captura }

- Si termina bien, muestra el mensaje de bienvenida y borra el paquete de
  `/opt/pandora-offline` (unos 5 GB que se recuperan). El servicio se desactiva
  y no vuelve a ejecutarse.
- Si falla, libera el login y deja en pantalla qué ha fallado y dónde mirar:
  `/var/log/pandora-firstboot.log` y `/var/log/pandorafms-deploy-*.log`.
- Si se cuelga, un timeout de dos horas libera la máquina.

#### Credenciales y primer acceso

| Qué | Valor |
|---|---|
| `root` del sistema operativo | `pandora`, caducada: el primer login obliga a cambiarla, en consola o por SSH. |
| `admin` de la consola | `pandora`. La consola pide una contraseña nueva en el primer acceso. |
| MySQL, `root` y usuario `pandora` | Una contraseña aleatoria por instalación, la misma para ambos. |
| Dónde está la de MySQL | `/root/pandora_credentials` (permisos `0600`). También en `/etc/pandora/pandora_server.conf` y `/var/www/html/pandora_console/include/config.php`. |

La contraseña de MySQL se genera mientras se instala y no aparece ni en la ISO
ni en los registros del instalador, y el mensaje de bienvenida tampoco la
muestra. Se lee del fichero, como root, la primera vez que haga falta.

!!! warning
    El cambio de contraseña de root y el de la consola no son opcionales. Si la
    instalación queda accesible con `pandora`/`pandora`, el problema no es la
    ISO: es que nadie ha entrado todavía.

#### Acceso SSH

En la instalación desatendida, `root` puede entrar por SSH con su contraseña. El
primer login obliga a cambiarla, así que quien entra primero se queda la
máquina. Es cómodo para terminar de configurar y una mala idea en cualquier red
que no controles: instala en redes de confianza o cambia la contraseña antes de
exponer el puerto.

En la instalación con el asistente gráfico lo decide el asistente: hay que marcar
la casilla de permitir el acceso de `root` por SSH con contraseña en la pantalla
de la contraseña de root.

El banner que el instalador offline muestra antes del login SSH
(`/etc/issue.net`) no se toca: conserva las direcciones del momento de la
instalación y la IP pública que el instalador intentó averiguar. El mensaje de
bienvenida propio está en `/etc/issue` y en `/etc/motd.d/10-pandora`.

#### Mensaje de bienvenida

Al terminar, el mensaje de la pantalla de login y el que aparece tras entrar por
SSH resumen lo que necesitas para empezar: la URL de la consola, las
credenciales, cómo poner una IP fija con `nmtui`, cómo entrar por SSH, cómo
reiniciar, cómo comprobar los servicios, dónde leer la contraseña de la base de
datos y el enlace a esta documentación. La IP de la captura es un ejemplo.

![Mensaje de bienvenida antes del login: URL de la consola, credenciales, cómo fijar la IP con nmtui, acceso SSH, reinicio y comprobación de servicios](../../assets/img/parte-01/iso-mensaje-final-login.png){ .captura }

Se edita en dos ficheros:

| Fichero | Dónde se ve |
|---|---|
| `/etc/issue` | Pantalla de login de la consola. `\4` se sustituye por la IP actual. |
| `/etc/motd.d/10-pandora` | Después del login por SSH. No admite `\4`, así que indica cómo ver la IP. |

#### IP fija con nmtui

La instalación pide la dirección por DHCP. Para dejarla fija, entra como root y
ejecuta `nmtui`:

1. **Edit a connection** y elige la interfaz de red.
2. **IPv4 CONFIGURATION**: cambia `Automatic` por `Manual` y pulsa **Show**.
3. Rellena **Addresses** (por ejemplo, `192.168.1.50/24`), **Gateway** y
   **DNS servers**.
4. Acepta con **OK** y sal.
5. **Activate a connection**: desactiva la conexión y vuelve a activarla, o
   reinicia la máquina.

Comprueba la dirección con `ip -4 addr` y abre la consola en la nueva IP. Si la
consola no responde después del cambio, el problema suele estar en la puerta de
enlace o en el DNS, no en Pandora FMS.

#### Comprobación de servicios

El servicio de primer arranque ya comprueba, antes de darse por terminado, que
`mysqld`, `httpd` y `pandora_server` están activos y que la consola responde con
un `200` o un `302`. La comprobación completa, a mano:

```bash
systemctl status mysqld httpd php-fpm pandora_server tentacle_serverd pandora_agent_daemon
```

Los seis tienen que estar en `active (running)`. Después, abre
`http://<ip>/pandora_console/` y confirma que carga la pantalla de acceso. El
resto de comprobaciones, iguales para cualquier instalación, están en
[Verificación](#verificacion).

#### Actualizar el sistema instalado

El instalador deja configurados los repositorios de Rocky Linux, EPEL, Remi y
Percona, así que la máquina se actualiza como cualquier Rocky:

```bash
dnf update
```

Con internet, el proceso está probado sobre una instalación recién hecha: llevó
el sistema de Rocky 10.2 a 10.3 con 315 paquetes, kernel nuevo incluido, y tras
reiniciar todo arrancó igual y la consola siguió respondiendo. Si el kernel
cambia, reinicia; el resto de servicios no lo necesita, pero tampoco le hace
daño.

### Instalación offline del servidor (paquete)

Los sistemas compatibles son **RHEL 9 / Rocky Linux 9** y **RHEL 10 / Rocky
Linux 10**.

Pasos:

1. Disponer de una instancia con los requisitos de hardware y el sistema
   operativo soportado, limpia.
2. Descargar el paquete *offline* para el sistema operativo desde el portal de
   soporte (disponible para versiones LTS y previas LTS).
3. Subir el tarball al servidor.
4. Descomprimirlo y ejecutar el instalador:

```bash
tar xvzf <offline_package>.tar.gz
cd pandora_packages/
./pandora_deploy_enterprise_local_el9.sh
```

En EL10 el script es `pandora_deploy_enterprise_local_el10.sh`. Cuando el proceso
termina, se accede a la consola web con el usuario `admin` y la contraseña
`pandora`.

### Instalación offline del satélite

#### Instalación manual en Linux

Instaladas las dependencias y descargado el paquete, se descomprime y se ejecuta
el instalador:

```bash
tar -xvzf pandorafms_satellite_server_X.XNG.XXX_x86_64.tar.gz
cd satellite_server/
./satellite_server_installer --install
```

Después hay que editar `/etc/pandora/satellite_server.conf` y fijar el token
`server_ip` con la dirección del Pandora FMS Server. El servicio se arranca con:

```bash
systemctl start satellite_serverd
```

El registro está en `/var/log/satellite_server.log`.

#### Instalación en MS Windows

El instalador (firmado desde la versión 762) incluye Nmap y Visual C++
Redistributable de MS Visual Studio 2015-2022. Se ejecuta con derechos de
administrador, se introduce la licencia, se configura la dirección del servidor y
las reglas de exploración, y se reinicia la máquina. Si las consultas WMI fallan,
hay que ejecutar el servicio del Satellite Server con una cuenta de
Administrador.

### Instalación offline del EndPoint

El EndPoint se instala desde el paquete tarball, válido para cualquier
Unix/Linux/macOS. No requiere compilación.

```bash
tar xvzf pandorafms_one_agent_linux-latest.tar.gz
cd unix
./pandora_agent_installer --install
systemctl start pandora_agent_daemon
```

Puede hacer falta instalar manualmente `libnsl`. Si se usan las fuentes
(`.src.tar.gz`), hay dependencias adicionales de Perl, entre ellas `YAML::Tiny` y
`Thread::Semaphore`. En FreeBSD y NetBSD la ubicación de ficheros y el script de
arranque cambian: el agente queda en `/usr/local/bin/pandora_agent`, el script en
`/usr/local/etc/rc.d/pandora_agent`, la configuración en
`/usr/local/etc/pandora/pandora_agent.conf` y hay que añadir
`pandora_agent_enable="YES"` a `/etc/rc.conf`.

Tras la instalación hay que editar `/etc/pandora/pandora_agent.conf` para apuntar
al servidor y, como recomendación, activar la configuración remota:

```bash
sed -i "s/^remote_config.*$/remote_config 1/g" /etc/pandora/pandora_agent.conf
systemctl enable pandora_agent_daemon
```

#### Windows desatendida

El instalador de Windows soporta modo desatendido desde la versión 5.1 del
EndPoint:

```
"PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S
```

Ruta personalizada:

```
"PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S /D=C:\PFMS_agent
```

Parámetros que se escriben en la configuración del EndPoint: `--ip` (`server_ip`),
`--group` (`group`), `--alias` (`agent_alias`) y `--remote_config`
(`remote_config`). Ejemplo:

```
"PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S --ip 192.168.0.59 --group Applications --alias Mifunne --remote_config 1
```

## Verificación

Terminada la instalación, abre la consola en `http://<servidor>/pandora_console/`
y confirma que carga la pantalla de acceso. El usuario inicial es `admin` con la
contraseña `pandora`.

Después comprueba que los servicios del componente instalado están activos:

| Componente | Servicios | Registro |
|---|---|---|
| Servidor | `pandora_server` y `tentacle_serverd` | `/var/log/pandora/pandora_server.log` |
| Satélite | `satellite_serverd` | `/var/log/satellite_server.log` |
| EndPoint (Linux) | `pandora_agent_daemon` | `/var/log/pandora/pandora_agent.log` |

```bash
systemctl status pandora_server tentacle_serverd
```

Un servicio en `failed` casi siempre explica el motivo en su registro: léelo antes
de reinstalar nada. Si el EndPoint se ha instalado contra un servidor, en pocos
minutos debería aparecer como agente nuevo en **Monitorización → Vistas →
Detalle de agente**.

!!! warning
    Cambia la contraseña en el primer acceso. Y si has instalado con usuario
    personalizado o ruta distinta, comprueba el arranque de los servicios antes
    de darte por satisfecho; el fallo que no se revisa hoy se convierte en
    incidencia el lunes.

## Desinstalación

Los instaladores **no se copian** durante la instalación, así que no se puede
recurrir a su `--uninstall` a posteriori. La desinstalación hay que hacerla a
mano: estos son los ficheros y carpetas que deja cada componente y los comandos
para retirarlos (como **root**). Si varios componentes conviven en la misma
máquina, no borres los directorios compartidos hasta retirarlos todos.

### Servidor

- Binarios en `/usr/bin`: `pandora_server`, `pandora_exec`, `pandora_supervisor`,
  `pandora_db`, `pandora_ha`, `pandora_manage`, `pandora_revent`,
  `pandora_encrypt_db`, `braa`, `pandorafsnmp`, `pandorawmic`,
  `pandora_iot_server`, `pandora_netflow_server`, `tentacle_server`,
  `tentacle_client`, `clean_pandora_server`, `clean_tentacle_serverd` y
  `clean_tentacle_rmm`.
- Librerías y utilidades: `/usr/share/pandora_server`.
- Servicios: `/etc/systemd/system/pandora_server.service`, `pandora_ha.service`,
  `tentacle_serverd.service`, `tentacle_rmm.service`,
  `pandora_iot_server.service` y `pandora_netflow_server.service`.
- Tareas y rotación: `/etc/cron.hourly/pandora_db` y
  `/etc/logrotate.d/pandora_server`.
- Configuración: `/etc/pandora/pandora_server.conf`, `pandora_server.env`,
  `pandora_server_extra.env`, `/etc/pandora/conf.d` y `/etc/tentacle`.
- Datos, logs y PID: `/var/spool/pandora`, `/var/log/pandora` y
  `/var/run/pandora_supervisor.pid`.

```bash
systemctl stop pandora_server pandora_ha tentacle_serverd tentacle_rmm \
  pandora_iot_server pandora_netflow_server
systemctl disable pandora_server pandora_ha tentacle_serverd tentacle_rmm \
  pandora_iot_server pandora_netflow_server
rm -f /etc/systemd/system/{pandora_server,pandora_ha,tentacle_serverd,tentacle_rmm,pandora_iot_server,pandora_netflow_server}.service
systemctl daemon-reload
rm -f /usr/bin/{pandora_server,pandora_exec,pandora_supervisor,pandora_db,pandora_ha,pandora_manage,pandora_revent,pandora_encrypt_db,braa,pandorafsnmp,pandorawmic,pandora_iot_server,pandora_netflow_server,tentacle_server,tentacle_client,clean_pandora_server,clean_tentacle_serverd,clean_tentacle_rmm}
rm -Rf /usr/share/pandora_server
rm -f /etc/cron.hourly/pandora_db /etc/logrotate.d/pandora_server
```

Y, si no queda ningún otro componente, la configuración y los datos compartidos:

```bash
rm -Rf /etc/pandora /etc/tentacle /var/spool/pandora /var/log/pandora
```

### Consola

Depende de cómo se instaló:

- **RPM (RHEL / Rocky Linux)**: se retira con el gestor de paquetes.

```bash
dnf remove pandorafms_console
```

- **Tarball (Ubuntu)**: se copió a `/var/www/html/pandora_console` y dejó su
  rotación de logs.

```bash
rm -Rf /var/www/html/pandora_console
rm -f /etc/logrotate.d/pandora_console
```

La consola comparte con el servidor el directorio `/var/spool/pandora/data_in`
(`collections`, `conf`, `md5`, `netflow`): no lo borres si hay servidor. No toca
la base de datos; eso va aparte.

### Base de datos

La instalación crea la base `pandora` y el usuario `pandora`. Si MySQL o Percona
solo daban servicio a Pandora FMS:

```bash
systemctl stop mysqld
mysql -u root -p -e "DROP DATABASE pandora; DROP USER 'pandora'@'localhost';"
dnf remove 'Percona-Server*'        # RHEL/Rocky; en Ubuntu, apt remove percona-server-server o mysql-server
rm -Rf /var/lib/mysql /etc/my.cnf /etc/my.cnf.d
```

Si la base está en otro servidor o alberga datos de otras aplicaciones, limita la
operación a `DROP DATABASE` y `DROP USER`.

### Satélite

- Binarios en `/usr/bin`: `satellite_server`, `tentacle_client`,
  `pandorafsnmp`, `wmic`, `pandorawmic` y `clean_satellite_serverd`.
- Configuración: `/etc/pandora/satellite_server.conf`,
  `satellite_server.env`, `satellite_server_extra.env`,
  `/etc/pandora/satellite_plugins` y el directorio de agentes `/etc/pandora/conf`.
- Arranque: `/etc/init.d/satellite_serverd` (con su enlace en `/etc/rc.d`) y
  `/etc/systemd/system/satellite_serverd.service`.
- Rotación, logs y temporales: `/etc/logrotate.d/pandora_satellite`,
  `/var/log/satellite_server.log` y `/var/spool/pandora/tmp/satellite_server`.

```bash
systemctl stop satellite_serverd
systemctl disable satellite_serverd
rm -f /etc/systemd/system/satellite_serverd.service
systemctl daemon-reload
rm -f /etc/init.d/satellite_serverd
rm -f /etc/rc.d/rc?.d/S90satellite_server
rm -f /usr/bin/{satellite_server,tentacle_client,pandorafsnmp,wmic,pandorawmic,clean_satellite_serverd}
rm -Rf /etc/pandora/satellite_plugins /etc/pandora/conf /var/spool/pandora/tmp/satellite_server
rm -f /etc/pandora/satellite_server.conf /etc/pandora/satellite_server.env /etc/pandora/satellite_server_extra.env
rm -f /etc/logrotate.d/pandora_satellite /var/log/satellite_server.log
```

El directorio `/opt/pandorafms/perl5` del satélite es compartido con otros
componentes: bórralo solo si no queda ninguno instalado.

### EndPoint

En Linux y Unix deja:

- Binarios en `/usr/bin`: `pandora_agent`, `pandora_agent_exec`,
  `pandora_revent`, `tentacle_client` y `clean_pandora_agent_daemon`.
- Home del agente: `/usr/share/pandora_agent` (`plugins`, `collections`,
  `commands`, `ref`).
- Configuración: `/etc/pandora/pandora_agent.conf` y `pandora_agent.env`.
- Arranque: `/etc/systemd/system/pandora_agent_daemon.service` (o el script de
  `/etc/init.d`).
- Rotación, logs y páginas `man`: `/etc/logrotate.d/pandora_agent`,
  `/var/log/pandora/pandora_agent.log`,
  `/usr/share/man/man1/pandora_agent.1.gz` y `tentacle_client.1.gz`.

```bash
systemctl stop pandora_agent_daemon
systemctl disable pandora_agent_daemon
rm -f /etc/systemd/system/pandora_agent_daemon.service
systemctl daemon-reload
rm -f /usr/bin/{pandora_agent,pandora_agent_exec,pandora_revent,tentacle_client,clean_pandora_agent_daemon}
rm -Rf /usr/share/pandora_agent
rm -f /etc/pandora/pandora_agent.conf /etc/pandora/pandora_agent.env
rm -f /etc/logrotate.d/pandora_agent /var/log/pandora/pandora_agent.log
rm -f /usr/share/man/man1/pandora_agent.1.gz /usr/share/man/man1/tentacle_client.1.gz
```

Si hay servidor o satélite en la misma máquina, no borres `/etc/pandora` ni
`/var/spool/pandora` completos.

**MS Windows** sí incluye desinstalador. De forma desatendida:

```
"%ProgramFiles%\pandora_agent\uninst.exe" /S
```

O desde el binario del agente:

```
pandoraagent.exe --uninstall
```
