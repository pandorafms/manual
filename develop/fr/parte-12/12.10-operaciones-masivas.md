# Opérations massives

Déployer des agents, modifier des configurations et faire des nettoyages en lot,
sans y aller un par un.

Ce sont des opérations puissantes : **faites une sauvegarde avant la première**.

## Déployer des agents de façon massive

Pandora FMS le fait depuis le **centre de déploiements du Discovery**, et pour
l'utiliser il faut deux choses préparées :

1. **Un dépôt d'agents** : dans **Configuration → Dépôt d'EndPoints** (en anglais
   **Configuration → EndPoints repository**), on téléverse les installateurs, un
   par système d'exploitation.
2. **Le dépôt d'identifiants** : dans **Configuration → Dépôt d'identifiants** (en
   anglais **Configuration → Credential store**), on conserve les utilisateurs et
   mots de passe des machines cibles. C'est le même dépôt que celui qu'utilise
   Discovery.

Avec cela, le déploiement parcourt les machines, installe l'agent de leur système
et le laisse en train de remonter des données. C'est la différence entre préparer
cent machines à la main et vérifier le résultat de cent installations.

## Mettre à jour la configuration de tous les agents

Il y a deux cas, et ils se résolvent de manière différente :

- **Modules, plugins et alertes** : cela se fait avec des **politiques**. Elles
  s'appliquent aux agents du même système d'exploitation et les modules s'écrivent
  dans leur configuration sans les toucher un par un.
- **Paramètres spéciaux du fichier de l'agent** : ici, il faut passer par le
  serveur. Il convient de **faire d'abord une copie** de deux répertoires :
  `/var/spool/pandora/data_in/conf` (où le serveur conserve la configuration de
  chaque agent) et `/var/spool/pandora/data_in/md5` (les sommes de contrôle). Une
  fois la sauvegarde faite, on applique la modification massive et on laisse les
  agents la récupérer.

## Supprimer les agents qui n'ont jamais remonté de données

On peut localiser les candidats par base de données : ce sont les agents dont les
modules sont **tous non initialisés**. Exécutez d'abord une requête en lecture
seule pour les identifier. La base utilise InnoDB et ses tables sont liées : ne
supprimez pas de lignes directement dans `tagente`.

```sql
SELECT id_agente, nombre, notinit_count, total_count
FROM tagente
WHERE notinit_count = total_count;
```

Cette condition couvre les deux cas typiques : l'agent pour lequel aucun module
n'a été créé et celui qui les a tous en « non initialisé ». Contrôlez la liste et
supprimez les agents depuis les opérations d'agents de la console, pour que le
produit nettoie aussi les tables liées.

## Changer l'IP de nombreux modules d'un coup

Si un dispositif change d'adresse et que des centaines de modules le supervisent,
on ne les touche pas un par un. On met à jour depuis **Admin tools → DB
interface** (*Outils d'administration → Interface de base de données*) :

```sql
UPDATE tagente_modulo SET ip_target = '10.0.0.1' WHERE ip_target = '10.0.0.2';
```

La nouvelle adresse va dans `ip_target` et l'ancienne dans le `WHERE`. Il convient
d'exécuter d'abord un `SELECT` avec le même `WHERE` pour voir combien de modules
vont être touchés. Faites une copie de la base avant d'exécuter la requête
`UPDATE`.

## Nettoyer le `data_in` lorsqu'il s'est rempli de XML

Si le répertoire accumule des milliers de fichiers, ils se traitent sans perdre de
données. On déplace les XML vers un répertoire temporaire et on les renvoie **par
lots** :

```bash
mkdir -p /tmp/xml
mv /var/spool/pandora/data_in/*data /tmp/xml
ls -rt /tmp/xml | grep data | head -20 | xargs -i% mv /tmp/xml/% /var/spool/pandora/data_in
```

La dernière commande en renvoie 20 à chaque fois : on la répète jusqu'à vider le
répertoire temporaire, en laissant le serveur les traiter entre deux fournées. Ne
supprimez pas les XML s'ils peuvent contenir des données que vous devez récupérer.

## Supprimer un agent d'un serveur satellite

Un agent créé par un serveur satellite **ne disparaît pas en le supprimant
seulement dans la console** : le satellite le recrée. Il faut le retirer à
l'origine :

1. Supprimez-le du fichier d'hôtes du satellite (par défaut
   `/etc/pandora/satellite_hosts.txt`, ou celui qu'indique sa configuration dans
   `host_file`).
2. Supprimez le fichier de configuration de cet agent dans le répertoire du
   satellite (par défaut `/etc/pandora/conf`, ou celui qui est configuré dans
   `agent_conf_dir`).

Ensuite, dans la console, supprimez l'agent.

## Téléverser des fichiers plus gros depuis la console

Lorsque la console refuse un fichier (par exemple, à l'ajout à une collection), il
y a deux limites à relever :

- **PHP** : la valeur `upload_max_filesize` (et `post_max_size`) dans `php.ini`,
  puis redémarrer le service web.
- **La console** : le réglage **Collection size (Bytes)** dans **Gestion →
  Réglages → Configuration du système → Configuration générale** (jeton
  `collection_max_size`). Il vient avec un million d'octets par défaut.

Si on n'en change qu'une, l'autre continue à couper.
