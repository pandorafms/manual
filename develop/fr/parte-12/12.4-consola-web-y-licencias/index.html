    Console web et licences¶

    Entrer dans la console et la garder en état : accès, réglages de sécurité et la licence qui habilite la plateforme.

    La console web est la porte d'entrée de la plateforme. Ici se rassemblent les problèmes d'accès, d'affichage, de sécurité et de licences.

    J'ai perdu le mot de passe administrateur¶

    La console n'apporte pas de « mot de passe oublié » par courrier pour l'administrateur, donc cela se règle depuis le serveur, avec l'outil de gestion :

    /usr/share/pandora_server/util/pandora_manage.pl /etc/pandora/pandora_server.conf \
    --create_user admin_temporaire CHANGEZ_CETTE_CLE 1

    Cela crée un utilisateur administrateur temporaire. On y entre avec lui, on change le mot de passe de l'utilisateur d'origine et on supprime l'utilisateur temporaire, pour ne pas laisser une porte ouverte.

    Ne laissez pas l'utilisateur temporaire

    La fiche d'origine proposait de le créer avec le mot de passe none. Ne le faites pas : mettez un vrai mot de passe et supprimez le compte dès que vous avez terminé.

    Changer le mot de passe d'un utilisateur depuis la ligne de commandes¶

    Avec le même pandora_manage.pl, sans créer de nouveaux comptes :

    /usr/share/pandora_server/util/pandora_manage.pl /etc/pandora/pandora_server.conf \
    --update_user ID_UTILISATEUR password NOUVEAU_MOT_DE_PASSE

    La commande sert aussi pour d'autres champs de l'utilisateur : courriel, téléphone, langue, thème (id_skin), nom complet et le fait d'être administrateur.

    La console apparaît vide ou avec des erreurs MySQL¶

    Deux causes, par ordre de fréquence :

    • Une mise à jour ou une installation à moitié faite. Un fichier de la console est resté corrompu. On réinstalle les paquets de la console dans la même version que celle déjà installée.
    • Il manque des MR du schéma. S'il y a en plus des erreurs MySQL, le plus probable est que la base de données est restée à un MR antérieur. On applique ceux qui manquent.

    Si cela ne règle pas le problème, on réinstalle la console depuis zéro en conservant include/config.php, le contenu de attachment et les images personnalisées.

    Je ne peux pas accéder et le disque est plein¶

    Quand le disque se remplit, MySQL ne peut pas écrire, la console ne s'ouvre pas et les nouvelles données cessent d'être traitées. On cherche ce qui l'a mangé :

    • Des sauvegardes qui s'accumulent et que personne ne supprime. C'est la première chose à regarder.
    • Des journaux qui ne sont pas purgés.
    • Des fichiers d'une taille anormale. On les déplace ou on les supprime, avec précaution.
    • La base de données. Les modules de texte (generic_data_string) sont ceux qui grossissent le plus : ils stockent de longues chaînes qui se répètent à chaque intervalle.

    Les graphiques n'affichent pas de texte¶

    Si le graphique sort sans axes ni valeurs, il manque la police avec laquelle le texte est dessiné. Le chemin est déclaré dans la configuration de la console, dans le réglage fontpath. Il faut vérifier que la police existe à ce chemin et que l'utilisateur du serveur web peut la lire.

    Avis

    Les anciennes fiches parlaient de la variable $config_homedir. Ce réglage n'existe plus : si aucun texte n'apparaît sur les graphiques, regardez fontpath.

    La console répond lentement¶

    Il y a deux endroits à regarder, et on les distingue avec le journal et avec la consommation :

    1. Le serveur web. Si les processus d'Apache consomment 100 % de CPU ou de mémoire, le problème est là : il manque des ressources, ou php.ini est court en mémoire (memory_limit). Les erreurs de limite de PHP apparaissent dans le journal d'Apache ou dans pandora_console.log.
    2. MySQL. Si le serveur web est à l'aise et que la console reste lente, le goulot d'étranglement est dans la base de données. Voir Serveur et base de données.

    J'ai perdu le générateur de codes de la double authentification¶

    La double authentification (2FA) se désactive pour un utilisateur depuis le serveur :

    /usr/share/pandora_server/util/pandora_manage.pl /etc/pandora/pandora_server.conf \
    --disable_double_auth '<utilisateur>'

    Cela sert autant si c'est vous qui avez perdu le générateur que si vous êtes l'administrateur et qu'une autre personne vous le demande. Si ce que vous voulez est la désactiver pour toute la console, il existe le réglage double_auth_enabled dans la table tconfig, mais pour un seul compte la commande est plus propre.

    Thèmes de la console et copie des styles¶

    Les thèmes se changent depuis la console web, dans les préférences de l'utilisateur. Avant de toucher aux icônes ou aux styles propres, il convient de faire une copie : le produit apporte styles_backup.sh dans le dossier d'utilitaires du serveur (pandora_server/util/), qui exporte les icônes et le CSS vers pandora_console/styles_backup dans deux fichiers compressés avec date et heure.

    Mettre la console en HTTPS¶

    La console est servie en HTTPS avec un certificat du serveur web :

    1. Ayez prêts le certificat et sa clé (.crt et .key). N'utilisez pas d'autosignés : ils ne sont pas fiables pour l'utilisateur et n'évitent pas les avertissements.
    2. Configurez Apache pour écouter sur le 443 et pointer vers ces fichiers (SSLCertificateFile et SSLCertificateKeyFile).
    3. Redémarrez le service web.
    4. Si vous voulez que personne n'entre en HTTP, activez dans Gestion → Réglages → Configuration du système → Configuration générale le réglage qui force l'usage de HTTPS.

    L'authentification AD ou LDAP ne fonctionne pas¶

    Pandora FMS admet les deux, et elles partagent presque toute la configuration. Si les utilisateurs n'entrent pas, on vérifie :

    • Le serveur et le port du LDAP ou du domaine.
    • La fonction de recherche : Local Command utilise la commande ldapsearch (elle doit être installée sur le serveur Pandora FMS) ; PHP function utilise le moteur propre de la console. Le normal est PHP function, et Local Command n'a de sens que dans de très grands environnements.
    • Le domaine de base et les unités organisationnelles / groupes : c'est ici que tout le monde se trompe. Le chemin de recherche doit pointer exactement là où sont les utilisateurs.

    Fuseau horaire de la console¶

    La console utilise le fuseau du système ; s'il n'est pas défini, elle prend l'européen. Si les données vous apparaissent avec une autre heure, ajustez le fuseau horaire dans Gestion → Réglages → Configuration du système → Configuration générale (réglage timezone).

    Les anciennes fiches proposaient d'éditer include/config_process.php et de forcer date_default_timezone_set. Cela fonctionne encore, mais c'est le plan B : mieux vaut le laisser cohérent avec le système d'exploitation.

    Notifications : les gérer et les supprimer¶

    • Les supprimer : depuis Espace de travail → Messages → Liste des messages, où l'on peut toutes les éliminer.
    • Les configurer : dans Gestion → Réglages → Configuration du système → Notifications, on les active ou on les désactive par type et on les assigne à des utilisateurs ou à des groupes. Chaque utilisateur a en plus sa propre configuration de ce qu'il veut recevoir.

    Où voir les échecs de PHP¶

    Il y a deux endroits, et il convient de regarder les deux :

    • Le journal du serveur web : error_log, ou ssl_error_log si la console passe en HTTPS. Vérifiez dans /etc/php.ini que le journal d'erreurs est actif et que le chemin est défini.
    • Le journal de la console elle-même : il faut l'activer dans Gestion → Réglages → Configuration du système → Configuration générale → Activer le journal de la console, et il s'écrit dans pandora_console/log/console.log.

    Pour déboguer temporairement, on peut augmenter le rapport de PHP depuis include/config.php de la console :

    error_reporting(E_ALL);

    Quand vous avez terminé, remettez-le plus bas : en production, il ne convient pas de laisser ce niveau.

    Priorité des champs personnalisés dans les alertes¶

    Quand le même champ (_field1_ à _field20_) est défini à plusieurs endroits, le moteur d'alertes applique cet ordre de précédence :

    Type d'alerte Ordre de précédence
    Alertes conventionnelles action > modèle d'alerte
    Alertes SNMP configuration de l'alerte SNMP > action > valeurs par défaut de la commande

    Dans les alertes conventionnelles, ce qui est défini dans l'action écrase ce qui vient du modèle. Dans les alertes SNMP, la configuration de l'alerte SNMP a la priorité maximale ; si elle est vide, on prend la valeur de l'action, et en dernier recours les valeurs par défaut de la commande.

    Modules WUX qui ne s'initialisent pas¶

    Les modules WUX (Web User Experience) exécutent des transactions web dans un client web réel au moyen de Selenium. Les contrôles périodiques sont réalisés par le serveur interne WUX Server de Pandora FMS. Si les modules restent sans s'initialiser, on vérifie :

    1. Le serveur WUX est activé sur le serveur. Dans /etc/pandora/pandora_server.conf, le jeton wuxserver doit être à 1 (par défaut, il est désactivé à 0).
    2. La connectivité avec Selenium. Le serveur Pandora FMS doit atteindre l'hôte et le port configurés dans wux_host et wux_port (par défaut localhost:4444).
    3. Le journal du serveur Pandora FMS (pandora_server.log et pandora_server.error) et le journal de Selenium lui-même, où sont détaillés les échecs de session ou de transaction.

    « Console et serveur dans des versions différentes »¶

    Cet avertissement apparaît quand la console et le serveur ne sont pas dans la même version. Même si la plateforme fonctionne, ce n'est pas une situation saine : il faut les aligner.

    • La version de la console se voit dans le pied de page de la console.
    • Celle du serveur, dans Serveurs → Gérer les serveurs.

    Le correct est de mettre à jour les deux vers la même version ; l'ordre est dans Mises à jour.

    Que le serveur se relève seul après une chute¶

    Dans les distributions modernes avec systemd, le service pandora_server.service lui-même inclut une directive de redémarrage automatique (Restart=always) par le superviseur du démon. Pour vous assurer que le service démarre avec le système d'exploitation et se rétablit si le processus tombe :

    systemctl enable --now pandora_server
systemctl status pandora_server

    Dans les déploiements à haute disponibilité multi-hôtes (grappe actif/passif), Pandora FMS dispose en plus de l'outil de grappe pandora_ha, qui surveille le battement en base de données des nœuds et gère la commutation selon le runbook de haute disponibilité.

    Quelle licence ai-je¶

    Le type de licence et sa date d'expiration se consultent dans la console elle-même, dans Gestion → Réglages → Configuration du système → Licence. Cet écran est celui qui fait foi : il montre la limite contractée, ce qui est en usage et quelle modalité est active.

    Les modèles possibles (perpétuelle ou abonnement, par agents ou par modules) et les pièces qui ont besoin d'une licence à part sont expliqués dans Licences. Ici, il n'est pas question de prix ni de tranches commerciales.

    La licence a expiré : comment la renouveler¶

    Le processus est le même que celui de la première installation, avec la nouvelle clé :

    1. Le fournisseur envoie l'AuthKey de la nouvelle période.
    2. Dans la console, entrez dans Gestion → Réglages → Configuration du système → Licence et choisissez Request new license.
    3. Introduisez l'AuthKey dans le champ de clé d'authentification et appuyez sur la validation en ligne.

    La console génère la licence, la valide contre le serveur et la laisse installée. Si l'installation n'a pas d'accès à internet, la même boîte de dialogue permet de l'activer à la main ; la procédure complète est dans Licences.

    J'ai mis à jour et je veux revenir en arrière¶

    Il n'y a pas de retour en arrière pris en charge. Une mise à jour ne se défait pas en réinstallant les anciens paquets : si quelque chose s'est mal passé, ce que l'on fait est de restaurer la sauvegarde ou l'instantané de la machine, ce qui est justement ce que l'on demande avant de commencer (voir Mises à jour).

    C'est pour cela la recommandation de toujours : instantané avant de toucher, et la mise à jour dans une fenêtre avec de la marge pour revenir au point de départ.

    Avis

    Réinstaller d'anciens paquets « par-dessus » laisse l'installation dans un état qui n'est pas pris en charge. S'il faut revenir en arrière, restaurez la copie ou l'instantané complet, y compris la base de données et les fichiers de la console.
