# Installation

Installer Pandora FMS est la partie facile du projet. Le difficile, c'est de
décider sur quoi il tourne, ce qui reste dehors et qui s'en souviendra dans deux
ans. Ce chapitre couvre l'installation du produit, ses exigences et les décisions
qu'il vaut mieux prendre avant d'exécuter la première commande, pas après.

## Ce qui va être installé

L'installateur en ligne de Pandora FMS monte sur une seule machine le **serveur**,
la **console web**, la **base de données** et, en option, un **EndPoint local**
pour superviser le serveur lui-même. C'est l'environnement *monolithe* et il
couvre la majorité des cas.

Les composants n'ont pas besoin de vivre ensemble. L'installation individuelle de
chaque pièce se fait après coup pour adapter l'architecture : base de données sur
un serveur dédié, OpenSearch à part, un ou plusieurs satellites pour les réseaux
distants ou plusieurs nœuds coordonnés depuis le Command Center. Ici on explique
l'installation standard ; les variantes sont dans la section
[Personnalisation de l'installation automatique](#personnalisation-de-linstallation-automatique).

Les composants installables de Pandora FMS sont :

- **Serveur** (`pandora_server`), avec sa base de données et le serveur Tentacle.
- **Console web** (`pandora_console`).
- **EndPoint** (`pandora_agent` et agents associés), sur l'équipement à superviser.
- **Satellite Server**, serveur autonome pour les réseaux distants.
- **OpenSearch**, moteur de stockage des logs, en option.
- **Command Center**, pour les environnements distribués.

Les exigences complètes de chaque composant sont plus bas, dans
[Exigences minimales](#exigences-minimales). Lisez-les avant de commencer ; elles
font la différence entre une installation qui tient des années et une qui donne sa
première frayeur au bout de trois mois.

## Prérequis

Avant de lancer l'installation en ligne :

| Exigence | Détail |
|---|---|
| Internet | Accès à internet et aux dépôts officiels de la distribution (RHEL / Rocky Linux / Ubuntu Server). |
| `curl` | Installé (il est fourni par défaut dans presque toutes les distributions). |
| Utilisateur | **root** (ou l'équivalent avec `sudo`). |
| Système d'exploitation | RHEL, Rocky Linux et AlmaLinux 9 ou 10, ou Ubuntu Server 22.04 ou 24.04. Plus de détail dans [Exigences du serveur](#exigences-du-serveur). |
| Matériel | Respecter les [exigences minimales de matériel](#exigences-du-serveur). |
| RHEL | Machine sous licence et abonnée aux dépôts standard. |

## Installation en ligne du serveur

Si la machine a internet, c'est la voie recommandée. L'installateur en ligne monte
l'environnement serveur complet en une seule étape.

```bash
curl -SsL https://pfms.me/deploy_pandora_one | PANDORA_LTS=1 bash
```

Le script détecte la distribution, télécharge l'installateur correspondant et fonctionne avec **RHEL**,
**Rocky Linux**, **AlmaLinux** et **Ubuntu Server**. Red Hat est l'option
recommandée ; le reste est pris en charge avec les versions indiquées par le
[tableau des systèmes d'exploitation](#exigences-du-serveur).

L'exécution précédente réalise une installation complète. L'installateur accepte
en plus des variables d'environnement pour la personnaliser (mots de passe de base
de données, version de MySQL et de PHP, canal LTS ou Feature Release, paquets
précis, etc.). Elles sont toutes regroupées plus bas, dans
[Personnalisation de l'installation automatique](#personnalisation-de-linstallation-automatique).

## Installation en ligne de l'EndPoint

L'EndPoint est le programme qui vit dans l'équipement supervisé. Il n'est pas
obligatoire (la supervision distante existe), mais c'est la seule façon d'obtenir
le maximum de détail : processus, inventaire, logs locaux.

### Linux

L'installateur en ligne fonctionne avec les distributions Red Hat (RHEL, Fedora,
Rocky), SUSE/OpenSUSE et Debian/Ubuntu. Il installe **toujours depuis un TAR**,
jamais depuis un RPM, et il vérifie que le paquet téléchargé est un EndPoint
authentique avant de le configurer contre votre serveur.

Installation minimale (agent GO, version LTS) :

```bash
export PANDORA_SERVER_IP='10.0.0.1'
curl -sSL https://pfms.me/agent-deploy | bash
```

L'installateur accepte des variables d'environnement pour automatiser
l'installation ou choisir le paquet. Elles sont toutes regroupées plus bas, dans
[Personnalisation de l'installation automatique](#personnalisation-de-linstallation-automatique).

Architectures prises en charge : `x86_64` avec binaires. Sur `x86`, `armv7l` et
`aarch64`, le script passe automatiquement à une compilation depuis les sources
(`PERL_SOURCES`). Sur d'autres architectures, le processus s'arrête.

### MS Windows

L'EndPoint est fourni comme auto-installeur `.exe`. Pour l'installation en ligne,
exécutez PowerShell en administrateur :

```powershell
Invoke-WebRequest -Uri https://marketplace.pandorafms.com/pandorafms/LTS/PandoraFMS_One_Agent_Windows-lts.x86_64.exe -OutFile ${env:tmp}\pandora-agent-windows.exe; & ${env:tmp}\pandora-agent-windows.exe /S --ip <IP_DU_SERVEUR> --group <GROUPE> --remote_config 1
```

Et démarrez le service :

```powershell
NET START PandoraFMSAgent
```

Les détails de l'installation manuelle et sans surveillance sont dans
[Installation hors ligne de l'EndPoint](#installation-hors-ligne-de-lendpoint).

## Installation du satellite

Le **Satellite Server** est un serveur *headless* (sans interface web) pensé pour
découvrir et superviser les réseaux distants que le serveur de Pandora FMS
n'atteint pas et où l'on ne peut pas non plus installer d'EndPoints : éléments de
réseau par SNMP/ICMP, serveurs Windows par WMI et Linux par SNMP. Il exécute
jusqu'à 500 contrôles par seconde, n'a pas besoin de connexion à la base de
données de Pandora FMS et envoie les données en XML.

### Installation en ligne

Systèmes d'exploitation pris en charge : **EL8, EL9 et EL10** (RHEL / Rocky
Linux, EL10 étant l'option recommandée ; des paquets existent pour x86_64 et
ARM64), **Ubuntu Server 22.04** (Ubuntu 24.04 n'est pas encore pris en charge) et
**Raspberry Pi OS** (Debian 12+, ARM64, avec le paquet spécifique pour
Raspberry).

```bash
export PANDORA_SERVER_IP='<IP ou FQDN du Pandora FMS Server>'
curl -Ls https://pfms.me/satellite-ent-deploy | bash
```

L'installateur accepte des variables d'environnement (canal de version, groupe par
défaut, configuration distante, installation de l'agent, etc.), regroupées plus bas
dans
[Personnalisation de l'installation automatique](#personnalisation-de-linstallation-automatique).

!!! info "Compatibilité"
    Le Satellite Server 785 n'est pas compatible avec les versions antérieures de
    Pandora FMS. Installez-le à côté d'un environnement 785 ou supérieur, sinon
    vous aurez des fonctions qui apparaissent mais ne fonctionnent pas.

## Installation d'OpenSearch

La collecte de logs est optionnelle, et pour l'activer il faut une instance
d'**OpenSearch**. **Elle ne s'installe pas par défaut** avec le serveur : c'est un
déploiement à part, et la recommandation est qu'elle vive sur un serveur
indépendant de celui de Pandora FMS.

```bash
curl -SsL https://pfms.me/pandorafms-opensearch-el | bash
```

L'installateur crée un nœud prêt à l'emploi, avec HTTPS et authentification par
mot de passe, et il est compatible avec **EL8 ou ultérieur et Ubuntu 22.04 Server**. Il
accepte des variables d'environnement pour le nom du cluster et le mot de passe,
regroupées plus bas dans
[Personnalisation de l'installation automatique](#personnalisation-de-linstallation-automatique).

Vérification que le nœud répond :

```bash
curl -X GET https://127.0.0.1:9200 -ku 'admin:<mot_de_passe>'
```

Changez aussi ce mot de passe. Appliquez le même critère qu'avec la base de
données : ce qui est publié ne protège rien.

## Exigences minimales

### Exigences du serveur

**Matériel.** Les valeurs sont des minimums, calculés en supposant que 80 % des
modules conservent un historique et un échantillonnage moyen de cinq minutes, avec
serveur, console et base de données sur la même machine :

| Matériel | Petit (≤ 1 000 modules) | Moyen (≤ 10 000) | Grand (≤ 30 000) | Très grand (≤ 80 000) |
|---|---|---|---|---|
| CPU | 2 cœurs à 2 GHz | 4 cœurs à 2,5 GHz | 6 cœurs à 3 GHz | 10 cœurs à 3 GHz |
| RAM | 4 GB | 8 GB | 16 GB | 32 GB |
| Stockage | 15K rpm ou SSD ≥ 300 MB/s | 15K rpm ou SSD ≥ 300 MB/s | SSD ≥ 300 MB/s | SSD ≥ 300 MB/s |
| Disque (minimum / recommandé) | 40 / 60 GB | 60 / 150 GB | 120 / 250 GB | 250 / 400 GB |

Si l'on conserve des informations sur plus d'un mois, il faut déployer une
[base de données d'historique](#installation-dune-base-de-donnees-externe-pour-lhistorique).

!!! warning "Virtualisation"
    Dans les environnements virtuels, attribuez à la machine un disque
    indépendant, avec de l'espace réservé et à haute vitesse. Mettre la base de
    données sur un volume partagé et fin, c'est la façon la plus fiable d'obtenir
    un goulot d'étranglement que personne ne localisera avant des semaines.

Au-delà de 80 000 modules, un seul nœud n'a plus de sens : il faut de la
supervision distribuée avec plusieurs nœuds (**Command Center**).

**Logiciel.**

| Logiciel | Exigences |
|---|---|
| Système d'exploitation | RHEL 10, Rocky Linux 10, AlmaLinux 10, RHEL 9 (recommandé), Rocky Linux 9 (recommandé), AlmaLinux 9 (recommandé), Ubuntu Server 22.04 et 24.04. |
| Console | PHP 8.4 depuis la version 785 ; PHP 8.2 de la 776 à la 784 ; PHP 8 de la 760 à la 775 ; PHP 7.4 de la 759 à la 767 ; PHP 7.2 de la 729 à la 758. |
| Base de données | Percona Server for MySQL 8 (recommandé, surtout au-delà de 4 000 agents), MySQL 8 ou MySQL 8.4 depuis la version 785. |
| Navigateurs | Chrome, Firefox, Opera et Edge. Pour les graphiques interactifs et les cartes réseau, Firefox ou Chrome. |
| systemd | Nécessaire depuis la version 779. Il est installé et activé sur les OS pris en charge. |

!!! info "EL10 et Ubuntu"
    **EL10** désigne l'ensemble des systèmes recommandés : Rocky Linux 10,
    AlmaLinux 10 et Red Hat 10. **L'installation hors ligne n'est pas prise en
    charge sur Ubuntu Server**, donc ne le choisissez pas pour un serveur sans
    connexion. Pour le Command Center, il est recommandé d'éviter Ubuntu.

Chaque version LTS de Pandora FMS prend en charge des versions précises de système
d'exploitation ; consultez la politique de prise en charge des versions d'OS avant
de décider.

**Permissions.**

| Exigence | Détail |
|---|---|
| Utilisateur d'installation | Le serveur s'installe en **root**. L'installation crée un utilisateur `pandora` affecté au groupe `root` ; il peut être changé ensuite, en tenant compte du fait qu'il faudra reconfigurer le serveur Tentacle. Il existe aussi l'installation avec un utilisateur non privilégié, avec une procédure à part. |
| Console | Apache a besoin de permissions de lecture et d'exécution sur les fichiers de la console ; `config.php` doit avoir les permissions `600`. |
| Serveur | Permissions d'écriture sur `/var/spool/pandora/`. |

### Exigences de l'EndPoint

L'EndPoint peut s'exécuter sur tout équipement disposant du système d'exploitation
minimal requis :

| Composant | Système d'exploitation |
|---|---|
| Pandora EndPoint 4.0 ou ultérieur | RHEL 10 / Rocky Linux 10 ; RHEL 6.x, 8 et 9 ; Fedora 34 ; CentOS 6.x, 7 et 8 ; AlmaLinux ; SLES 11 SP1 ou ultérieur ; OpenSUSE 11.x ou ultérieur ; Debian 5.x ou ultérieur ; Ubuntu Server ou Desktop 11 ou ultérieur ; Linux Mint ; Elementary OS ; Manjaro ; HPUX B.11.11 ou ultérieur avec Perl 5.8 ; AIX 4.3.3 ou ultérieur avec Perl 5.8 ; AIX 7.1 et 7.2 ; BSD (NetBSD, OpenBSD, FreeBSD) avec Perl 5.8 ; MacOS X 10.6 ou ultérieur ; Solaris 8 ou ultérieur avec Perl 5.8 ; Windows NT4, XP, 2000, 2003, 2008, 7, 8, 10, 11, 2012, Server 2016 et Server 2019. |
| Pandora Android EndPoint 2.0 ou ultérieur | Android 6 ou ultérieur. |
| Pandora Embedded EndPoint 4.0 ou ultérieur | Appareils *embedded* ; nécessite une compilation. |

Sur les systèmes de type `*nix`, **systemd** doit être installé et démarré. Dans
les environnements UNIX, en plus :

| Exigence | Détail |
|---|---|
| Perl | 5.8 ou ultérieur. |
| Dépendances | `perl-YAML-Tiny-1.73-2`, `perl-Sys-Syslog` et `unzip`. |
| logrotate | Configuré pour l'agent (bloc suivant). |

```bash
cat> /etc/logrotate.d/pandora_agent <<EO_LRA
/var/log/pandora/pandora_agent.log {
        su root apache
        weekly
        missingok
        size 300000
        rotate 3
        maxage 90
        compress
        notifempty
        copytruncate
}
EO_LRA
chmod 0644 /etc/logrotate.d/pandora_agent
```

Sur Linux, l'EndPoint s'exécute en **root** pour disposer de toutes les
fonctionnalités ; sur Windows, avec des permissions d'administrateur.

### Exigences du satellite

| Satellite | Détails |
|---|---|
| Matériel (Windows) | x64 ; minimum 2 cœurs à 2 GHz (4 recommandé) ; minimum 6 GB de RAM (8 recommandé) ; disque minimum 5 GB (10 recommandé). |
| Matériel (Linux) | x64 ; minimum 2 cœurs à 2 GHz (4 recommandé) ; minimum 4 GB de RAM (6 recommandé) ; disque minimum 5 GB (10 recommandé). |
| Systèmes d'exploitation | Linux 64 bits ; MS Windows 64 bits. |
| Dépendances | `fping`, `nmap`, `perl`, `pandorawmic` (version NG 762 ou ultérieure) et `libnsl` ; `snmp` pour SNMP. |

Sur Rocky Linux 8 ou ultérieur, il faut d'abord configurer le dépôt EPEL. Sur
Windows, selon la version du système, il faut installer Microsoft Visual C++
Redistributable.

### Exigences d'OpenSearch

| Exigence | Détail |
|---|---|
| Système d'exploitation | RHEL, Rocky Linux ou AlmaLinux 8 ou ultérieur ; Ubuntu Server 22.04. |
| RAM | Minimum 4 GB (dev/testing) ; recommandé 8 GB par instance. Il faut l'estimer selon le volume de données. |
| CPU | Minimum 4 cœurs. |
| SWAP | Désactivé sur le ou les nœuds OpenSearch. |
| Stockage | 50 GB de disque système et 100 GB pour OpenSearch. |
| Connectivité | Depuis le serveur et la console de Pandora FMS vers l'API OpenSearch (`9200/TCP`) et entre nœuds de cluster (`9300/TCP`). |

Un seul nœud avec ces caractéristiques stocke jusqu'à 1 GB de données par jour
pendant 30 jours. Pour plus de résilience et de capacité, on configure un
**cluster** (minimum 3 nœuds pour garantir l'intégrité des données) et on répartit
la charge avec un répartiteur de type **Keepalived**.

### Exigences du SIEM

| Exigence | Détail |
|---|---|
| OpenSearch | Base de données **OpenSearch sur une instance dédiée**. |
| Collecte de logs | Activée. |
| Ressources du nœud | Minimum **4 cœurs, 8 GB de RAM et 100 GB de disque SSD**. |
| Instance SIEM | Un serveur dédié est recommandé pour `siemserver` et `siemevents`. |
| Licence | Avec la fonctionnalité SIEM activée. |

Une fois les exigences remplies, le SIEM s'active depuis la console dans
**Management → Settings → System Settings → SIEM → Activate SIEM**. À
l'enregistrement, les modèles de normalisation sont créés dans OpenSearch et
`siemserver` et `siemevents` sont activés sur les serveurs correspondants.

## Personnalisation de l'installation automatique

### Serveur et console

#### Valeurs pour l'installateur en ligne

L'exécution de base installe l'environnement complet. Ces variables
d'environnement la personnalisent (valeurs pour RHEL et Rocky Linux) :

| Variable | Fonction | Par défaut |
|---|---|---|
| `TZ` | Fuseau horaire de la machine ; s'il n'est pas défini, il n'est pas modifié | Inchangé |
| `DBHOST` | Hôte de la base de données | `127.0.0.1` |
| `DBNAME` | Nom de la base à créer | `pandora` |
| `DBUSER` | Utilisateur de la base | `pandora` |
| `DBPASS` | Mot de passe de l'utilisateur | `Pandor4!` |
| `DBPORT` | Port de la base | `3306` |
| `DBROOTPASS` | Mot de passe root de la base | `Pandor4!` |
| `SKIP_PRECHECK` | Ignorer la vérification d'installation préalable | `0` |
| `SKIP_DATABASE_INSTALL` | Ne pas installer la base (en utiliser une externe) | `0` |
| `SKIP_KERNEL_OPTIMIZATIONS` | Ignorer l'optimisation du noyau | `0` |
| `SKIP_DOCKER_INSTALL` | Ne pas installer Docker (il est installé, et laissé désactivé, pour le débogage) | `0` |
| `POOL_SIZE` | Mémoire de MySQL (buffer pool) | Automatique |
| `MYVER` | Version de MySQL (`80` ou `84` ; sur EL10, seulement `84`) | `84` |
| `PHPVER` | Version de PHP (`8.2` ou `8.4`) | `8.4` |
| `PANDORA_SERVER_PACKAGE` | URL du tarball du serveur | dernière disponible |
| `PANDORA_CONSOLE_PACKAGE` | URL du paquet de la console (RPM sur EL, tarball de sources sur Ubuntu) | dernière disponible |
| `PANDORA_AGENT_PACKAGE` | URL du tarball de l'agent | dernière disponible |
| `PANDORA_BETA` | Installer la bêta (`1`) | `0` |
| `PANDORA_LTS` | Installer la branche LTS au lieu de Feature Release | `1` |

La liste est la même sur RHEL, Rocky Linux, AlmaLinux et Ubuntu Server. Sur EL10,
l'installateur ne prend en charge que MySQL 8.4 (`MYVER=84`). `POOL_SIZE` se calcule
automatiquement d'après la mémoire de la machine (25 % en dessous de 7,5 Go et 40 %
au-dessus) ; ne le fixez que pour une autre répartition. Docker est installé, et
laissé désactivé, uniquement pour les tâches de débogage : avec
`SKIP_DOCKER_INSTALL=1`, il n'est pas installé.

Exemple sur EL10 avec des valeurs explicites :

```bash
env TZ='Europe/Madrid' \
    DBHOST='127.0.0.1' \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='ChangezCeMotDePasse' \
    DBPORT='3306' \
    DBROOTPASS='ChangezCeMotDePasseRoot' \
    MYVER=84 \
    PHPVER=8.4 \
    SKIP_PRECHECK=0 \
    SKIP_DATABASE_INSTALL=0 \
    SKIP_KERNEL_OPTIMIZATIONS=0 \
    PANDORA_BETA=0 \
    PANDORA_LTS=1 \
    bash -c "$(curl -fsSL https://pfms.me/deploy_pandora_one)"
```

!!! warning "Changez les mots de passe par défaut"
    `Pandor4!` est écrit dans la documentation publique. C'est le premier que
    tentera toute personne qui sait par où entrer. Le laisser en place n'est pas
    une négligence, c'est laisser la porte ouverte et poser le paillasson.

#### Valeurs d'optimisation du noyau

L'installateur en ligne ajuste certains paramètres du noyau. Avec
`SKIP_KERNEL_OPTIMIZATIONS=1`, il n'y touche pas, mais il vaut mieux savoir ce que
l'on perd : ce sont des réglages pensés pour que le serveur supporte beaucoup de
connexions simultanées sans que le système d'exploitation devienne le goulot
d'étranglement.

| Paramètre | Par défaut | Fixé par Pandora | Ce qu'il fait |
|---|---|---|---|
| `net.ipv4.tcp_syn_retries` | 5 | 3 | Tentatives lors de l'envoi d'une demande de connexion TCP avant de la considérer comme échouée. |
| `net.ipv4.tcp_synack_retries` | 5 | 3 | Tentatives lors de la réception de l'accusé de réception d'une connexion TCP. |
| `net.ipv4.tcp_max_syn_backlog` | 1024 | 65536 | Taille maximale de la file des connexions TCP en attente d'acceptation. |
| `net.core.wmem_max` | 124928 | 8388608 | Tampon maximal d'envoi de données par connexion réseau. |
| `net.core.rmem_max` | 131071 | 8388608 | Tampon maximal de réception de données par connexion réseau. |
| `net.core.somaxconn` | 128 | 1024 | Connexions en attente dans la file d'écoute des sockets. |
| `net.core.optmem_max` | 20480 | 81920 | Tampon maximal pour les options de socket. |

Ne les touchez pas à la main, sauf si vous savez exactement ce que vous faites.
Laissez `SKIP_KERNEL_OPTIMIZATIONS=0` et laissez l'installateur faire son travail.

#### Installation sur une base de données externe

S'il existe un serveur dédié pour la base de données, la marche à suivre est :
créer la base et l'utilisateur, lui donner toutes les permissions sur cette base et
installer avec `SKIP_DATABASE_INSTALL=1` et les valeurs de connexion. Avant
d'installer, testez la connexion depuis le futur serveur de Pandora FMS. Découvrir
le pare-feu à deux heures du matin s'évite avec cinq minutes de vérification.

```bash
env DBHOST='192.168.1.107' \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='ChangezCeMotDePasse' \
    DBPORT='3306' \
    SKIP_DATABASE_INSTALL=1 \
    bash -c "$(curl -fsSL https://pfms.me/deploy_pandora_one)"
```

Restreignez l'utilisateur de la base de données à l'IP du serveur de Pandora FMS :
si le mot de passe se retrouve compromis, qu'il ne serve depuis nulle part ailleurs.

#### Installation d'une base de données externe pour l'historique

Pour déployer une base de données dédiée (historique compris), il existe un
installateur en ligne propre. Il ne demande que `curl` et un système compatible :

- **EL9** : Rocky Linux 9.x ou RHEL 9.x.
- **EL10** : Rocky Linux 10 ou RHEL 10.
- **Ubuntu** : 22.04.

```bash
curl -fsSL https://pfms.me/db-deploy-el9 | bash
```

Sur Ubuntu :

```bash
curl -fsSL https://pfms.me/db-deploy-u2204 | bash
```

Variables prises en charge :

| Variable | Description | Par défaut |
|---|---|---|
| `TZ` | Fuseau horaire de la machine ; s'il n'est pas défini, il n'est pas modifié | Inchangé |
| `MYVER` | Version de MySQL (8.0 ou 8.4) | `84` |
| `DBNAME` | Nom de la base à créer | `pandora` |
| `DBUSER` | Utilisateur de la base | `pandora` |
| `DBPASS` | Mot de passe de l'utilisateur | `Pandor4!` |
| `DBROOTPASS` | Mot de passe de l'utilisateur root | `Pandor4!` |
| `SKIP_KERNEL_OPTIMIZATIONS` | Ignorer les optimisations du noyau | `0` |
| `POOL_SIZE` | Mémoire pour MySQL (buffer pool) | Automatique |

```bash
env TZ='Europe/Madrid' \
    MYVER=84 \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='ChangezCeMotDePasse' \
    DBROOTPASS='ChangezCeMotDePasseRoot' \
    POOL_SIZE=4G \
    bash -c "$(curl -fsSL https://pfms.me/db-deploy-el9)"
```

#### Installation dans un autre chemin

Pour installer le serveur dans un autre chemin, l'installateur accepte
`--destdir` :

```bash
./pandora_server_installer --install --destdir <destdir>
```

Ensuite, il faut configurer le démarrage automatique et le script de maintenance
`pandora_db` dans le cron :

```bash
echo "\"<destdir>/usr/share/pandora_server/util/pandora_db\" \
 \"<destdir>/etc/pandora/pandora_server.conf\">/dev/null 2>&1"> /etc/cron.hourly/pandora_db
```

#### Installation avec un utilisateur non privilégié

L'installateur accepte de s'exécuter avec un utilisateur sans privilèges :

```bash
./pandora_server_installer --install --no-root --destdir /opt/pandora
```

Cet utilisateur doit avoir des permissions d'écriture sur le chemin indiqué dans
`--destdir`.

#### Installation avec un utilisateur non privilégié

Il peut aussi s'exécuter avec un utilisateur autre que `root`. Par exemple, avec

```bash
./pandora_agent_installer --install /home/pandora pandora

En spécifiant un utilisateur personnalisé, l'installation doit aller dans un

`pandora` est désactivé par défaut : pour l'utiliser, il faut lui donner un *shell*

### Satellite

#### Valeurs pour l'installateur en ligne

| Variable | Par défaut | Description |

| `VERSION` | `LATEST` | Canal d'installation : `LATEST` ou `LEGACY`. `LEGACY` n'est pas compatible avec Pandora FMS 785 ou supérieur (l'installateur avertit et demande confirmation) et n'existe que pour x86_64. |

| `INSTALL_AGENT` | `1` | Installe l'EndPoint sur le satellite lui-même (`1`=oui). |
| `PANDORA_GROUP` | `Servers` | Groupe par défaut des agents du satellite. |
| `SKIP_KERNEL_OPTIMIZATIONS` | `0` | Omet les réglages de performance du noyau (`1`=omettre). |
| `RHEL_CHECK_SUBSCRIPTION` | `1` | Vérifie les abonnements actifs sur RHEL (`1`=oui). |
| `PANDORA_SKIP_CONFIRMATION` | `0` | Installation sans surveillance et sans confirmations (`1`=oui). |
| `PANDORA_BETA` | `0` | Installe la version bêta de développement (`1`=oui). |
| `SATELLITE_SERVER_PACKAGE` | Sélection automatique | URL personnalisée du tarball du Satellite Server. |

env TZ='Europe/Madrid' \

```

En outre, l'installation manuelle demande de fixer le jeton `server_ip` dans

## Installation hors ligne

Pour les environnements sans connexion à internet. **Elle n'est pas prise en
charge sur Ubuntu.**

### Installation hors ligne du serveur

Les systèmes compatibles sont **RHEL 9 / Rocky Linux 9** et **RHEL 10 / Rocky
Linux 10**.

Étapes :

1. Disposer d'une instance propre, avec les exigences matérielles et le système
   d'exploitation pris en charge.
2. Télécharger le paquet *offline* pour le système d'exploitation depuis le
   portail de support (disponible pour les versions LTS et LTS précédentes).
3. Téléverser le tarball sur le serveur.
4. Le décompresser et exécuter l'installateur :

```bash
tar xvzf <offline_package>.tar.gz
cd pandora_packages/
./pandora_deploy_enterprise_local_el9.sh
```

Sur EL10, le script est `pandora_deploy_enterprise_local_el10.sh`. Quand le
processus se termine, on accède à la console web avec l'utilisateur `admin` et le
mot de passe `pandora`.

### Installation hors ligne du satellite

#### Installation manuelle sous Linux

Une fois les dépendances installées et le paquet téléchargé, on le décompresse et
on exécute l'installateur :

```bash
tar -xvzf pandorafms_satellite_server_X.XNG.XXX_x86_64.tar.gz
cd satellite_server/
./satellite_server_installer --install
```

Ensuite, il faut éditer `/etc/pandora/satellite_server.conf` et fixer le jeton
`server_ip` avec l'adresse du Pandora FMS Server. Le service se démarre avec :

```bash
systemctl start satellite_serverd
```

Le journal est dans `/var/log/satellite_server.log`.

#### Installation sous MS Windows

L'installateur (signé depuis la version 762) inclut Nmap et Visual C++
Redistributable de MS Visual Studio 2015-2022. Il s'exécute avec les droits
d'administrateur : on saisit la licence, on configure l'adresse du serveur et les
règles d'exploration, puis on redémarre la machine. Si les requêtes WMI échouent,
il faut exécuter le service du Satellite Server avec un compte Administrateur.

### Installation hors ligne de l'EndPoint

L'EndPoint s'installe depuis le paquet tarball, valable pour tout
Unix/Linux/macOS. Il ne demande pas de compilation.

```bash
tar xvzf pandorafms_one_agent_linux-latest.tar.gz
cd unix
./pandora_agent_installer --install
systemctl start pandora_agent_daemon
```

`libnsl` peut devoir être installé manuellement. Si l'on utilise les sources
(`.src.tar.gz`), il y a des dépendances Perl supplémentaires, dont `YAML::Tiny` et
`Thread::Semaphore`. Sous FreeBSD et NetBSD, l'emplacement des fichiers et le
script de démarrage changent : l'agent reste dans `/usr/local/bin/pandora_agent`,
le script dans `/usr/local/etc/rc.d/pandora_agent`, la configuration dans
`/usr/local/etc/pandora/pandora_agent.conf`, et il faut ajouter
`pandora_agent_enable="YES"` à `/etc/rc.conf`.

Après l'installation, il faut éditer `/etc/pandora/pandora_agent.conf` pour
pointer vers le serveur et, en recommandation, activer la configuration distante :

```bash
sed -i "s/^remote_config.*$/remote_config 1/g" /etc/pandora/pandora_agent.conf
systemctl enable pandora_agent_daemon
```

#### Windows sans surveillance

L'installateur Windows prend en charge le mode sans surveillance depuis la version
5.1 de l'EndPoint :

```
"PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S
```

Chemin personnalisé :

```
"PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S /D=C:\PFMS_agent
```

Paramètres écrits dans la configuration de l'EndPoint : `--ip` (`server_ip`),
`--group` (`group`), `--alias` (`agent_alias`) et `--remote_config`
(`remote_config`). Exemple :

```
"PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S --ip 192.168.0.59 --group Applications --alias Mifunne --remote_config 1
```

## Vérification

Une fois l'installation terminée, ouvrez la console à l'adresse
`http://<serveur>/pandora_console/` et confirmez qu'elle charge l'écran de
connexion. L'utilisateur initial est `admin` avec le mot de passe `pandora`.

Vérifiez ensuite que les services du composant installé sont actifs :

| Composant | Services | Journal |
|---|---|---|
| Serveur | `pandora_server` et `tentacle_serverd` | `/var/log/pandora/pandora_server.log` |
| Satellite | `satellite_serverd` | `/var/log/satellite_server.log` |
| EndPoint (Linux) | `pandora_agent_daemon` | `/var/log/pandora/pandora_agent.log` |

```bash
systemctl status pandora_server tentacle_serverd
```

Un service à l'état `failed` en explique presque toujours la cause dans son
journal : lisez-le avant de réinstaller quoi que ce soit. Si l'EndPoint a été
installé contre un serveur, il devrait apparaître en quelques minutes comme
nouvel agent dans **Surveillance → Vues → Détail de l'agent**.

!!! warning
    Changez le mot de passe à la première connexion. Et si vous avez installé avec
    un utilisateur personnalisé ou un chemin différent, vérifiez le démarrage des
    services avant de vous déclarer satisfait ; la panne que l'on ne vérifie pas
    aujourd'hui devient un incident lundi.

## Désinstallation

Les installateurs **ne sont pas copiés** pendant l'installation, donc on ne peut
pas recourir à leur `--uninstall` après coup. La désinstallation doit se faire à
la main : voici les fichiers et les dossiers que laisse chaque composant et les
commandes pour les retirer (en **root**). Si plusieurs composants cohabitent sur la
même machine, ne supprimez pas les répertoires partagés avant de les avoir tous
retirés.

### Serveur

- Binaires dans `/usr/bin` : `pandora_server`, `pandora_exec`, `pandora_supervisor`,
  `pandora_db`, `pandora_ha`, `pandora_manage`, `pandora_revent`,
  `pandora_encrypt_db`, `braa`, `pandorafsnmp`, `pandorawmic`,
  `pandora_iot_server`, `pandora_netflow_server`, `tentacle_server`,
  `tentacle_client`, `clean_pandora_server`, `clean_tentacle_serverd` et
  `clean_tentacle_rmm`.
- Bibliothèques et utilitaires : `/usr/share/pandora_server`.
- Services : `/etc/systemd/system/pandora_server.service`, `pandora_ha.service`,
  `tentacle_serverd.service`, `tentacle_rmm.service`,
  `pandora_iot_server.service` et `pandora_netflow_server.service`.
- Tâches et rotation : `/etc/cron.hourly/pandora_db` et
  `/etc/logrotate.d/pandora_server`.
- Configuration : `/etc/pandora/pandora_server.conf`, `pandora_server.env`,
  `pandora_server_extra.env`, `/etc/pandora/conf.d` et `/etc/tentacle`.
- Données, logs et PID : `/var/spool/pandora`, `/var/log/pandora` et
  `/var/run/pandora_supervisor.pid`.

```bash
systemctl stop pandora_server pandora_ha tentacle_serverd tentacle_rmm \
  pandora_iot_server pandora_netflow_server
systemctl disable pandora_server pandora_ha tentacle_serverd tentacle_rmm \
  pandora_iot_server pandora_netflow_server
rm -f /etc/systemd/system/{pandora_server,pandora_ha,tentacle_serverd,tentacle_rmm,pandora_iot_server,pandora_netflow_server}.service
systemctl daemon-reload
rm -f /usr/bin/{pandora_server,pandora_exec,pandora_supervisor,pandora_db,pandora_ha,pandora_manage,pandora_revent,pandora_encrypt_db,braa,pandorafsnmp,pandorawmic,pandora_iot_server,pandora_netflow_server,tentacle_server,tentacle_client,clean_pandora_server,clean_tentacle_serverd,clean_tentacle_rmm}
rm -Rf /usr/share/pandora_server
rm -f /etc/cron.hourly/pandora_db /etc/logrotate.d/pandora_server
```

Et, s'il ne reste aucun autre composant, la configuration et les données
partagées :

```bash
rm -Rf /etc/pandora /etc/tentacle /var/spool/pandora /var/log/pandora
```

### Console

Cela dépend de la façon dont elle a été installée :

- **RPM (RHEL / Rocky Linux)** : elle se retire avec le gestionnaire de paquets.

```bash
dnf remove pandorafms_console
```

- **Tarball (Ubuntu)** : elle a été copiée dans `/var/www/html/pandora_console` et
  a laissé sa rotation de logs.

```bash
rm -Rf /var/www/html/pandora_console
rm -f /etc/logrotate.d/pandora_console
```

La console partage avec le serveur le répertoire `/var/spool/pandora/data_in`
(`collections`, `conf`, `md5`, `netflow`) : ne le supprimez pas s'il y a un
serveur. Elle ne touche pas à la base de données ; cela se fait à part.

### Base de données

L'installation crée la base `pandora` et l'utilisateur `pandora`. Si MySQL ou
Percona ne servaient qu'à Pandora FMS :

```bash
systemctl stop mysqld
mysql -u root -p -e "DROP DATABASE pandora; DROP USER 'pandora'@'localhost';"
dnf remove 'Percona-Server*'        # RHEL/Rocky ; sous Ubuntu, apt remove percona-server-server ou mysql-server
rm -Rf /var/lib/mysql /etc/my.cnf /etc/my.cnf.d
```

Si la base est sur un autre serveur ou héberge des données d'autres applications,
limitez l'opération à `DROP DATABASE` et `DROP USER`.

### Satellite

- Binaires dans `/usr/bin` : `satellite_server`, `tentacle_client`,
  `pandorafsnmp`, `wmic`, `pandorawmic` et `clean_satellite_serverd`.
- Configuration : `/etc/pandora/satellite_server.conf`,
  `satellite_server.env`, `satellite_server_extra.env`,
  `/etc/pandora/satellite_plugins` et le répertoire d'agents `/etc/pandora/conf`.
- Démarrage : `/etc/init.d/satellite_serverd` (avec son lien dans `/etc/rc.d`) et
  `/etc/systemd/system/satellite_serverd.service`.
- Rotation, logs et fichiers temporaires : `/etc/logrotate.d/pandora_satellite`,
  `/var/log/satellite_server.log` et `/var/spool/pandora/tmp/satellite_server`.

```bash
systemctl stop satellite_serverd
systemctl disable satellite_serverd
rm -f /etc/systemd/system/satellite_serverd.service
systemctl daemon-reload
rm -f /etc/init.d/satellite_serverd
rm -f /etc/rc.d/rc?.d/S90satellite_server
rm -f /usr/bin/{satellite_server,tentacle_client,pandorafsnmp,wmic,pandorawmic,clean_satellite_serverd}
rm -Rf /etc/pandora/satellite_plugins /etc/pandora/conf /var/spool/pandora/tmp/satellite_server
rm -f /etc/pandora/satellite_server.conf /etc/pandora/satellite_server.env /etc/pandora/satellite_server_extra.env
rm -f /etc/logrotate.d/pandora_satellite /var/log/satellite_server.log
```

Le répertoire `/opt/pandorafms/perl5` du satellite est partagé avec d'autres
composants : ne le supprimez que s'il ne reste aucun composant installé.

### EndPoint

Sur Linux et Unix, il laisse :

- Binaires dans `/usr/bin` : `pandora_agent`, `pandora_agent_exec`,
  `pandora_revent`, `tentacle_client` et `clean_pandora_agent_daemon`.
- Répertoire de base de l'agent : `/usr/share/pandora_agent` (`plugins`,
  `collections`, `commands`, `ref`).
- Configuration : `/etc/pandora/pandora_agent.conf` et `pandora_agent.env`.
- Démarrage : `/etc/systemd/system/pandora_agent_daemon.service` (ou le script de
  `/etc/init.d`).
- Rotation, logs et pages `man` : `/etc/logrotate.d/pandora_agent`,
  `/var/log/pandora/pandora_agent.log`,
  `/usr/share/man/man1/pandora_agent.1.gz` et `tentacle_client.1.gz`.

```bash
systemctl stop pandora_agent_daemon
systemctl disable pandora_agent_daemon
rm -f /etc/systemd/system/pandora_agent_daemon.service
systemctl daemon-reload
rm -f /usr/bin/{pandora_agent,pandora_agent_exec,pandora_revent,tentacle_client,clean_pandora_agent_daemon}
rm -Rf /usr/share/pandora_agent
rm -f /etc/pandora/pandora_agent.conf /etc/pandora/pandora_agent.env
rm -f /etc/logrotate.d/pandora_agent /var/log/pandora/pandora_agent.log
rm -f /usr/share/man/man1/pandora_agent.1.gz /usr/share/man/man1/tentacle_client.1.gz
```

S'il y a un serveur ou un satellite sur la même machine, ne supprimez pas
`/etc/pandora` ni `/var/spool/pandora` en entier.

**MS Windows** inclut bien un désinstalleur. De façon automatisée :

```
"%ProgramFiles%\pandora_agent\uninst.exe" /S
```

Ou depuis le binaire de l'agent :

```
pandoraagent.exe --uninstall
```
