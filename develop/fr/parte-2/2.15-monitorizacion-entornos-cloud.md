# Supervision des environnements Cloud

Dans le cloud, il n'y a pas de serveur où installer un EndPoint : il y a une
API. Pandora FMS l'interroge depuis Discovery avec un compte en lecture seule et
transforme ce qu'il trouve en agents et en modules, de sorte que les instances,
les bases de données, le stockage et les coûts de chaque fournisseur apparaissent
dans la console web comme n'importe quel autre élément supervisé.

| Fournisseur | Services couverts | Guides de l'intégration |
|---|---|---|
| Amazon Web Services | Instances EC2, bases de données RDS, stockage S3, métriques CloudWatch, prix et coûts. | [EC2](https://pandorafms.com/docs/integrations/latest/fr/discovery/amazon-ec2/), [RDS](https://pandorafms.com/docs/integrations/latest/fr/discovery/amazon-rds/), [S3](https://pandorafms.com/docs/integrations/latest/fr/discovery/amazon-s3/), [CloudWatch](https://pandorafms.com/docs/integrations/latest/fr/discovery/amazon-cloudwatch/), [Pricing](https://pandorafms.com/docs/integrations/latest/fr/discovery/aws-pricing/) |
| Microsoft Azure | Machines virtuelles, SQL, stockage, Application Gateway, Load Balancer et sauvegardes. | [Compute](https://pandorafms.com/docs/integrations/latest/fr/discovery/azure-microsoft-compute/), [SQL](https://pandorafms.com/docs/integrations/latest/fr/discovery/azure-sql/), [Storage](https://pandorafms.com/docs/integrations/latest/fr/discovery/azure-storage/), [Application Gateway](https://pandorafms.com/docs/integrations/latest/fr/discovery/azure-application-gateway/), [Load Balancer](https://pandorafms.com/docs/integrations/latest/fr/discovery/azure-load-balancer/), [Backup](https://pandorafms.com/docs/integrations/latest/fr/discovery/azure-backup/) |
| Google Cloud | Instances de Compute Engine. | [Compute Engine](https://pandorafms.com/docs/integrations/latest/fr/discovery/google-cloud-compute-engine/) |
| OVHcloud | Instances et volumes de Public Cloud, serveurs dédiés et coûts. | [OVH](https://pandorafms.com/docs/integrations/latest/fr/discovery/ovh/) |
| DigitalOcean | Droplets et consommation du compte. | [DigitalOcean](https://pandorafms.com/docs/integrations/latest/fr/discovery/digital-ocean/) |

Le catalogue de services de chaque fournisseur grandit et change souvent ; c'est
pourquoi ce chapitre ne les énumère pas en détail : les guides du tableau sont la
référence en vigueur de ce qui est supervisé, des permissions que requiert chaque
service et de leurs paramètres. L'installation d'un paquet .disco et le cycle
commun de ses tâches sont dans
[Comment fonctionne la tâche d'un paquet .disco](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#comment-fonctionne-la-tache-dun-paquet-disco).

Avant de créer une tâche, il convient de préparer chez le fournisseur une
identité dédiée avec des permissions en lecture seule, limitée aux services qui
seront interrogés. Ses identifiants se conservent dans le
[gestionnaire d'identifiants](2.2-gestor-de-credenciales.md) et ne se copient ni
dans des fichiers ni dans la documentation interne. Il convient de vérifier dans
chaque guide si les requêtes à l'API ont un coût ou un quota chez le
fournisseur.

## Amazon Web Services

Chaque service d'AWS a sa propre intégration : EC2 pour les instances, RDS pour
les bases de données, S3 pour les buckets, CloudWatch pour les requêtes de
métriques définies par l'utilisateur et Pricing pour les prix publics et les
coûts facturés. Elles s'authentifient avec une clé d'accès AWS associée à un
utilisateur disposant de permissions de lecture. En général, chaque tâche génère
un agent par région et, en option, un agent global avec des statistiques. Les
permissions exactes et les options de chaque service sont dans leurs guides.

## Microsoft Azure

Azure se supervise par services : machines virtuelles, bases de données SQL,
comptes de stockage, Application Gateway, Load Balancer et sauvegardes. Les
intégrations lisent un abonnement au moyen d'une application enregistrée avec un
accès en lecture et obtiennent les métriques d'Azure Monitor. On peut choisir
entre un agent par ressource et un agent consolidé, selon le guide de chaque
service.

## Google Cloud

L'intégration de Google Cloud supervise les instances de Compute Engine d'un
projet et les zones qui les contiennent, en interrogeant les API de Compute
Engine et de Cloud Monitoring avec un compte de service. Les exigences et les
paramètres sont dans le
[guide de Compute Engine](https://pandorafms.com/docs/integrations/latest/fr/discovery/google-cloud-compute-engine/).

## OVHcloud et DigitalOcean

Ces deux fournisseurs ont une intégration propre qui se connecte à leur API.
OVHcloud couvre les instances et les volumes de Public Cloud, les serveurs
dédiés et, si on le souhaite, les coûts. DigitalOcean couvre les droplets et la
consommation du compte. Chaque guide explique comment obtenir les identifiants
d'API nécessaires et quels agents la tâche génère.

## Résultats et premières vérifications

Après avoir exécuté la tâche :

1. Examiner les erreurs d'exécution et confirmer que l'identité en lecture seule
   a des permissions suffisantes. Une permission manquante se traduit souvent
   par des agents sans modules, non par une erreur évidente.
2. Chercher les agents attendus : un global et plusieurs par région, ressource ou
   service, selon l'intégration.
3. Vérifier que les modules reçoivent des données récentes et comparer un
   échantillon avec la console du fournisseur lui-même.
4. Vérifier, selon le guide, si les requêtes à l'API ont un coût ou un quota.

Le diagnostic spécifique relève du guide de chaque service. Pour les erreurs du
cycle de la tâche, voir
[Quand cela échoue](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#quand-cela-echoue).
