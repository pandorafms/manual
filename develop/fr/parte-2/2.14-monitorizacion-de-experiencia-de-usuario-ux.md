# Supervision de l'expérience utilisateur (UX)

Vérifier qu'un port répond ne dit pas si l'utilisateur parvient à ouvrir une
session, à chercher un produit ou à finaliser une commande. La supervision de
l'expérience utilisateur parcourt ce flux comme le ferait une personne, le
chronomètre phase par phase et prévient quand il se casse ou se ralentit.
Pandora FMS la résout avec des transactions synthétiques : un parcours enregistré
ou écrit, répété périodiquement, dont le résultat devient des agents et des
modules.

| Outil | Ce qu'il automatise | Comment il s'exécute | Guide de l'intégration |
|---|---|---|---|
| **Playwright** (recommandé pour le web) | Un test Playwright qui parcourt une application web. | Tâche de Discovery ; le test s'exécute dans un conteneur Docker. | [Playwright](https://pandorafms.com/docs/integrations/latest/fr/discovery/playwright/) |
| Selenium 4 | Tests web enregistrés avec Selenium IDE. | Tâche de Discovery. | [Selenium 4](https://pandorafms.com/docs/integrations/latest/fr/discovery/selenium-4/) |
| Oculix | Applications de bureau ou toute interface, au moyen d'images d'écran. | Plugin de serveur. | [Oculix](https://pandorafms.com/docs/integrations/latest/fr/plugins/oculix/) |

Pour superviser une application web, l'option recommandée est Playwright. Les
transactions web se consultent dans l'extension de console **WUX Transactions**,
décrite plus bas. Selenium 4 reste disponible pour qui possède déjà des tests
enregistrés avec Selenium IDE, et Oculix couvre ce qui n'est pas du web.

L'installation d'un paquet .disco et le cycle commun de ses tâches sont dans
[Comment fonctionne la tâche d'un paquet .disco](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#comment-fonctionne-la-tache-dun-paquet-disco).
Les guides du tableau réunissent les exigences, l'installation, les paramètres,
les modules, les limitations et le dépannage de chaque outil. Ici, on explique
seulement lequel choisir et où regarder les résultats.

## Playwright

Playwright est l'outil privilégié pour la supervision web. La tâche de Discovery
exécute un seul test Playwright dans un conteneur Docker, et chaque phase du
test devient une information que Pandora FMS chronomètre et représente. Le test
peut être enregistré avec les outils de Playwright, écrit à la main ou généré
avec l'aide d'un agent d'IA ; le
[guide de Playwright](https://pandorafms.com/docs/integrations/latest/fr/discovery/playwright/)
explique chaque voie, comment découper le test en phases et comment affiner les
délais d'attente.

Les résultats se consultent dans l'extension de console **WUX Transactions**,
disponible dans le menu d'opération de la console web. Elle réunit les
transactions découvertes dans une seule vue, avec un résumé de celles qui sont
correctes, en échec ou sans données, le temps moyen et, quand la tâche a le
débogage activé, la preuve de chaque transaction. C'est le meilleur point de
départ pour savoir dans quelle phase un parcours s'est cassé ; le détail de son
fonctionnement est dans le guide.

## Selenium 4

L'intégration avec Selenium 4 exécute des tests web enregistrés avec l'extension
de navigateur Selenium IDE contre un vrai navigateur. Elle se configure au moyen
d'une tâche de Discovery et admet différents modes d'exécution, d'un contrôleur
local à des conteneurs ou à un serveur Selenium distant. C'est une bonne option
s'il existe déjà un projet de tests Selenium IDE que l'on veut réutiliser. Le
[guide de Selenium 4](https://pandorafms.com/docs/integrations/latest/fr/discovery/selenium-4/)
détaille les modes, les exigences et les paramètres.

## Oculix

Oculix automatise ce qui n'est pas accessible depuis un navigateur : applications
de bureau, clients lourds ou toute interface qui n'existe qu'à l'écran. Il
fonctionne par reconnaissance visuelle d'images et exécution de scripts, et
génère des modules de supervision. Ce n'est pas une tâche de Discovery, mais un
plugin de serveur. Sa préparation, sa compatibilité et sa configuration sont dans
le [guide d'Oculix](https://pandorafms.com/docs/integrations/latest/fr/plugins/oculix/).

## Résultats et premières vérifications

Une transaction n'est utile que si l'on peut s'y fier. Après la première
exécution :

1. Confirmer que la tâche s'est exécutée sans erreur et que ses agents et ses
   modules existent dans la console web.
2. Vérifier que les données sont récentes. Avec Playwright, ouvrir **WUX
   Transactions** et contrôler que chaque transaction apparaît avec ses phases.
3. Refaire le parcours à la main et comparer les temps avec ceux mesurés.
4. En cas d'échec, distinguer si c'est l'application qui échoue ou la
   transaction elle-même (un sélecteur qui a changé, une attente trop courte ou
   un environnement d'exécution sans accès au site). La preuve de l'échec aide à
   trancher.

Le diagnostic spécifique se trouve dans le guide de chaque outil. Pour les
erreurs du cycle de la tâche, voir
[Quand cela échoue](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#quand-cela-echoue).
