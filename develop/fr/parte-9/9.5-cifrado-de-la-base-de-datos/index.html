    Chiffrement de la base de données¶

    Une base de données non chiffrée est franche jusqu'à l'indiscrétion : quiconque obtient un vidage emporte, avec les données de supervision, tous les mots de passe que Pandora FMS conserve pour le compte de tiers. Le chiffrement de la base de données ferme cette bouche : il chiffre à la source les champs qui gardent des mots de passe et des secrets, de sorte qu'un mysqldump perdu, volé ou mal archivé ne livre rien de lisible.

    Ce que c'est et ce que cela protège¶

    C'est une fonctionnalité Enterprise. L'algorithme est Rijndael 128 bits en mode ECB — la même chose qu'AES-256-ECB via OpenSSL dans la console web —, avec une clé de 256 bits dérivée du MD5 de la phrase de chiffrement (encryption_passphrase) saisie dans la configuration. Cette phrase n'est stockée nulle part dans la base de données, ni elle ni la clé qui en découle : elle vit uniquement dans les fichiers de configuration de chaque nœud. Si elle est perdue, il n'y a pas de retour en arrière : les mots de passe chiffrés restent illisibles pour toujours. Une fois configuré, le chiffrement est transparent : la console web et le serveur chiffrent à l'enregistrement et déchiffrent à la lecture sans que personne n'ait rien d'autre à faire.

    Ce qu'il protège, groupé par domaine fonctionnel :

    Ce qui est chiffré Détail
    Supervision Mots de passe des modules de plugin et identifiants SNMPv3 des modules, des composants réseau et des politiques.
    Inventaire Mots de passe des modules d'inventaire Enterprise.
    Champs personnalisés Champs personnalisés d'agent marqués comme type mot de passe.
    Configuration de la console Mot de passe du serveur de messagerie (SMTP) ; mot de passe d'administration de LDAP/Active Directory (serveur principal et secondaire) et l'option d'enregistrer une copie locale de ce mot de passe ; mot de passe de la base de données d'historique ; mot de passe de la base de données de réplication de la console ; mot de passe d'accès à l'API ; mot de passe du proxy de mises à jour ; mot de passe d'accès à Pandora RC ; mot de passe de la console web de commandes distantes ; mot de passe du hachage d'accès automatique entre nœuds ; identifiants des sources d'authentification distante de type Pandora FMS et Babel Enterprise.
    Haute disponibilité Mot de passe de réplication de base de données entre nœuds de haute disponibilité.
    Exportation de serveurs Mot de passe du serveur d'exportation de données vers un autre Pandora FMS distant.
    Command Center Données de connexion de chaque nœud enregistré (mots de passe de ses bases de données, de son API et de sa console).
    Plugins Macros masquées de plugins.
    Gestionnaire d'identifiants Les données des identifiants enregistrés (utilisateurs, mots de passe, clés et autres données d'accès de chaque type), voir Gestionnaire d'identifiants.

    Ce que cela ne protège PAS : le mot de passe d'accès des utilisateurs de la console web utilise un mécanisme distinct, avec un hachage non réversible, et ne dépend pas de cette fonctionnalité. Les mots de passe que le Serveur satellite garde dans sa configuration non plus : ils ont leur propre clé (credential_pass) et leur propre mécanisme, indépendant de ce chapitre.

    Exigences¶

    Exigence Détail
    Édition Pandora FMS Enterprise. Sans elle, encryption_passphrase n'a aucun effet et les mots de passe sont stockés sans chiffrement.
    Accès Accès administrateur aux fichiers de configuration de la console web (config.php) et du serveur (pandora_server.conf) de chaque nœud et du Command Center.
    Arrêt du service Le serveur Pandora FMS doit être arrêté sur chaque nœud et sur le Command Center pendant l'exécution de pandora_encrypt_db.
    Phrase de chiffrement La même chaîne dans config.php et dans pandora_server.conf, et la même sur tous les nœuds et sur le Command Center.

    Activer le chiffrement¶

    Les étapes se répètent sur le Command Center et sur chaque nœud, dans cet ordre :

    1. Arrêter le serveur Pandora FMS.
    2. Ajouter la même encryption_passphrase dans config.php (/var/www/html/pandora_console/include/config.php, avec la ligne $config["encryption_passphrase"]="phrase";) et dans pandora_server.conf (encryption_passphrase phrase) ; dans ce dernier, elle est commentée par défaut.
    3. Exécuter pandora_encrypt_db /etc/pandora/pandora_server.conf (la syntaxe complète se trouve dans Référence de pandora_encrypt_db).
    4. Redémarrer le serveur.

    Changer la phrase de chiffrement¶

    Si la phrase de chiffrement a été compromise, il ne suffit pas de la remplacer dans les fichiers de configuration : il faut déchiffrer avec l'ancienne phrase et chiffrer à nouveau avec la nouvelle.

    1. Déchiffrer avec la phrase actuelle : pandora_encrypt_db -d /etc/pandora/pandora_server.conf.
    2. Changer encryption_passphrase dans config.php et dans pandora_server.conf, sur tous les nœuds et sur le Command Center.
    3. Chiffrer à nouveau : pandora_encrypt_db /etc/pandora/pandora_server.conf.

    Aucune des deux étapes n'utilise l'option -m : c'est une option héritée de la migration entre versions anciennes et elle ne fait pas partie de cette procédure ; l'utiliser ici laisse certains champs chiffrés deux fois, avec l'ancienne phrase et avec la nouvelle, et inutilisables. Plus de détail dans Référence de pandora_encrypt_db.

    Supprimer le chiffrement¶

    1. Arrêter le serveur sur le Command Center et sur chaque nœud.
    2. Déchiffrer : pandora_encrypt_db -d /etc/pandora/pandora_server.conf.
    3. Commenter encryption_passphrase dans config.php et dans pandora_server.conf, sur tous les nœuds et sur le Command Center. Dans config.php, la ligne devient ainsi : # $config["encryption_passphrase"]="phrase"; ; dans pandora_server.conf, #encryption_passphrase phrase.
    4. Redémarrer le serveur.

    Il est recommandé de maintenir le chiffrement actif. Le supprimer laisse en texte clair tout ce qui est listé dans Ce que c'est et ce que cela protège.

    Conséquences et précautions¶

    • Phrase identique partout. Un nœud ou le Command Center avec une phrase différente du reste ne pourra pas lire les champs chiffrés avec une autre phrase. La défaillance est silencieuse : aucune exception visible n'est levée, on obtient simplement des octets dépourvus de sens là où devrait se trouver un mot de passe.
    • Phrase perdue, identifiants perdus. Il n'existe aucun moyen de récupérer une phrase de chiffrement oubliée ni de déchiffrer sans elle. Il convient de faire une sauvegarde de config.php et de pandora_server.conf — les fichiers qui la contiennent — séparément de la sauvegarde de la base de données, et non à côté d'elle.
    • Protection contre la double exécution. L'outil se souvient s'il a déjà chiffré ou déchiffré la base de données et refuse de répéter la même opération deux fois de suite : il faut déchiffrer avant de chiffrer à nouveau, et inversement.
    • Haute disponibilité. La réplique de haute disponibilité fonctionne au niveau de la base de données : elle copie les champs déjà chiffrés tels quels, sans les déchiffrer ni les chiffrer à nouveau. C'est le comportement correct et attendu ; il n'est pas nécessaire d'exécuter pandora_encrypt_db sur le nœud réplique.
    • Sauvegardes. Une sauvegarde de la base de données inclut les champs chiffrés tels quels, et c'est ainsi qu'il faut qu'elle soit. Pour la restaurer, il faut en plus la phrase de chiffrement, qui vit dans les fichiers de configuration : gardez-la en lieu sûr et à part, mais disponible le jour où il faudra restaurer. Une sauvegarde sans sa phrase ne sert qu'à ce qui n'est pas un mot de passe.

    Référence de pandora_encrypt_db¶

    Champ Valeur
    Chemin installé /usr/bin/pandora_encrypt_db (paquet du serveur ; il est supprimé à la désinstallation).
    Utilisation pandora_encrypt_db [-d] [-m] <chemin vers pandora_server.conf>
    -d Déchiffrer au lieu de chiffrer.
    -m Option héritée pour la migration de la version 749 à la 750 : lorsqu'elle est utilisée, l'outil laisse intacts les champs supplémentaires des identifiants du gestionnaire d'identifiants, aussi bien au chiffrement qu'au déchiffrement. Elle ne fait pas partie de la procédure normale de chiffrement, de déchiffrement ni de changement de phrase ; utilisez-la uniquement si vous savez exactement pourquoi vous en avez besoin, jamais pour changer la phrase de chiffrement.
    Condition préalable encryption_passphrase doit exister dans le fichier de configuration indiqué ; si elle manque, le script se termine par un avertissement indiquant que le chiffrement des mots de passe est désactivé.
