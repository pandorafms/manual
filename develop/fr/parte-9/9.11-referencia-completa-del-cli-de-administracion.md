# Référence complète du CLI d'administration (pandora_manage)

`pandora_manage` est l'outil d'administration qui s'exécute **sur le serveur** et
parle directement à la base de données et aux bibliothèques du produit. Ce n'est
pas un client de l'API : il n'y a ni requête HTTP, ni jeton, ni liste d'adresses
autorisées. Cela lui permet de faire des choses que l'API ne peut pas faire et,
pour la même raison, il ne sert à rien pour administrer une console depuis
l'extérieur.

Il n'est ni retiré ni relégué : c'est encore le seul moyen de réaliser une
demi-douzaine d'opérations que l'API v2 n'expose pas. Ce qui change, c'est le
partage des rôles. Les trois outils en ligne de commande ne sont pas en
concurrence :

| Outil | Où il s'exécute | À quoi il parle | Ce qui l'autorise |
|---|---|---|---|
| `pandora_manage` | Sur le serveur | Base de données et bibliothèques locales | Accès au système |
| `pandora_revent` | Sur n'importe quelle machine | API v1 (`api.php`) | IP autorisée, mot de passe d'API et utilisateur |
| [`pandora-cli`](../parte-13/13.5-cli-de-la-api-v2-pandora-cli.md) | Sur n'importe quelle machine | API v2 | Session ou jeton de l'utilisateur |

La conséquence pratique est la même que toujours : ce qui se fait avec
`pandora_manage` **ne passe pas par l'API**, donc les couches de sécurité de
l'API —la liste d'IP et le mot de passe d'API— ne s'appliquent pas, pas plus que
ses permissions d'utilisateur. Ce qui limite son usage, c'est l'accès au serveur
et à la base de données. C'est pourquoi il s'exécute en root, sur la machine, et
qu'on ne le confie pas à un script distant.

## Où il vit et ce dont il a besoin

Le binaire est installé avec le serveur dans `/usr/bin/pandora_manage`. Il a
besoin de trois choses :

- **La configuration du serveur**, passée en premier argument :
  `/etc/pandora/pandora_server.conf`.
- **Les permissions root.** Il lit la configuration du serveur et écrit dans la
  base de données.
- **Une base de données accessible.** Le programme se connecte dès son démarrage,
  avant d'exécuter la moindre option ; si la configuration ou la connexion
  échoue, il ne fait rien.

```bash
pandora_manage /etc/pandora/pandora_server.conf --option parametre1 parametre2
```

Il n'y a pas d'autre cérémonie : ni connexion, ni contexte, ni fichier
d'identifiants propre.

## Syntaxe et guillemets

La forme générale est celle ci-dessus. Les paramètres obligatoires et facultatifs
apparaissent entre crochets dans l'aide, et se passent dans le même ordre.

- **Guillemets simples** pour toute valeur contenant des espaces :
  `--create_group 'Serveurs virtuels'`.
- **Deux guillemets simples collés** (`''`) pour sauter un paramètre facultatif
  sans décaler le suivant. Si le paramètre était obligatoire, le programme répond
  avec l'erreur et l'aide.
- **`use_alias` à la fin** dans les commandes qui l'acceptent : l'agent est alors
  identifié par son alias au lieu de son nom interne. Il se place en dernier
  paramètre, pas au milieu.
- **Orthographe exacte** des noms qui existent déjà. Quand la valeur est le nom
  d'un agent, d'un groupe ou d'un serveur, utilisez la même chaîne que la console
  stocke : le programme cherche une correspondance, et une différence de casse ou
  un espace de trop signifie « n'existe pas ».

## L'aide

L'aide complète, avec toutes les catégories :

```bash
pandora_manage --h | more
```

`--help` fait la même chose. Le programme accepte toute option qui commence par un
tiret et finit par `h`, donc `--h` est la forme courte réellement utilisée.

L'exécuter sans aucune option n'affiche pas l'aide proprement : il avertit
d'abord qu'il n'y a pas d'arguments, puis l'affiche. Et si une option est passée
avec un nombre de paramètres différent de celui attendu, le programme répond avec
l'erreur de paramètres et **seulement la ligne de cette option**, ce qui est le
moyen rapide de consulter une signature :

```
[ERROR] Parameters error: 0 received | 1 necessary.
```

## Ce que l'API n'expose pas

Ces opérations n'ont pas d'équivalent dans l'API v2, elles ne peuvent donc se
faire qu'ici aujourd'hui. Elles renvoient au chapitre qui les traite lorsqu'il
existe :

| Opération | Option | Où elle est traitée |
|---|---|---|
| Débloquer un utilisateur bloqué par des tentatives échouées | `--unlock_user <utilisateur>` | [7.11](../parte-7/7.11-configuracion-segura.md) |
| Retirer la double authentification d'un utilisateur | `--disable_double_auth <utilisateur>` | [4.2](../parte-4/4.2-autenticacion-externa-y-centralizacion-de-accesos.md) |
| Activer ou désactiver l'ACL avancée | `--enable_eacl`, `--disable_eacl` | [4.3](../parte-4/4.3-seguridad-y-visibilidad-avanzada-enterprise-acl.md) |
| Nettoyer ou supprimer la configuration distante d'un agent | `--clean_conf_file`, `--delete_conf_file` | Ce chapitre |
| Clusters : créer, ajouter des agents et des éléments, consulter l'état | `--new_cluster`, `--add_cluster_agent`, `--get_cluster_status` | [9.6](9.6-monitorizacion-de-clusters.md) |
| Réinitialiser les compteurs de modules et d'alertes d'un agent | `--reset_agent_counts <id_agent>` | Ce chapitre |
| Vérifier une vulnérabilité contre la base locale | `--check_vulnerabilities <logiciel> <version> [<os>]` | [7.4](../parte-7/7.4-analisis-de-vulnerabilidades.md) |

Un exemple de chacune des deux premières, qui sont les plus utilisées dans
l'urgence :

```bash
pandora_manage /etc/pandora/pandora_server.conf --unlock_user jdoe
pandora_manage /etc/pandora/pandora_server.conf --disable_double_auth jdoe
```

Les deux écrivent dans la base de données et ne demandent aucune confirmation.
Vérifiez l'utilisateur avant de les lancer.

## Recettes courantes

**Créer un groupe et un agent dedans.** Le système d'exploitation et le serveur
doivent déjà exister dans la console :

```bash
pandora_manage /etc/pandora/pandora_server.conf \
    --create_group 'Serveurs virtuels' 'Serveurs'

pandora_manage /etc/pandora/pandora_server.conf \
    --create_agent web1 Linux 'Serveurs virtuels' pandora.local 10.0.0.5 'Frontal web'
```

**Créer un utilisateur.** Le troisième paramètre vaut `1` pour administrateur et
`0` pour un utilisateur normal :

```bash
pandora_manage /etc/pandora/pandora_server.conf \
    --create_user jdoe 'mot-de-passe-long' 0 'Equipe operations'
```

Un utilisateur fraîchement créé sans profil assigné ne peut pas se connecter ; les
profils s'ajoutent avec `--add_profile_to_user`.

**Lancer un événement.** Les trois premiers paramètres sont obligatoires ; les
autres sont facultatifs et peuvent être sautés avec `''` :

```bash
pandora_manage /etc/pandora/pandora_server.conf \
    --create_event 'Redémarrage planifié' system 'Serveurs virtuels'
```

**Appliquer une politique à un agent.** Le premier paramètre est l'identifiant de
la politique, pas son nom :

```bash
pandora_manage /etc/pandora/pandora_server.conf --apply_policy 7 42
```

Les arrêts planifiés ont leur propre section dans
[3.8](../parte-3/3.8-paradas-planificadas.md), avec la syntaxe complète et les
quatre types.

## Quand ne pas l'utiliser

- **Travail distant.** Si la console est sur un autre serveur, ou si le script
  tourne sur une autre machine, cela ne sert à rien : utilisez l'API v2 ou
  [`pandora-cli`](../parte-13/13.5-cli-de-la-api-v2-pandora-cli.md).
- **Travail qui doit rester soumis aux permissions de la console.** Ici, aucun
  profil ACL ne s'applique : qui peut exécuter le binaire peut faire l'opération.
- **Événements contre une console distante.** C'est le rôle de `pandora_revent`,
  qui parle à l'API v1 avec les identifiants d'un utilisateur.

La règle est simple : si l'opération existe dans l'API et que vous la faites
depuis l'extérieur, faites-la par l'API. Si elle n'existe pas, ou si vous êtes sur
le serveur et devez toucher la base de données, c'est ce chemin.

## Problèmes courants

| Message | Cause et remède |
|---|---|
| `[ERROR] No valid arguments` | Exécuté sans option. Ajoutez l'option, ou `--h` pour l'aide. |
| `[ERROR] Parameters error: N received | M necessary.` | Nombre de paramètres incorrect. La ligne de cette option s'affiche en dessous. |
| `[ERROR] Error: The user 'jdoe' does not exist.` | Le nom ou l'identifiant n'existe pas dans la console. Vérifiez l'orthographe. |
| `[ERROR] Error: The group 'Servers' already exists.` | Un élément de ce nom existe déjà. Utilisez-en un autre, ou modifiez l'existant. |
| Le nœud est en mode centralisé et l'opération est refusée | Cette opération se fait dans le Command Center, pas sur le nœud. |
| `Can't locate PandoraFMS/SIEMServer.pm` | C'est le `.pl` de `util/` qui est exécuté au lieu du binaire installé. Utilisez `/usr/bin/pandora_manage`. |
| Rien ne se passe et aucune erreur n'apparaît | La configuration ou la base de données n'a pas chargé. Le programme se connecte au démarrage : vérifiez le chemin du `.conf` et l'accès à la base. |
