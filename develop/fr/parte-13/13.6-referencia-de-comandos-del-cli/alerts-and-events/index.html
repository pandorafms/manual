    Command Method Path

    alert-action¶

    Alert actions

    Holds action DEFINITIONS (what to do when an alert fires: execute a command, send an email, run a script) and their configuration, not whether an alert has actually fired. For the firing history see alert-fired; for alerts assigned to a module see module-alert, and for the actions a module alert fired see module-alert-action.

    Aliases: alert-actions

    Command Method Path
    alert-action list POST /alert/action/list
    alert-action get <idAlertAction> GET /alert/action/{idAlertAction}
    alert-action create POST /alert/action
    alert-action update <idAlertAction> PUT /alert/action/{idAlertAction}
    alert-action delete <idAlertAction> DELETE /alert/action/{idAlertAction}
    alert-action copy <idAlertAction> POST /alert/action/{idAlertAction}/copy

    Fields for --where, --fields and --in: actionThreshold, createWorkunitInItsm, idAlertAction, idAlertCommand, idGroup, isDefault, name

    fired-alert¶

    Alert fired history

    Read-only history of the alerts that actually fired, one row per firing, served by /alert/fired. It holds no alert definitions: see alert-action, alert-template and module-alert for those.

    Rows whose alert assignment no longer exists are not listed, cannot be authorized and answer 404 on get. On a metaconsole serverId is required and selects one node; calls are not aggregated.

    Aliases: fired-alerts

    Command Method Path
    fired-alert list POST /alert/fired/list
    fired-alert get <idAlertFired> GET /alert/fired/{idAlertFired}

    Fields for --where, --fields and --in: idAgentModuleAlert, idAlertFired, recovered, recoveryType, recoveryUtimestamp, utimestamp

    --filter additionally accepts every other field of the entity (13 in total).

    event bulk-create — A bulk create on a plural path, outside the verb convention.

    event tag assign — The second id is the payload, not a body. Outside the verb convention.

    event summary — Takes an optional event filter (--set severity=4, --set idGroup=0...) in the request body of a GET. Without any filter, or without a date range, it covers the last 8 hours. On a metaconsole, target a node with --set serverId=; the value travels in the filter body as an array, exactly as in event list.
