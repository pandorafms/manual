# CLI de l'API v2 (pandora-cli)

`pandora-cli` est un client en ligne de commande de l'API v2. Chaque commande est
une requête HTTP : le binaire s'authentifie, convertit les arguments et affiche
la réponse. Rien de plus. Toute la validation, les permissions et les règles
métier restent dans la console, qui est leur place.

Cela définit ce qu'il peut faire et ce qu'il ne peut pas faire. **Il ne remplace
pas le CLI d'administration `pandora_manage`** : l'API v2 n'expose pas encore
tout ce que fait l'outil classique — débloquer des utilisateurs, gérer des
clusters, toucher les fichiers de configuration locaux, créer des graphiques
personnalisés ou réinitialiser des compteurs, entre autres. La comparaison des
trois outils (`pandora_manage`, `pandora_revent` et `pandora-cli`) se trouve dans
la [référence du CLI d'administration](../parte-9/9.11-referencia-completa-del-cli-de-administracion.md),
dans la Partie 09.

## Comment l'obtenir

Le binaire est distribué avec le paquet du serveur, où le service Pandora AI
l'utilise, et il **sera également disponible dans le Marketplace**
(<https://marketplace.pandorafms.com/>), où il pourra être téléchargé une fois
publié. Ce chapitre ne donne pas d'étapes d'installation : lorsque la fiche du
Marketplace existera, c'est là qu'il faudra aller.

Il est compilé pour Linux (x86-64 et ARM64), macOS (Intel et Apple silicon) et
Windows (x86-64). La version testée pour cette édition est Linux x86-64.

## Prérequis

Trois choses, dont aucune n'est facultative :

- **Un jeton de l'API v2.** Il se crée dans la console sous l'utilisateur dont
  les permissions le CLI doit utiliser. Chaque commande s'exécute avec le profil
  ACL de cet utilisateur. La façon de le créer et de l'envoyer est expliquée dans
  le [chapitre 13.1](13.1-primeros-pasos-y-autenticacion.md).
- **L'accès réseau à la console**, en HTTP ou HTTPS.
- **L'adresse du client autorisée par l'ACL de l'API.** La console restreint
  l'accès par IP. Si l'adresse n'est pas dans la liste, chaque appel échoue avec :

  ```
  401 IP 10.0.0.5 is not in ACL list
  ```

  Cela se règle dans la console, pas dans le CLI : le champ **« IP list with API
  access »** de **Administration → Configuration → Général**. Une IP par ligne.

## Configurer l'accès

### Enregistrer un jeton

`auth login` vérifie le jeton auprès de la console **avant** d'écrire quoi que ce
soit. Si elle le rejette, rien n'est enregistré.

```bash
pandora-cli auth login --token <token> --url https://console.example.com/pandora_console/api/v2/
```

L'adresse doit pointer vers la racine de l'API et se terminer par `/api/v2/`. Si
elle est omise, la valeur par défaut est
`http://localhost/pandora_console/api/v2/`.

Les identifiants sont écrits dans `~/.pandora-cli/config.json`, avec le répertoire
en `0700` et le fichier en `0600`. Le jeton est enregistré en base64 : cela le
garde hors d'un regard distrait dans le terminal, mais **ce n'est pas du
chiffrement** ; ce qui protège le fichier, ce sont les permissions. Le CLI refuse
de lire une configuration dont les permissions sont plus larges que `0600`. Pour
l'enregistrer ailleurs, `PANDORA_CLI_HOME`.

### Plusieurs consoles

Chaque console est un contexte nommé :

```bash
pandora-cli auth login --token <token> --url https://prod/pandora_console/api/v2/ --context prod
pandora-cli auth login --token <token> --url https://lab/pandora_console/api/v2/  --context lab --insecure

pandora-cli auth context list
pandora-cli auth context use prod
pandora-cli user list --context lab
```

`--token` et `--url` peuvent aussi être passés à n'importe quelle commande.
Utilisés ainsi, le jeton n'est jamais écrit sur le disque, ce qui convient à une
tâche de CI qui le détient déjà dans un secret. Le prix à payer : il reste dans
l'historique du shell et dans la liste des processus du système d'exploitation.
Ne l'utilisez pas sur une machine partagée.

### Certificats auto-signés

`--insecure` désactive la vérification TLS. Il ne s'applique jamais par défaut.
Passé à `auth login`, il est mémorisé pour ce contexte ; passé à toute autre
commande, il ne vaut que pour cette exécution.

### Vérifier que cela fonctionne

```bash
pandora-cli auth status
```

```
Context:  prod
URL:      https://console.example.com/pandora_console/api/v2/
Insecure: false
Config:   /home/user/.pandora-cli/config.json
Token:    valid
Version:  v8.0NG.805 (build PC260915)
MR:       805
Package:  805
LTS:      Feature Release

Console specification: 519 operations, 69 entities (read 2026-10-23T09:12:37Z)
```

`Token: valid` signifie que la console l'a accepté. Sinon, la commande se termine
avec un code non nul. Les lignes de version, MR, paquet et LTS sont ce que la
console dit d'elle-même, et n'apparaissent que lorsqu'elle le dit. Avec `-o json`,
la sortie contient les mêmes données dans un objet, plus un objet `console` avec
la version lorsque la console la publie. `--refresh` relit la description de
l'API après une mise à jour de la console.

Ensuite, quelque chose de réel :

```bash
pandora-cli user list
```

```
IDUSER  FULLNAME  EMAIL              ISADMIN  DISABLED
admin   Pandora   admin@example.com  true     false

1 shown, 1 total.
```

## Corrélation avec les sessions Pandora AI

`--ai-session-id` ajoute un en-tête de corrélation (`X-Pandora-AI-Session`) à
chaque requête. Il regroupe dans l'audit les appels d'une même session de travail.

- Dans `auth login`, un identifiant explicite est **enregistré** dans ce
  contexte ; sans l'option, le contexte conserve celui qu'il avait ; et
  `--ai-session-id=` l'efface.
- Dans toute autre commande, il est transitoire : il vaut pour cette exécution et
  ne touche pas à la valeur enregistrée. `--ai-session-id=` désactive l'en-tête
  pour cet appel.
- Un `auth login` échoué n'écrit rien.

L'ordre de résolution est : option explicite, puis le contexte actif, puis rien.
C'est une métadonnée de corrélation, **pas un identifiant** : elle n'authentifie
pas et n'accorde aucune permission. Le fait que la console l'enregistre ou
l'affiche dans l'audit est expliqué dans
[Audit de Pandora AI](../parte-8/8.5-auditoria.md).

## La sortie

La sortie est un **tableau dans le terminal** et du **JSON lorsqu'elle est
redirigée ou envoyée dans un tube**, afin qu'un script n'ait pas à demander de
format :

```bash
pandora-cli user list                      # tableau
pandora-cli user list | jq '.[].idUser'    # JSON
pandora-cli user list > users.json         # JSON
```

On peut la forcer avec `-o json`, `-o table` ou `-o yaml`. Les lignes
informatives (`1 shown, 1 total.`) n'apparaissent qu'au format tableau ; pas en
JSON ni en YAML, donc ce qui est envoyé dans un tube est toujours valide. La
commande se termine par `0` en cas de succès et par un code non nul en cas
d'échec, ce qui permet de l'utiliser directement dans un `if`.

## Pagination et filtres

Voici le piège numéro un du CLI, et il vient de la source : **`--page` commence à
1**, alors que le paramètre `page` de l'API **commence à 0**. Le CLI traduit, mais
il vaut mieux le savoir pour ne pas mélanger les deux mondes. Les règles de
pagination de l'API sont dans [Conventions de l'API](13.2-convenciones-de-la-api.md#pagination).

| Option du CLI | Ce qu'elle fait |
|---|---|
| `--page <n>` | Numéro de page, **1-based**. `--page 1` est la première. |
| `--size <n>` | Lignes par page. |
| `--limit <n>` | Nombre maximal de lignes à renvoyer. Alternative à `--page`/`--size`. |
| `--offset <n>` | Lignes à sauter. Alternative à `--page`/`--size`. |

`--limit` et `--offset` ne peuvent pas être mélangés avec `--page` et `--size` ;
le CLI le refuse avant d'envoyer quoi que ce soit. Une liste dont l'endpoint ne
les accepte pas, comme `event list`, ne les propose pas. Si `--size` est passé
sans `--page`, le CLI envoie les deux quand même, car certains endpoints ignorent
la taille sans numéro de page.

### La correspondance avec l'API

Les trois filtres avancés du CLI sont les paramètres de l'API sous un autre nom :

| Option du CLI | Paramètre de l'API |
|---|---|
| `--where` | `fieldConditions` |
| `--fields` | `requestedFields` |
| `--in` | `multipleSearchString` |

`--filter` est différent : il accepte n'importe quel champ de l'entité et se
combine avec **ET**. Lorsque le schéma déclare le champ comme un tableau,
répéter `--filter` accumule des valeurs au lieu d'ajouter des conditions, et un
`null` explicite vide le champ.

L'acceptation de `--where`, `--fields` et `--in` se décide **par entité**, pas par
console : `/user/list` peut accepter `fieldConditions` et `/event/list` le
refuser. Le CLI valide les deux ensembles en local et, en cas d'erreur, liste les
noms valides. `event` est l'exception : il ne valide pas ces trois filtres et
laisse la console décider.

### Quand la console refuse un filtre

Si l'entité n'accepte pas le paramètre, la réponse est un `400` et le CLI nomme
l'option qui l'a envoyé :

```
Error: POST event/list failed: 400 Field: fieldConditions is not a valid parameter
--where (fieldConditions) is not available on this console.
```

Le reste de l'appel n'est pas affecté : seule la requête refusée échoue. Pour
voir ce que l'entité accepte dans la version installée, `pandora-cli <entité>
--help`.

### Un cas particulier : `dateRange`

Le filtre de dates de `event list` n'accepte pas la chaîne `"<début> - <fin>"` :
il veut du JSON. Un preset et un intervalle relatif :

```bash
pandora-cli event list --filter 'dateRange={"preset":{"value":"last_24_hours"}}'
pandora-cli event list --filter 'dateRange={"start":{"mode":"relative","value":1,"unit":"hours"},"end":{"mode":"now"}}'
```

L'ancienne chaîne échoue avec `400 Invalid date range format. Must be valid
JSON`. Dans Windows PowerShell 5.1 (et dans PowerShell 7 antérieur à 7.3), les
guillemets doubles de l'argument sont perdus avant d'atteindre le CLI ; il faut
donc les échapper :

```powershell
pandora-cli event list --filter 'dateRange={\"preset\":{\"value\":\"last_24_hours\"}}'
```

Les valeurs sont converties dans leur type JSON : `true` et `false` sont des
booléens, les chiffres sont des nombres et `null` est nul. Pour forcer une chaîne,
on la met entre guillemets : `--filter name='"42"'`.

## Créer et modifier

`--set` ajoute un champ au corps et peut être répété. Pour un corps complet,
`--from-file` lit un JSON depuis un fichier ou l'entrée standard :

```bash
pandora-cli user create --set idUser=jdoe --set fullName='Jane Doe' --set password=secret
pandora-cli user update jdoe --set email=jane@example.com
pandora-cli user delete jdoe --yes

pandora-cli user create --from-file user.json
cat user.json | pandora-cli user create --from-file -
```

`--set` et `--from-file` ne se combinent pas. `--from-file` accepte un objet ou un
tableau complet, tolère un BOM UTF-8 au début (éditeurs Windows) et constitue le
seul moyen d'envoyer des objets et des tableaux imbriqués.

`--set` convertit les valeurs dans leur type JSON, et il y a un piège classique :
un champ texte dont la valeur ressemble à un nombre est envoyé comme un nombre.
`--set permissions=0755` envoie `755`. On le met entre guillemets pour forcer la
chaîne :

```bash
pandora-cli <entité> <verbe> --set permissions='"0755"'
```

Dans un champ déclaré comme tableau, répéter `--set` accumule des éléments, et un
`null` explicite vide le tableau. `--set` n'interprète pas les littéraux d'objet
ni de tableau : `--set rules='{"agentGroup":2}'` voyage comme du texte. Pour cela,
utilisez `--from-file`.

`delete` demande confirmation. Dans une session non interactive, il **refuse** au
lieu de demander, de sorte qu'un script qui a oublié `--yes` échoue bruyamment au
lieu de supprimer en silence.

Certaines règles ne vivent que dans la console et n'apparaissent pas dans la
liste des champs :

- `agent create` a besoin d'un groupe réel : `idGroup=0` est refusé avec
  `400 Agent group is missing`. Le nom de l'agent est généré par la console ;
  pour l'étiquette que vous contrôlez, utilisez `alias`.
- `module create` a besoin de `idModule` (le type de serveur) avec
  `idModuleType`, pas seulement des colonnes des filtres.
- Un utilisateur non administrateur fraîchement créé a besoin d'au moins un
  profil assigné avec `user profile add` avant de pouvoir se connecter.
- La première règle d'un `event-alert-rule` doit porter `operation=NOP` ; la
  console refuse toute autre valeur.
- `module force-check` demande une vérification immédiate et répond `202` sans
  corps : la vérification se termine d'elle-même. Les modules qui n'admettent pas
  de vérification immédiate, comme ceux à données poussées, renvoient `400`.

## Entités imbriquées et groupes

Une entité imbriquée prend d'abord l'identifiant du parent :

```bash
pandora-cli report-design-page list 12
pandora-cli report-design-page-widget list 12 3
```

Les listes imbriquées prennent les mêmes options de liste que celles de premier
niveau, chacune seulement si la commande la déclare. Donner la même propriété
avec une option et avec `--set` échoue en local :

```
Error: --page conflicts with "page" already present in the payload: give it once
```

Certaines entités regroupent une partie de leurs commandes en **groupes**, avec la
forme `<entité> <groupe> <verbe> <ids…>` : `policy`, `collection`, `service`,
`agent`, `module`, `log`, `pandora-ai-audit`, `rmm` et `notification`.
`pandora-cli <entité> --help` liste les groupes de chacune.

```bash
pandora-cli policy module list 7
pandora-cli collection file upload 3 --file ./a.conf
pandora-cli service element add 2 --set description='Frontend CPU' --set idAgenteModulo=42
```

## Recettes et limites de l'API v2

Ce qui suit n'est pas le manuel du CLI : c'est ce que l'API fait et ne dit pas.
C'est regroupé par domaine parce que chacun a ses manies.

| Bloc | Origine |
|---|---|
| Agents, modules, politiques, collections, arrêts, graphiques, compteurs et 2FA | Testé contre une console |
| NCM : fournisseurs, modèles, firmware, scripts, modèles de configuration et `ncm agent list` | Testé contre une console |
| NCM sur l'équipement (`enable`, `bulk`, `update`, `backup`, `queue`, `script`) | Documenté depuis `--help` |
| RMM, notifications, e-mail, SIEM et tâches Pandora AI | Documenté depuis `--help` |

Dans les blocs « documenté depuis `--help` », c'est l'interface qui est décrite,
pas un comportement vérifié : contrôlez la réponse avant de vous y fier.

### Agents et modules

`monitoring create` pousse des données d'agent. Le corps est un **tableau** avec
des clés en snake_case : `agent_data` et `module_data`.

```bash
cat > payload.json << 'EOF'
[
  {
    "agent_data": {"agent_name": "web1", "address": "10.0.0.5", "interval": 300},
    "module_data": [
      {"name": "cpu_usage", "type": "generic_data", "data": 12.5}
    ]
  }
]
EOF
pandora-cli monitoring create --from-file payload.json
```

`agent_name`, `address` et `interval` sont obligatoires ; chaque entrée de
`module_data` a besoin d'un `type`. Renvoyer le même agent, module et horodatage
met à jour la valeur au lieu de la dupliquer.

Deux pièges qui coûtent une après-midi chacun :

- **Les données d'un agent qui existe déjà sont ignorées en silence** si le
  payload ne le nomme pas comme la console le stocke : `agent_name` doit être le
  `name`, pas l'alias, et l'agent a besoin d'un `serverName` correspondant au
  nœud. On les voit avec `pandora-cli agent get <id> -o json`. Un agent créé par
  l'API a un `name` haché, un alias pour l'affichage et aucun `serverName`.
- Les modules écrits ainsi ont besoin d'un type asynchrone (`async_data`,
  `async_proc`, `async_string`) pour avoir un état et déclencher des alertes. Un
  `generic_*` stocke la valeur mais ne calcule pas d'état.

### Politiques

La file des politiques est **asynchrone** : `policy purge` et les opérations de
`policy queue` mettent du travail en file et reviennent sans attendre. Une
politique ne peut pas être supprimée tant qu'elle a des entrées en file ou des
agents assignés : consultez `policy queue list` — ou `policy queue summary` — et
utilisez `policy queue clear`, ou attendez.

**Retirer n'est pas supprimer.** `remove`, `delete` et `bulk-delete` sur un enfant
de la politique (agent, alerte, collection, groupe, module, plugin) ne font que
le marquer `pendingDelete` ; l'effet arrive quand la file est appliquée, et
`restore` annule la marque. `policy alert-action remove` et `policy queue delete`
sont l'exception : ils agissent immédiatement.

Retirer un agent se fait en deux étapes : `policy agent remove` le marque, et
`policy queue apply-pending` **ignore** les agents dans cet état. Il faut mettre
l'opération en file :

```bash
pandora-cli policy agent remove 7 25
pandora-cli policy queue add 7 --set operation=delete --set idAgent=42
```

`policyLinked` a quatre états : `0` non lié, `1` lié, `10` déliaison en attente et
`11` liaison en attente. `module policy link` et `unlink` les font passer de l'un
à l'autre. Les opérations `bulk-*` des plugins prennent un tableau JSON
d'identifiants, que `--set` ne peut pas construire : elles passent par
`--from-file`. Le détail quotidien des politiques, avec leur file et leurs
marques, est dans
[Politiques de supervision](../parte-2/2.10-politicas-de-monitorizacion.md).

### Collections

`collection file upload` envoie du `multipart/form-data` : les fichiers avec
`--file` (répétable, au moins un) et les champs texte avec `--set`. `collection
file download` renvoie des octets, donc il exige `--output-file` ; un fichier
existant n'est remplacé qu'avec `--force`, et un téléchargement échoué ne laisse
pas de fichier à moitié écrit.

Assigner une collection à un agent (`agent collection add`) exige un agent avec
configuration distante (`remote=1`) disponible dans la console. L'assignation ne
reste que dans sa configuration distante ; après avoir changé les fichiers, il
faut exécuter `collection apply` pour que les agents récupèrent le paquet. Le
[chapitre des collections](../parte-2/2.9-colecciones.md) couvre le reste.

### Arrêts planifiés

`dateFrom` et `dateTo` sont des horodatages Unix, pas des dates lisibles. L'arrêt
et ce qu'il couvre sont des entités distinctes : `scheduled-downtime-agent` et
`scheduled-downtime-module` se créent à part, avec l'identifiant de l'arrêt
devant. `scheduled-downtime-module` n'a pas d'`update` : on retire le module et on
le rajoute. Le module de `idAgentModule` doit appartenir à l'agent de `idAgent`,
sinon la console répond `404`.

### Graphiques

`module graph` ne renvoie pas une image binaire : il renvoie l'image encodée en
base64 dans le champ `graph`, avec son `mimeType` et son `encoding` à côté.
`period` est en secondes (minimum 300 ; par défaut, un jour).

```bash
pandora-cli module graph 12 --set period=3600 -o json | jq -r .graph | base64 -d > graph.png
```

`graphType` n'accepte que `data` ou `histogram` ; les styles ligne, aire et
barres appartiennent à `chartType`. Tout autre `graphType` renvoie `400 Invalid
value for graphType`.

### SIEM et audit

- `siem-event` et `siem-log` sont en lecture seule et ont besoin d'un backend
  SIEM configuré dans la console ; sans lui, `503 Invalid or missing log backend
  configuration`. Ce ne sont pas les mêmes : `siem-event` cherche des événements
  et `siem-log` cherche les journaux décodés. Sans dates, ils couvrent les
  dernières 24 heures.
- `log` lit les enregistrements conservés par agent et pagine avec un **curseur** :
  utilisez `--size` et, pour la page suivante, `--cursor` avec la valeur renvoyée
  par la précédente. Il n'a pas de `--page`.
- `audit-log` (alias `audit`) est en lecture seule et lit la piste d'audit de la
  console. `get <idSession>` renvoie une entrée avec ses données étendues.

### Notifications et e-mail

`notification` gère les messages de la console, leurs sources (lecture seule) et
les préférences de chaque utilisateur. `message create` exige `idUser`, `subject`
et `message` ; `message update` ignore `read`, qui est en lecture seule. `email
send` envoie un message par le transport de la console et `email config` montre
la configuration sans identifiants.

### Pandora AI

`ai-task` gère les tâches planifiées de Pandora AI : `create` exige `firstRun`
(horodatage Unix) et `periodicity` accepte `hourly`, `daily`, `weekly`, `monthly`
ou `yearly` ; `notifySuccess` et `notifyError` acceptent `never`, `on_request` ou
`always`. `ai-notify send` prévient le propriétaire d'une tâche et exige
`idScheduledTask`, `event`, `subject` et `message`. L'audit des conversations se
lit avec `pandora-ai-audit`, qui est en lecture seule.

### RMM

`rmm` couvre la supervision et la gestion distantes : agents, scripts,
ressources, routines, planifications, travaux par lots et leurs files. Ce sont
des groupes, pas des verbes isolés : `rmm agent`, `rmm batch`, `rmm
pending-software`, `rmm queue`, `rmm resource`, `rmm routine`, `rmm rule`, `rmm
schedule`, `rmm script` et `rmm settings`. Les champs qui portent des tableaux,
comme `inputs` ou `idAgentsRmm`, s'envoient avec `--from-file`. Les routines n'ont
pas de `delete` pour leurs agents ni pour leurs planifications : on les marque
avec `--set pendingDelete=true`.

### NCM

`ncm` gère la configuration des équipements réseau : les agents sous gestion, le
firmware, les scripts, les modèles et les fabricants. C'est une seule entité avec
des groupes, et elle compte 51 commandes. Les types de script sont `TEST`,
`GET_CONFIGURATION`, `SET_CONFIGURATION`, `GET_FIRMWARE`, `SET_FIRMWARE`,
`CUSTOM_TASK`, `SNIPPET` et `GET_OS_VERSION`.

Le champ `regexp` d'un script est une liste de paires `[expression, booléen]`, il
passe donc par `--from-file` :

```bash
echo '{"name":"Show version","idGroup":0,"type":"SNIPPET","content":"show version","regexp":[["^.*$",true]]}' \
  | pandora-cli ncm script create --from-file -
```

Un modèle prend l'identifiant d'un script existant dans `idScript` ; son type
vient de ce script et ne peut pas être fixé. Le
[chapitre NCM](../parte-3/3.6-gestion-de-configuracion-de-equipos-de-red-ncm.md)
couvre la partie console.

### 2FA et sessions web

`user 2fa` gère le second facteur : `status`, `reset` (crée ou renouvelle le
secret ; il n'apparaît que dans cette réponse), `disable`, `bulk-disable` et
`disable-all`. `reason` est facultatif et va dans l'audit. `bulk-disable` et
`disable-all` demandent confirmation ; `disable-all` touche toute la console,
vérifiez donc où vous le lancez.

`token session` gère les **sessions de console**, celles qu'ouvrent le web et les
applications mobiles, qui ne sont pas les jetons d'API de `token create` :

```bash
pandora-cli token session login --set id_user=jdoe --set password='...'
pandora-cli --token <access_token> token session logout
```

`login` n'a pas besoin de jeton. Il renvoie `access_token`, `access_expires_in` et
`session_expires_at` ; si le compte a un second facteur, il renvoie `status:
mfa_required` avec un `mfa_token`, complété par `token session login-mfa`. Une
session ne peut pas être renouvelée depuis le CLI : le renouvellement a besoin du
cookie `HttpOnly` que pose la console, et l'outil ne garde pas de cookies. Quand
elle expire, il faut se reconnecter. Le jeton d'accès se traite comme un mot de
passe : hors de l'historique et hors des journaux.

## Inspecter l'API et diagnostiquer

`spec` lit la description que la console publie d'elle-même, sans ouvrir le
`swagger.json` à la main :

```bash
pandora-cli spec list                # schémas publiés
pandora-cli spec show EventFilter    # un schéma, avec allOf résolu
pandora-cli spec raw                 # le swagger complet
```

Les noms sont ceux que publie la console (`EventFilter`, `ReportDataSource`), pas
les noms avec trait d'union du CLI ; `spec list` les liste et `spec show` suggère
le plus proche en cas d'erreur.

Pour voir ce qui est envoyé et ce qui revient, `--verbose` trace la requête et le
statut de la réponse vers la sortie d'erreur, et laisse la sortie standard propre
pour la redirection :

```bash
pandora-cli user list --filter isAdmin=true -v -o json > users.json
```

```
→ POST https://console.example.com/pandora_console/api/v2/user/list
→ body: {"isAdmin":true}
← 200, 1834 bytes
```

`pandora-cli docs` imprime la référence complète de la build installée, et
`pandora-cli skill install` laisse une skill d'usage pour les agents qui
travaillent dans un terminal. Relancez-la après une mise à jour, pour que la
skill continue de décrire le binaire présent.

## Problèmes courants

| Symptôme | Cause et remède |
|---|---|
| `401 ... token was rejected` | Jeton incorrect ou expiré. Relancez `auth login`. |
| `401 IP ... is not in ACL list` | L'adresse n'est pas dans l'ACL de l'API. Ajoutez-la dans la console. |
| `403 ... lacks permission` | Le jeton est valide, mais le profil ACL de son utilisateur n'autorise pas l'opération. |
| `404 ... or the API base URL is wrong` | Vérifiez `auth status` : l'adresse doit se terminer par `/api/v2/`. |
| `TLS verification failed` | Certificat auto-signé. `--insecure`, ou enregistrez-le dans le contexte au moment du login. |
| `has permissions 0644` | Le fichier de configuration est lisible par d'autres. `chmod 0600 ~/.pandora-cli/config.json`. |
| `--fields ... is not available on this console` | L'entité n'accepte pas ce paramètre ; le CLI nomme l'option qui l'a envoyé. |
| `unknown field "..."` | Le champ n'existe pas sur l'entité ; le message liste les valides. |
| `the "..." entity does not exist on this console` | La console ne publie pas cette entité. Essayez `auth status --refresh` si vous l'avez mise à jour. |
| Une valeur comme `0755` arrive comme `755` | `--set` convertit ce qui ressemble à un nombre. Mettez la valeur entre guillemets ou utilisez `--from-file`. |
| Un objet ou un tableau de `--set` arrive comme du texte | `--set` n'interprète pas `{...}` ni `[...]`. Utilisez `--from-file`. |
| `unknown flag: --limit` | Cette liste n'admet pas `--limit`/`--offset`. Utilisez `--page` et `--size`. |
| Une politique ne peut pas être supprimée | Elle a des entrées en file ou des agents assignés. `policy queue clear` ou `policy purge`, et attendez. |
| Un enfant de politique est encore là après `remove` | Il n'est que marqué `pendingDelete`. Appliquez la file ou utilisez `restore`. |
| Une collection ne s'assigne pas à un agent | L'agent a besoin d'une configuration distante (`remote=1`) disponible. |
