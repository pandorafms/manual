# Monitorización de entornos virtualizados

En un entorno virtualizado, monitorizar solo las máquinas invitadas deja a
oscuras la capa que las sostiene: el hipervisor, el clúster, el almacenamiento
y el gestor que lo coordina. Pandora FMS consulta esa capa a través de las API de cada
plataforma y genera agentes y módulos tanto para los
hosts como para las máquinas virtuales que ejecutan.

| Plataforma | Mecanismo | Guía de la integración |
|---|---|---|
| VMware | Tarea de Discovery contra vCenter. | [VMware](https://pandorafms.com/docs/integrations/latest/es/discovery/vmware/) |
| Proxmox | Tarea de Discovery contra la API del clúster. | [Proxmox](https://pandorafms.com/docs/integrations/latest/es/discovery/proxmox/) |
| Oracle VM | Plugin contra la API REST de Oracle VM Manager. | [Oracle VM](https://pandorafms.com/docs/integrations/latest/es/plugins/oracle-vm/) |
| KVM | Tarea de Discovery o plugin de agente. | [KVM Discovery](https://pandorafms.com/docs/integrations/latest/es/discovery/kvm/), [plugin KVM](https://pandorafms.com/docs/integrations/latest/es/plugins/kvm/) |
| Hyper-V | Tarea de Discovery contra el host mediante WinRM. | [Hyper-V](https://pandorafms.com/docs/integrations/latest/es/discovery/hyper-v/) |
| XenServer | Tarea de Discovery contra XenServer. | [XenServer](https://pandorafms.com/docs/integrations/latest/es/discovery/xenserver/) |

Las guías de la tabla son la referencia vigente de qué recursos genera cada
integración, los permisos que necesita y sus parámetros; cambian con el
producto, por lo que este capítulo no los repite. La instalación de un paquete
.disco y el ciclo común de sus tareas están en
[Cómo funciona la tarea de un paquete .disco](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#como-funciona-la-tarea-de-un-paquete-disco).

Antes de configurar, hay que preparar en la plataforma una cuenta dedicada con
los permisos de lectura que indique la guía, comprobar que el equipo que ejecuta
la tarea alcanza el gestor o el hipervisor y guardar las credenciales en el
[gestor de credenciales](2.2-gestor-de-credenciales.md).

## VMware

La integración se conecta a un servidor vCenter y descubre los recursos de un
datacenter: el propio datacenter, sus hosts ESXi y las máquinas virtuales, con
módulos de disponibilidad, capacidad, configuración y rendimiento. Las opciones
de selección y el detalle de lo que se genera están en la
[guía de VMware](https://pandorafms.com/docs/integrations/latest/es/discovery/vmware/).

## Proxmox

Discovery se conecta a un clúster de Proxmox VE a través de su API y genera un
agente por cada recurso descubierto: nodos, máquinas virtuales y el resto de
recursos que detalla la
[guía de Proxmox](https://pandorafms.com/docs/integrations/latest/es/discovery/proxmox/).

## Oracle VM

A diferencia de las anteriores, Oracle VM se monitoriza con un plugin que lee la
API REST de Oracle VM Manager. Cada ejecución convierte el estado del manager y
de lo que gestiona (pools, servidores, máquinas virtuales y almacenamiento) en
agentes y módulos. Su instalación y configuración están en la
[guía de Oracle VM](https://pandorafms.com/docs/integrations/latest/es/plugins/oracle-vm/).

## KVM, Hyper-V y XenServer

KVM se puede monitorizar con una tarea de Discovery, que lee los hipervisores por
SSH o de forma local, o con un plugin de agente; las dos guías indican cuándo
conviene cada uno. Hyper-V se consulta de forma remota mediante WinRM con
consultas de solo lectura. XenServer se consulta mediante su API. En los tres
casos, el host y sus máquinas virtuales se reflejan como agentes; consulte la
guía de cada plataforma para los requisitos y las opciones.

## Resultados y primeras comprobaciones

Tras ejecutar la tarea o el plugin:

1. Revisar los errores de ejecución y confirmar que la cuenta de la plataforma
   puede leer lo que se quiere monitorizar.
2. Buscar los agentes del gestor o del host y los de las máquinas virtuales, y
   comprobar que reciben datos recientes.
3. Contrastar una muestra de valores con la consola de la propia plataforma.
4. Recordar que el agente de una máquina virtual descubierta no sustituye a un
   EndPoint dentro del sistema operativo invitado: mide lo que ve el
   hipervisor, no lo que ocurre dentro de la máquina.

El diagnóstico específico corresponde a la guía de cada plataforma. Para errores
del ciclo de tarea, véase
[Cuando falla](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#cuando-falla).
