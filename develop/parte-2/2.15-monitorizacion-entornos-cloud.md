# Monitorización de entornos Cloud

En la nube no hay un servidor donde instalar un EndPoint: hay una API. Pandora
FMS la consulta desde Discovery con una cuenta de solo lectura y convierte lo
que encuentra en agentes y módulos, de modo que las instancias, bases de datos,
almacenamiento y costes de cada proveedor aparecen en la consola web como
cualquier otro elemento monitorizado.

| Proveedor | Servicios cubiertos | Guías de la integración |
|---|---|---|
| Amazon Web Services | Instancias EC2, bases de datos RDS, almacenamiento S3, métricas de CloudWatch y precios y costes. | [EC2](https://pandorafms.com/docs/integrations/latest/es/discovery/amazon-ec2/), [RDS](https://pandorafms.com/docs/integrations/latest/es/discovery/amazon-rds/), [S3](https://pandorafms.com/docs/integrations/latest/es/discovery/amazon-s3/), [CloudWatch](https://pandorafms.com/docs/integrations/latest/es/discovery/amazon-cloudwatch/), [Pricing](https://pandorafms.com/docs/integrations/latest/es/discovery/aws-pricing/) |
| Microsoft Azure | Máquinas virtuales, SQL, almacenamiento, Application Gateway, Load Balancer y copias de seguridad. | [Compute](https://pandorafms.com/docs/integrations/latest/es/discovery/azure-microsoft-compute/), [SQL](https://pandorafms.com/docs/integrations/latest/es/discovery/azure-sql/), [Storage](https://pandorafms.com/docs/integrations/latest/es/discovery/azure-storage/), [Application Gateway](https://pandorafms.com/docs/integrations/latest/es/discovery/azure-application-gateway/), [Load Balancer](https://pandorafms.com/docs/integrations/latest/es/discovery/azure-load-balancer/), [Backup](https://pandorafms.com/docs/integrations/latest/es/discovery/azure-backup/) |
| Google Cloud | Instancias de Compute Engine. | [Compute Engine](https://pandorafms.com/docs/integrations/latest/es/discovery/google-cloud-compute-engine/) |
| OVHcloud | Instancias y volúmenes de Public Cloud, servidores dedicados y costes. | [OVH](https://pandorafms.com/docs/integrations/latest/es/discovery/ovh/) |
| DigitalOcean | Droplets y consumo de la cuenta. | [DigitalOcean](https://pandorafms.com/docs/integrations/latest/es/discovery/digital-ocean/) |

El catálogo de servicios de cada proveedor crece y cambia con frecuencia, por eso
este capítulo no los enumera con detalle: las guías de la tabla son la referencia
vigente de lo que se monitoriza, de los permisos que necesita cada servicio y de
sus parámetros. La instalación de un paquete .disco y el ciclo común de sus
tareas están en
[Cómo funciona la tarea de un paquete .disco](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#como-funciona-la-tarea-de-un-paquete-disco).

Antes de crear una tarea, conviene preparar en el proveedor una identidad
dedicada con permisos de solo lectura, limitada a los servicios que se van a
consultar. Sus credenciales se guardan en el
[gestor de credenciales](2.2-gestor-de-credenciales.md) y no se copian a
ficheros ni a la documentación interna. Conviene comprobar en cada guía si las consultas
a la API tienen un coste o una cuota en el proveedor.

## Amazon Web Services

Cada servicio de AWS tiene su propia integración: EC2 para instancias, RDS para
bases de datos, S3 para buckets, CloudWatch para consultas de métricas
definidas por el usuario y Pricing para precios públicos y costes facturados.
Se autentican con una clave de acceso de AWS asociada a un usuario con permisos
de lectura. En general, cada tarea genera un agente por región y, de forma
opcional, un agente global con estadísticas. Los permisos exactos y las opciones
de cada servicio están en sus guías.

## Microsoft Azure

Azure se monitoriza por servicios: máquinas virtuales, bases de datos SQL,
cuentas de almacenamiento, Application Gateway, Load Balancer y copias de
seguridad. Las integraciones leen una suscripción mediante una aplicación
registrada con acceso de lectura y obtienen las métricas de Azure Monitor. Se
puede elegir entre un agente por recurso y un agente consolidado, según la
guía de cada servicio.

## Google Cloud

La integración de Google Cloud monitoriza las instancias de Compute Engine de un
proyecto y las zonas que las contienen, consultando las API de Compute Engine y
Cloud Monitoring con una cuenta de servicio. Los requisitos y parámetros están
en la [guía de Compute Engine](https://pandorafms.com/docs/integrations/latest/es/discovery/google-cloud-compute-engine/).

## OVHcloud y DigitalOcean

Ambos proveedores tienen una integración propia que se conecta a su API.
OVHcloud cubre instancias y volúmenes de Public Cloud, servidores dedicados y,
si se desea, costes. DigitalOcean cubre los droplets y el consumo de la cuenta.
Cada guía explica cómo obtener las credenciales de API necesarias y qué agentes
genera la tarea.

## Resultados y primeras comprobaciones

Tras ejecutar la tarea:

1. Revisar los errores de ejecución y confirmar que la identidad de solo lectura
   tiene permisos suficientes. Un permiso que falta suele traducirse en
   agentes sin módulos, no en un error evidente.
2. Buscar los agentes esperados: uno global y varios por región, recurso o
   servicio, según la integración.
3. Comprobar que los módulos reciben datos recientes y contrastar una muestra con
   la consola del propio proveedor.
4. Comprobar, según la guía, si las consultas a la API tienen coste o cuota.

El diagnóstico específico corresponde a la guía de cada servicio. Para errores del
ciclo de tarea, véase
[Cuando falla](2.3-monitorizacion-y-descubrimiento-automatico-con-discovery.md#cuando-falla).
