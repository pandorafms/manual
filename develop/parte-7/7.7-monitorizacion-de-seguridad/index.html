    Monitorización de seguridad¶

    Los incidentes serios rara vez empiezan con un ataque brillante. Empiezan con un usuario admin cuya contraseña es admin, con un servidor de pruebas que deja entrar a root por SSH o con un puerto que alguien abrió para una demo hace dos años y nadie volvió a cerrar. Son descuidos pequeños, en máquinas que nadie mira porque «solo son de pruebas», y por eso funcionan: el atacante no busca la puerta blindada, busca la ventana que se quedó abierta.

    Pandora FMS trabaja la seguridad en tres frentes:

    • Monitoriza la infraestructura de seguridad como cualquier otra: copias de seguridad, antivirus, VPN, firewalls, IDS/IPS, SIEM, honeypots, sistemas de autenticación, almacenamiento o recogida de logs. Al final son servicios, procesos, puertos y logs, y se vigilan con las mismas herramientas que el resto.
    • Se protege a sí mismo, con doble autenticación (2FA), contraseñas cifradas en la base de datos y registro de auditoría propio (Configuración segura), autenticación externa y envío de datos cifrado con SSL/TLS en Tentacle.
    • Trae funciones de seguridad propias:
    Función Qué hace
    SIEM Recoge y correlaciona los logs y eventos de seguridad.
    SOAR Automatiza la respuesta cuando el SIEM detecta algo.
    Análisis de vulnerabilidades Busca vulnerabilidades conocidas en el software de los equipos Linux, MS Windows y remotos.
    Hardening Evalúa a lo largo del tiempo lo segura que es la configuración de los equipos Linux y MS Windows.
    FIM Avisa cuando alguien crea, cambia o borra ficheros críticos en Linux o MS Windows.
    Plugins de seguridad Comprueban lo básico en cada intervalo del EndPoint, en Linux y MS Windows. Son el tema de este capítulo.

    La empresa detrás de Pandora FMS tiene la certificación ISO 27001 y es CNA (CVE Numbering Authority) de MITRE, de modo que da de alta los CVE de sus propias vulnerabilidades. Su política de seguridad es pública y está abierta a auditores independientes.

    Los plugins de seguridad son dos programas ligeros, uno para Linux y otro para MS Windows, que el EndPoint ejecuta en cada intervalo (cinco minutos, por defecto). Cada comprobación se convierte en un módulo que está en normal si todo está en orden y en crítico si encuentra algo. No sustituyen al hardening ni al FIM, pero vigilan sin descanso lo que nunca debería fallar.

    Requisitos previos¶

    Requisito Detalle
    EndPoint para Linux Versión 774 o posterior, que instala el plugin pandora_security_check. Necesita Perl en el sistema y que el EndPoint se ejecute como root (lo hace por defecto) para poder leer /etc/shadow.
    EndPoint para MS Windows Versión 775 o posterior, que instala pandora_security_win.exe. Las opciones --metrics y --verbose llegan con la 805.
    Configuración del EndPoint Acceso a su pandora_agent.conf, en el propio equipo o desde la consola web con la configuración remota.

    Plugin de seguridad para Linux¶

    El EndPoint para Linux trae el plugin instalado pero desactivado. Para activarlo, edita /etc/pandora/pandora_agent.conf, busca esta línea y quítale el # del principio:

    module_plugin perl /usr/share/pandora_agent/plugins/pandora_security_check --conf /usr/share/pandora_agent/plugins/pandora_security_check.conf

    El plugin y su fichero de configuración viven en /usr/share/pandora_agent/plugins/, la misma carpeta a la que apunta /etc/pandora/plugins. Reinicia el EndPoint y los módulos aparecen en la consola tras la primera ejecución.

    Si el agente tiene la configuración remota activa, haz el cambio desde la consola web: el EndPoint sustituye su fichero local por el del servidor. Para activarlo en muchos equipos a la vez, añade la misma línea como plugin de EndPoint en una política.

    Comprobaciones y módulos¶

    Cada comprobación crea un módulo de tipo generic_proc en el grupo Security: vale 1 (normal) si todo está en orden y 0 (crítico) si encuentra algo. La descripción del módulo cuenta qué ha encontrado.

    Módulo Qué comprueba Pasa a crítico si…
    SELinux status El estado de SELinux, con sestatus. SELinux está desactivado o no se puede saber (no existe sestatus).
    SSH root access status La directiva PermitRootLogin de /etc/ssh/sshd_config. Tiene cualquier valor distinto de no (también prohibit-password) o el fichero no se puede leer.
    SSH root keys status Las claves SSH de tipo RSA en /root/.ssh y sus subcarpetas, sin contar authorized_keys ni known_hosts. Encuentra alguna. La descripción lista los ficheros.
    Authorized ports status Los puertos TCP en escucha, en IPv4 e IPv6, salvo los que solo escuchan en 127.0.0.1 o ::1. Alguno no está en la lista de puertos permitidos. La descripción dice cuáles.
    Files check status La huella MD5 de cada fichero de la lista, comparada con la de la ejecución anterior. Algún fichero ha cambiado desde la ejecución anterior. La descripción dice cuáles.
    Insecure passwords status Las contraseñas de /etc/shadow, contra el diccionario y contra el nombre de cada usuario. Algún usuario tiene una contraseña del diccionario o igual a su nombre. La descripción dice quiénes.

    Tres de ellas merecen una explicación:

    • Claves de root. No busca quién puede entrar como root en este equipo (eso está en authorized_keys), sino las claves con las que root puede entrar sin contraseña en otras máquinas. Quien se haga con este equipo se las lleva de regalo.
    • Ficheros. El plugin guarda las huellas de una ejecución a otra; la primera solo toma la referencia. El crítico dura una ejecución: en la siguiente, la huella nueva pasa a ser la referencia y el módulo vuelve a normal. Por eso este módulo pide una alerta. Si necesitas saber qué cambió en cada fichero, usa el FIM.
    • Contraseñas. El diccionario trae 100 de las contraseñas más usadas del mundo. Añade las que circulan por tu organización: el nombre de la empresa seguido del año tiene un éxito que no te imaginas. Las cuentas sin contraseña utilizable (*, !!, !locked o !* en /etc/shadow) no se comprueban.

    Sin SELinux, sin ese módulo

    En las distribuciones que no usan SELinux (Debian y Ubuntu, por ejemplo, usan AppArmor), SELinux status estará siempre en crítico. Desactiva esa comprobación con --check_selinux 0.

    Personalizar las listas¶

    Los puertos permitidos, los ficheros vigilados y las contraseñas del diccionario salen de dos sitios que se suman: las listas internas del plugin y su fichero de configuración, pandora_security_check.conf. El fichero tiene tres bloques, [PORTS], [FILES] y [PASSWORDS], con una entrada por línea. Así viene de serie:

    [PORTS]
22
80
443
41121
8080

[FILES]
/etc/httpd/httpd.conf
/etc/my.cnf
/etc/sudoers
/etc/passwd
/etc/hosts

[PASSWORDS]
pandora
PANDORA
P4nd0r4
password
root
linux
admin
    Lista Listas internas El fichero de serie añade
    Puertos permitidos 22, 80 443, 41121 (Tentacle), 8080
    Ficheros vigilados /etc/shadow, /etc/passwd, /etc/hosts, /etc/resolv.conf, /etc/ssh/sshd_config, /etc/rsyslog.conf /etc/httpd/httpd.conf, /etc/my.cnf, /etc/sudoers
    Contraseñas 100 contraseñas comunes pandora, PANDORA, P4nd0r4, root, linux, admin

    Añade los puertos de los servicios que el equipo debe ofrecer, los ficheros de configuración de tus aplicaciones y las contraseñas que conviene desterrar. Los ficheros que no existen se saltan sin más. Si prefieres que mande solo tu fichero, sin las listas internas, añade --include_defaults 0 a la línea del plugin.

    Opciones del plugin¶

    Opción Qué hace
    --conf <fichero> Fichero de configuración con los bloques [PORTS], [FILES] y [PASSWORDS].
    --check_selinux {0,1} Activa (1) o desactiva (0) la comprobación de SELinux.
    --check_ssh_root_access {0,1} Activa o desactiva la comprobación del acceso de root por SSH.
    --check_ssh_root_keys {0,1} Activa o desactiva la búsqueda de claves SSH de root.
    --check_ports {0,1} Activa o desactiva la comprobación de puertos.
    --check_files {0,1} Activa o desactiva la comprobación de ficheros.
    --check_passwords {0,1} Activa o desactiva la comprobación de contraseñas.
    --include_defaults {0,1} Con 0, descarta las listas internas y usa solo las del fichero de configuración.
    --integrity_file <fichero> Fichero donde se guardan las huellas de los ficheros vigilados. Por defecto, uno en /tmp.

    Todas las comprobaciones están activas por defecto. Por ejemplo, en un Ubuntu, sin SELinux y con las huellas fuera de /tmp:

    module_plugin perl /usr/share/pandora_agent/plugins/pandora_security_check --conf /usr/share/pandora_agent/plugins/pandora_security_check.conf --check_selinux 0 --integrity_file /var/lib/pandora_security_check.integrity

    Plugin de seguridad para MS Windows¶

    El EndPoint para MS Windows trae pandora_security_win.exe en la carpeta util de su instalación, también desactivado. Para activarlo, edita su pandora_agent.conf, busca el bloque Pandora basic security check plugin for windows y quita el # de las tres líneas del módulo:

    # Pandora basic security check plugin for windows.
module_begin
module_plugin "%PROGRAMFILES%\Pandora_Agent\util\pandora_security_win.exe" --conf "%PROGRAMFILES%\Pandora_Agent\util\pandora_security_win.conf" 2> nul
module_end

    Reinicia el servicio del EndPoint (PandoraFMSAgent) y los módulos aparecen tras la primera ejecución. Lo dicho para Linux sobre la configuración remota y las políticas vale igual aquí.

    Comprobaciones y módulos¶

    Todos los módulos son generic_proc del grupo Security, como en Linux.

    Módulo Qué comprueba Pasa a crítico si…
    <antivirus> Antivirus status Cada antivirus registrado en el Centro de seguridad de Windows, de Microsoft o de terceros. Por ejemplo, Windows Defender Antivirus status. El antivirus no está activo.
    <antivirus> Antivirus up to date Las firmas de ese mismo antivirus. Las firmas no están al día.
    Lockscreen status Que ninguna directiva desactive la pantalla de bloqueo (valores de registro DisableLockScreen y NoLockScreen). Alguno de los dos la desactiva.
    Microsoft Update system status La fecha de la última actualización instalada con Windows Update. Han pasado 10 días o más.
    Firewall profile: Domain status, Firewall profile: Private status y Firewall profile: Public status Cada uno de los tres perfiles del cortafuegos de Windows. Ese perfil está desactivado.
    All users enforced password Que todas las cuentas de usuario exijan contraseña. Alguna no la exige. La descripción dice cuántas.
    Check logon event audited Que la auditoría de inicios de sesión registre los aciertos y los errores, con auditpol. No registra los dos (tampoco vale solo los aciertos).

    En MS Windows Server no existe el Centro de seguridad de Windows: los módulos de antivirus no se crean, y es lo esperado.

    Sistemas en otros idiomas¶

    auditpol contesta en el idioma del sistema, así que el plugin necesita saber cómo se llama la subcategoría de inicio de sesión y qué textos significan «aciertos y errores» y «sin auditoría». Eso está en pandora_security_win.conf, en la misma carpeta util. De serie viene en inglés, con el español comentado al lado:

    auditpol_logon_category = Logon
#auditpol_logon_category = Inicio de sesión

auditpol_logon_success_conf = Success and Failure
#auditpol_logon_success_conf = Aciertos y errores

auditpol_logon_noaudit_conf = No Auditing
#auditpol_logon_noaudit_conf = Sin auditoría

    En un MS Windows en español, comenta las tres líneas en inglés y quita el # de las tres en español. En cualquier otro idioma, escribe los textos tal como los muestra auditpol /get /category:* en ese equipo.

    Opciones del plugin¶

    Opción Qué hace
    --conf <fichero> Fichero de configuración con los textos de auditpol.
    -m, --metrics Comprobaciones que se ejecutan: all (por defecto), Antivirus, Lockscreen, Windows_update, Firewall, Password y Logon. Admite varias, separadas por espacios. Desde la 805.
    -v, --verbose Escribe los errores por la salida de error. Sirve para ejecutar el plugin a mano y ver qué falla. Desde la 805.

    Por ejemplo, para quedarte solo con el cortafuegos, las contraseñas y la auditoría:

    module_plugin "%PROGRAMFILES%\Pandora_Agent\util\pandora_security_win.exe" --conf "%PROGRAMFILES%\Pandora_Agent\util\pandora_security_win.conf" --metrics Firewall Password Logon 2> nul

    Consultar los resultados¶

    Los módulos aparecen en la vista del agente, en el grupo Security, junto a los del hardening, el análisis de vulnerabilidades y el FIM si están activos. Para ver solo ese grupo, abre Filters sobre la lista de módulos y elige Security en Module group. La columna Description dice qué ha encontrado cada comprobación: qué puertos, qué ficheros, qué usuarios.

    En la misma vista, el panel Security resume el grupo en SecurityMon: crítico si algún módulo del grupo Security lo está, aviso si alguno está en aviso y normal si todos están bien. Como el grupo incluye también los módulos del hardening, las vulnerabilidades y el FIM, SecurityMon es el semáforo de seguridad del agente entero.

    Alertas¶

    Como son módulos generic_proc, les sirve cualquier plantilla de alerta para módulos en crítico. Cómo montarlas está en Alertas y notificaciones.

    Ponle una a Files check status sí o sí. Su crítico dura una ejecución: en la siguiente vuelve a normal, y aunque queda el evento, si nadie lo mira, el cambio pasa sin pena ni gloria. El resto de módulos se quedan en crítico mientras el problema siga ahí.

    Operación y solución de problemas¶

    Síntoma Qué comprobar
    No aparecen los módulos La línea del plugin sigue comentada o el EndPoint no se ha reiniciado. Con la configuración remota activa, el cambio tiene que hacerse desde la consola web.
    No aparecen los módulos en Linux, con la línea activa Que Perl está instalado: el plugin es un script de Perl.
    SELinux status siempre en crítico La distribución no usa SELinux: añade --check_selinux 0.
    Authorized ports status en crítico por un servicio legítimo Añade su puerto al bloque [PORTS] de pandora_security_check.conf.
    Insecure passwords status en crítico con «Can not read /etc/shadow» El EndPoint no se ejecuta como root.
    Files check status en normal aunque un fichero cambió El crítico dura una ejecución. Revisa los eventos del módulo o ponle una alerta.
    Faltan los módulos de antivirus en MS Windows En MS Windows Server no se crean: no hay Centro de seguridad de Windows.
    Check logon event audited no aparece o está siempre en crítico El sistema está en otro idioma: ajusta pandora_security_win.conf. Si sigue igual, comprueba con auditpol que se auditan los aciertos y los errores.
    Microsoft Update system status en crítico El equipo lleva 10 días o más sin instalar actualizaciones de Windows Update.
