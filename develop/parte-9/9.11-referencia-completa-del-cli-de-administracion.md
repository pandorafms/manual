# Referencia completa del CLI de administración (pandora_manage)

`pandora_manage` es la herramienta de administración que se ejecuta **en el
servidor** y habla directamente con la base de datos y con las librerías del
producto. No es un cliente de la API: no hay petición HTTP, ni token, ni lista de
direcciones permitidas. Eso le deja hacer cosas que la API no puede hacer y, por
la misma razón, no sirve para administrar una consola desde fuera.

No está retirado ni es una reliquia: sigue siendo la única vía para media docena
de operaciones que la API v2 no expone. Lo que cambia es el reparto. Las tres
herramientas de línea de comandos no compiten entre sí:

| Herramienta | Dónde se ejecuta | Con qué habla | Qué la autoriza |
|---|---|---|---|
| `pandora_manage` | En el servidor | Base de datos y librerías locales | Acceso al sistema |
| `pandora_revent` | En cualquier máquina | API v1 (`api.php`) | IP permitida, contraseña de API y usuario |
| [`pandora-cli`](../parte-13/13.5-cli-de-la-api-v2-pandora-cli.md) | En cualquier máquina | API v2 | Sesión o token del usuario |

La consecuencia práctica es la de siempre: lo que se hace con `pandora_manage`
**no pasa por la API**, así que no le afectan sus capas de seguridad —la lista de
IPs ni la contraseña de API— y tampoco sus permisos de usuario. Lo que limita el
uso es el acceso al servidor y a la base de datos. Por eso se ejecuta como root,
en la máquina, y no se le da a un script remoto.

## Dónde vive y qué necesita

El binario se instala con el servidor en `/usr/bin/pandora_manage`. Necesita tres
cosas:

- **La configuración del servidor**, que va como primer argumento:
  `/etc/pandora/pandora_server.conf`.
- **Permisos de root.** Lee la configuración del servidor y escribe en la base de
  datos.
- **La base de datos accesible.** El programa se conecta nada más arrancar, antes
  de ejecutar ninguna opción; si la configuración o la conexión fallan, no hace
  nada.

```bash
pandora_manage /etc/pandora/pandora_server.conf --opcion parametro1 parametro2
```

No hay más ceremonia: ni login, ni contexto, ni fichero de credenciales propio.

## Sintaxis y comillas

La forma general es la de arriba. Los parámetros obligatorios y los opcionales
aparecen en la ayuda entre corchetes, y se pasan en el mismo orden.

- **Comillas simples** para cualquier valor con espacios:
  `--create_group 'Servidores virtuales'`.
- **Dos comillas simples juntas** (`''`) para saltar un parámetro opcional sin
  pasar al siguiente. Si el parámetro era obligatorio, el programa responde con
  el error y la ayuda.
- **`use_alias` al final** en los comandos que lo admiten: así el agente se
  identifica por su alias en vez de por su nombre interno. Va como último
  parámetro, no en medio.
- **Grafía exacta** de los nombres que ya existen. Cuando el valor es el nombre
  de un agente, un grupo o un servidor, usa la misma cadena que guarda la
  consola: el programa busca coincidencia, y una diferencia de mayúsculas o un
  espacio de más es un «no existe».

## La ayuda

La ayuda completa, con todas las categorías:

```bash
pandora_manage --h | more
```

`--help` hace lo mismo. El programa reconoce cualquier opción que empiece por
guion y termine en `h`, así que `--h` es la forma corta que se usa en la calle.

Ejecutarlo sin ninguna opción no imprime la ayuda limpia: primero avisa de que no
hay argumentos y después la muestra. Y si se pasa una opción con un número de
parámetros distinto del que espera, el programa responde con el error de
parámetros y **solo la línea de esa opción**, que es la forma rápida de consultar
una firma concreta:

```
[ERROR] Parameters error: 0 received | 1 necessary.
```

## Lo que la API no expone

Estas operaciones no tienen equivalente en la API v2, así que hoy solo se pueden
hacer aquí. Van con el capítulo donde se cuentan si lo tienen:

| Operación | Opción | Dónde se cuenta |
|---|---|---|
| Desbloquear un usuario bloqueado por intentos fallidos | `--unlock_user <usuario>` | [7.11](../parte-7/7.11-configuracion-segura.md) |
| Quitar la doble autenticación a un usuario | `--disable_double_auth <usuario>` | [4.2](../parte-4/4.2-autenticacion-externa-y-centralizacion-de-accesos.md) |
| Activar o desactivar la ACL avanzada | `--enable_eacl`, `--disable_eacl` | [4.3](../parte-4/4.3-seguridad-y-visibilidad-avanzada-enterprise-acl.md) |
| Limpiar o borrar la configuración remota de un agente | `--clean_conf_file`, `--delete_conf_file` | Este capítulo |
| Clústeres: crear, añadir agentes y elementos, consultar estado | `--new_cluster`, `--add_cluster_agent`, `--get_cluster_status` | [9.6](9.6-monitorizacion-de-clusters.md) |
| Reiniciar los contadores de módulos y alertas de un agente | `--reset_agent_counts <id_agente>` | Este capítulo |
| Comprobar una vulnerabilidad contra la base local | `--check_vulnerabilities <software> <versión> [<so>]` | [7.4](../parte-7/7.4-analisis-de-vulnerabilidades.md) |

Un ejemplo de cada una de las dos primeras, que son las que más se usan en una
urgencia:

```bash
pandora_manage /etc/pandora/pandora_server.conf --unlock_user jdoe
pandora_manage /etc/pandora/pandora_server.conf --disable_double_auth jdoe
```

Las dos escriben en la base de datos y no piden confirmación. Comprueba el
usuario antes de lanzarlas.

## Recetas frecuentes

**Crear un grupo y un agente dentro.** El sistema operativo y el servidor tienen
que existir ya en la consola:

```bash
pandora_manage /etc/pandora/pandora_server.conf \
    --create_group 'Servidores virtuales' 'Servidores'

pandora_manage /etc/pandora/pandora_server.conf \
    --create_agent web1 Linux 'Servidores virtuales' pandora.local 10.0.0.5 'Frontal web'
```

**Crear un usuario.** El tercer parámetro es `1` para administrador y `0` para un
usuario normal:

```bash
pandora_manage /etc/pandora/pandora_server.conf \
    --create_user jdoe 'contraseña-larga' 0 'Equipo de operaciones'
```

Un usuario recién creado sin perfil asignado no puede entrar; los perfiles se
añaden con `--add_profile_to_user`.

**Lanzar un evento.** Los tres primeros parámetros son obligatorios; el resto son
opcionales y se pueden dejar con `''`:

```bash
pandora_manage /etc/pandora/pandora_server.conf \
    --create_event 'Reinicio programado' system 'Servidores virtuales'
```

**Aplicar una política a un agente.** El primer parámetro es el identificador de
la política, no su nombre:

```bash
pandora_manage /etc/pandora/pandora_server.conf --apply_policy 7 42
```

Las paradas planificadas tienen su propia sección en
[3.8](../parte-3/3.8-paradas-planificadas.md), con la sintaxis completa y los
cuatro tipos.

## Cuándo no usarlo

- **Trabajo remoto.** Si la consola está en otro servidor, o el script corre en
  otra máquina, esto no sirve: usa la API v2 o
  [`pandora-cli`](../parte-13/13.5-cli-de-la-api-v2-pandora-cli.md).
- **Trabajo que debe quedar sujeto a permisos de consola.** Aquí no hay perfil
  ACL que valga: quien puede ejecutar el binario puede hacer la operación.
- **Eventos contra una consola remota.** Para eso está `pandora_revent`, que
  habla con la API v1 con las credenciales de un usuario.

La regla es simple: si la operación existe en la API y la vas a hacer desde
fuera, hazla por la API. Si no existe, o estás en el servidor y necesitas tocar
la base de datos, este es el camino.

## Problemas habituales

| Mensaje | Causa y remedio |
|---|---|
| `[ERROR] No valid arguments` | Se ejecutó sin opción. Añade la opción, o `--h` para ver la ayuda. |
| `[ERROR] Parameters error: N received | M necessary.` | Número de parámetros distinto del que espera. Debajo sale la línea de esa opción. |
| `[ERROR] Error: The user 'jdoe' does not exist.` | El nombre o identificador no existe en la consola. Revisa la grafía. |
| `[ERROR] Error: The group 'Servidores' already exists.` | Ya hay un elemento con ese nombre. Usa otro, o modifica el existente. |
| El nodo está en modo centralizado y la operación se rechaza | Esa operación se hace en el Command Center, no en el nodo. |
| `Can't locate PandoraFMS/SIEMServer.pm` | Se está ejecutando el `.pl` de `util/` en vez del binario instalado. Usa `/usr/bin/pandora_manage`. |
| No hace nada y no hay error visible | La configuración o la base de datos no cargan. El programa se conecta al arrancar: revisa la ruta del `.conf` y el acceso a la base de datos. |
