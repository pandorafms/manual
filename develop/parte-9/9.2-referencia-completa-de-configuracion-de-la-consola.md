# Referencia completa de configuración de la consola

Esta referencia no se lee de corrido: se consulta por nombre de opción o por
pestaña, como un diccionario. Reúne toda la configuración de la consola web
(nodo y Command Center) y de `include/config.php`, para que cualquier otro
capítulo pueda enlazar aquí en vez de repetir una tabla de opciones.

Dónde vive cada cosa:

- **Consola web (Ajustes → Configuración del sistema).** Casi toda la
  configuración de comportamiento, aspecto y credenciales de servicios
  externos. Se guarda en la base de datos, no en un fichero: cambia en
  caliente, sin reiniciar nada.
- **`include/config.php`.** Un puñado de valores que solo se editan a mano,
  antes de que la consola pueda conectar con la base de datos: conexión a la
  base de datos, ruta de instalación, frase de cifrado. Ver § 23.
- **Command Center.** Consola especial que centraliza varios nodos. Tiene sus
  propias páginas de configuración (§ 22) y, además, puede fijar
  centralizadamente ciertos ajustes de los nodos que gestiona.

Un nodo con «Gestión centralizada» activa en una sección concreta deja de
aceptar cambios locales en esa sección: se editan desde el Command Center y
se sincronizan al nodo.

| Token de Telegram | Sustituye la macro de alerta que referencia el token del bot | Vacío |  |

La opción **Autenticación SMTP** no prueba los mecanismos uno detrás de otro.
El servidor de Pandora FMS usa el primero de los que anuncia el servidor de
correo y, si lo rechaza, el envío falla. Un proveedor que anuncie
`DIGEST-MD5` y luego lo rechace —Postmark es el caso que originó este
ajuste— obliga a elegir `LOGIN` a mano. `PLAIN` queda fuera del valor por
defecto porque algunos servidores responden con el error `451 4.5.0 SMTP
protocol violation`. La opción solo actúa cuando el correo se configura en la
consola; si `pandora_server.conf` define `mta_address`, mandan los valores
`mta_*` del fichero y este ajuste no interviene.

### 1.8 Update

Formulario de correo de prueba (Email test) para validar la configuración de
la pestaña anterior sin salir de la página; no es una opción de
configuración. El envío lo hace la consola, no el servidor, y no usa el
mecanismo de autenticación SMTP de § 1.7: que la prueba llegue no garantiza
que salgan las alertas.

*Ver también:* [9.3 · Referencia completa de configuración del
servidor](9.3-referencia-completa-de-configuracion-del-servidor.md) § 11,
para el correo saliente que usa el propio servidor al ejecutar alertas.

### 22.3 Qué se sincroniza del nodo desde el Command Center

La «gestión centralizada» permite que el Command Center escriba la
configuración de un nodo, además de políticas, ACL avanzado y componentes,
de forma sincronizada: la sección afectada del nodo deja de aceptar cambios
locales mientras la gestión centralizada esté activa (ver introducción de
este capítulo). El detalle exacto de qué secciones son sincronizables no
está verificado a fecha de esta redacción; se ampliará en una revisión
posterior de este capítulo.
