# Mapas GIS

## Introducción

Un **mapa GIS** es una representación visual de dónde está, geográficamente, cada
agente de la instalación. Sobre un mapa base (calles, imagen de satélite o un
plano propio), los agentes aparecen como marcadores en su última posición
conocida, con el color de su estado. De un vistazo se ve dónde está cada equipo y
cómo está. Los agentes que no reportan coordenadas propias no se quedan fuera: se
dibujan en la **posición por defecto para agentes sin información GIS** del mapa,
un punto que se fija al crear la conexión o el mapa.

Es la vista geográfica de la Parte 5. El capítulo
[5.7 Mapas topológicos de red](5.7-mapas-topologicos-de-red.md) dibuja relaciones:
quién depende de quién, cómo se conectan los equipos. Un mapa GIS dibuja lugares.
No compiten: uno responde a «qué se cae con qué» y el otro, a «dónde está lo que
se cae».

Para que un mapa GIS muestre algo hay que poner de acuerdo a tres piezas. El
EndPoint aporta la posición, el servidor de Pandora FMS la procesa y la guarda, y
la consola web define las conexiones de mapa y los mapas. El capítulo recorre las
tres en ese orden y termina con la referencia de los parámetros implicados.

## Requisitos y activación

| Requisito | Detalle |
|---|---|
| Servidor con GIS activado | Token `activate_gis` a `1` en `pandora_server.conf`. Por defecto vale `0` y, con ese valor, el servidor descarta toda la información de posición que reciba |
| Consola con la funcionalidad activada | Interruptor **Habilitar funcionalidades GIS** en la configuración general de la consola web |
| Un mapa por defecto | Debe haber un mapa marcado como predeterminado; es el que usa la vista de agente para situarlo |
| Acceso a Internet | Las conexiones OpenStreetMap y Google Maps cargan las teselas del mapa base desde el navegador del usuario |
| Clave de API de Google Maps | Una clave válida; puede tardar unos minutos en activarse del todo |
| Geoposicionamiento inverso | Internet (Google u OpenStreetMap) o un fichero local de MaxMind GeoLiteCity |

El interruptor de la consola web está en **Gestión → Ajustes → Configuración del sistema → Configuración
general**, en la pestaña **Características**: «Habilitar funcionalidades GIS» →
**Actualizar**.

![Pestaña Características de la configuración general, con el interruptor Habilitar funcionalidades GIS](../../assets/img/parte-05/gis-activar-funcionalidades.png)

Recuerda que son dos interruptores distintos: el de la consola decide qué partes
de la interfaz se muestran; el del servidor decide si la información de posición
se procesa y se guarda. La consola puede estar mostrando los mapas mientras el
servidor ignora lo que recibe.

## Configurar la posición de los EndPoints

El fichero de configuración del EndPoint, `pandora_agent.conf`, admite parámetros
de posición fija. Con ellos se sitúa el agente sin depender de nada más:

```ini
latitude 40.37346827
longitude -3.6418548
altitude 637
position_description Madrid, Vallecas
```

| Requisito | Detalle |
|---|---|
| `latitude` | Latitud en grados decimales |
| `longitude` | Longitud en grados decimales |
| `altitude` | Altitud en metros; es opcional |
| `position_description` | Descripción legible del lugar (por ejemplo, «Madrid, Vallecas»); es opcional |
| `gis_exec` | Ruta de un **script** que devuelve las coordenadas |

`gis_exec` apunta a un script que, al ejecutarse, imprime una única línea con las
coordenadas separadas por comas: `latitud,longitud,altitud`. La altitud es
opcional. Un ejemplo de salida válida sería `41.377,-5.105,2.365`. El script debe
existir en el sistema; si la ruta no resuelve a un fichero real, el EndPoint
ignora `gis_exec` y usa los valores manuales. Cuando `gis_exec` está definido y
es ejecutable, manda sobre `latitude` y `longitude`.

!!! warning "La salida de `gis_exec` no se interpreta igual en todas las piezas"
    El **EndPoint** lee la cadena como `latitud,longitud,altitud`; el **servidor
    satélite**, en cambio, como `longitud,latitud,altitud`. Si un mismo script va
    a alimentar a los dos, ten presente el orden que espera cada uno: el mismo
    `41.377,-5.105` significa coordenadas distintas según quién lo lea.

## Geoposicionamiento inverso y Discovery

El servidor de Discovery puede calcular la posición de los agentes que descubre
sin que estos reporten nada: geolocaliza su dirección IP y los coloca en el
mapa. Para ello usa un algoritmo de geolocalización inversa y una base de datos
que relaciona direcciones IP con posiciones. El token
`recon_reverse_geolocation_file` señala el fichero con esa información, en formato
MaxMind GeoLiteCity (`GeoLiteCity.dat`). Si el fichero no existe o no se puede
leer, el servidor avisa y lo descarta.

Como la posición deducida de una IP es aproximada, el token
`recon_location_scatter_radius` dispersa los agentes al azar alrededor del punto
calculado, con un radio en metros, para que no se apilen todos en el mismo
lugar. Un valor de `0` los deja exactamente en el punto deducido.

Además del fichero local, el servidor puede resolver la dirección en línea:

- `google_maps_description`, a `1`, activa el geoposicionamiento inverso con la
  API pública de Google Maps.
- `openstreetmaps_description`, a `1`, lo activa con la API pública de
  OpenStreetMap.

!!! warning "El geoposicionamiento inverso en línea cuesta rendimiento"
    Las dos opciones anteriores **disminuyen el rendimiento** del servidor y
    **necesitan acceso a Internet**: hay que resolver la dirección de cada
    posición recibida. Dependen, además, de que el proveedor del servicio esté
    disponible.

El último token del procesado es `location_error`, un radio en metros. Dos
posiciones separadas por menos de esa distancia se consideran la misma. Sirve
para que un agente inmóvil no parezca moverse por el ruido del receptor GPS: si
el salto no supera el umbral, el servidor actualiza la posición actual pero no la
archiva como un desplazamiento. Cuando el agente sí se mueve más allá del umbral,
el servidor guarda la posición anterior en el histórico y fija la nueva. La
posición actual y el histórico de posiciones se guardan en la base de datos; su
esquema está en [10.1](../parte-10/10.1-esquema-de-la-base-de-datos.md) y
[10.2](../parte-10/10.2-referencia-de-tablas.md).

## Conexiones de mapa

Una **conexión de mapa** define de dónde salen los mapas base: el servidor de
teselas, la clave de Google, la imagen estática o el servicio WMS. Se crean desde
la consola web en **Gestión → Ajustes → Configuración del sistema → Conexión de mapa GIS**. La lista
muestra las conexiones existentes y el botón **Crear** abre el formulario de
alta.

![Lista de conexiones de mapa GIS, con las dos conexiones de OpenStreetMap predefinidas](../../assets/img/parte-05/gis-conexiones-lista.png)

Toda conexión comparte unos campos básicos antes de elegir el tipo:

| Requisito | Detalle |
|---|---|
| Nombre de la conexión | Nombre con el que se identifica y se selecciona después al montar un mapa |
| Grupo | Grupo al que pertenece la conexión |
| Número de niveles de zoom | Niveles de aumento disponibles en el mapa |
| Nivel de zoom por defecto | Nivel con el que se abre el mapa, salvo que el propio mapa lo redefina |

Elegido el tipo, aparecen sus campos propios. Los cuatro tipos posibles son
**OpenStreetMaps**, **Google Maps**, **Imagen estática** y **Servidor WMS**.

**OpenStreetMaps.** Solo pide la URL del servidor de teselas, con los marcadores
`${z}`, `${x}` e `${y}` en su sitio:

```text
http://tiles.example.com/${z}/${x}/${y}.png
```

![Formulario de conexión de tipo OpenStreetMaps, con el campo de la URL del servidor tile](../../assets/img/parte-05/gis-conexion-openstreetmap.png)

La instalación trae dos conexiones de OpenStreetMap listas para probar,
«OpenStreetMap (MapQuest Open)» y «OpenStreetMap (Standard)».

**Google Maps.** Pide el tipo de mapa base (Google Hybrid, Google Physical o
Google Satélite) y la clave de API de Google Maps.

![Formulario de conexión de tipo Google Maps, con el tipo de mapa y la clave de API](../../assets/img/parte-05/gis-conexion-google.png)

**Imagen estática.** Usa una imagen propia como mapa base. La imagen debe estar
en la proyección EPSG:4326 (WGS84). Se indican su URL, sus esquinas (izquierda,
inferior, derecha y superior) y su tamaño en píxeles (anchura y altura).

![Formulario de conexión de tipo imagen estática, con la URL, las esquinas y el tamaño](../../assets/img/parte-05/gis-conexion-imagen-estatica.png)

**Servidor WMS.** Se indica la URL del servicio y la lista de capas que se
quieren obtener de él. Es la vía para un servidor de mapas propio (por ejemplo,
GeoServer) cuando no se puede tirar de un servicio en línea.

![Formulario de conexión de tipo servidor WMS, con la URL del servicio y las capas](../../assets/img/parte-05/gis-conexion-wms.png)

Una vez fijado el tipo, quedan el **centro del mapa** y la **posición por defecto
para agentes sin información GIS**: el punto en el que se abre el mapa y el punto
en el que se colocan los agentes que no reportan coordenadas. La consola ofrece
dos formas de fijarlos. Se previsualiza el mapa con **Vista previa del mapa** y se
hace clic sobre él, eligiendo antes con el selector **Cambiar en el mapa** cuál de
los dos puntos se está moviendo; o se escriben los valores a mano en sus celdas,
con el punto como separador decimal.

![Centro del mapa y posición por defecto para agentes sin información GIS](../../assets/img/parte-05/gis-conexion-centro-mapa.png)

Se guarda la conexión con **Guardar**.

## Crear y definir un mapa GIS

Los mapas GIS se gestionan en **Operación → Mapas topológicos → Mapas GIS →
Lista de mapas GIS**. La lista permite crear,
editar, ver y borrar mapas, y marcar cuál es el **mapa por defecto** con el botón
de opción de la columna «Por defecto».

![Lista de mapas GIS, con el mapa de ejemplo marcado como predeterminado](../../assets/img/parte-05/gis-mapas-lista.png)

!!! warning "Hace falta un mapa por defecto"
    La vista de agente sitúa al agente sobre el mapa por defecto. Sin uno marcado
    como tal, esa vista avisa de que no hay mapa por defecto y no muestra
    posición.

El botón **Crear** abre el creador de mapas. Los primeros campos son el **Nombre
del mapa**, el grupo, el **Zoom por defecto** y las coordenadas del centro y de
la posición por defecto. Después se añaden una o más **conexiones de mapa**, que
se usarán como capas base: se seleccionan en **Añadir conexión al mapa** y se van
sumando a la lista. Solo una de ellas puede estar activa como capa base a la vez.

![Creador de mapas GIS con el nombre, las conexiones y las coordenadas](../../assets/img/parte-05/gis-mapa-crear.png)

Al marcar una conexión como la predeterminada del mapa, o al cambiarla, la
consola pregunta si se quieren usar sus datos por defecto. Si se acepta, rellena
las coordenadas del centro, la posición por defecto y el zoom con los valores de
la conexión; si se rechaza, no toca nada y solo añade la conexión.

**Capas.** Una capa decide qué agentes se pintan en el mapa. Cada capa puede
mostrar los agentes de un grupo, una lista concreta de agentes o un grupo con un
agente representante. Se crean desde **Nueva capa**, donde se fija su nombre, si
está visible, el grupo del que toma los agentes y la lista de agentes, y se
añaden a la lista de capas del mapa. Las capas se pueden ordenar, editar y borrar,
y todas se guardan con el resto del mapa.

!!! warning "Un grupo con representante no se repite"
    Una vez que una capa tiene un grupo con su agente representante, no se puede
    crear otra capa con ese mismo grupo y otro representante.

El mapa se guarda con **Guardar mapa**. Si el mapa va a ser el mapa por defecto, no hace falta
definir capas: se usa para situar al agente en su vista.

## Operar el mapa

El visor del mapa muestra el mapa con sus capas y sus controles. En el título
aparece el nombre del mapa y, en la barra
superior, los controles de operación.

![Visor de un mapa GIS, con el mapa base y los controles de la barra superior](../../assets/img/parte-05/gis-mapa-visor.png)

**Navegación.** Las flechas de la esquina superior izquierda desplazan el mapa en
cada dirección; los iconos **+** y **-** y la barra de zoom cambian el nivel de
aumento. También se puede arrastrar el mapa con el ratón.

**Capas.** El control de capas permite elegir la capa base (cuando el mapa tiene
más de una conexión) y marcar qué capas se ven y cuáles no. Entre ellas está la
capa del sistema **Jerarquía de agentes**, que dibuja líneas punteadas
entre un agente y su padre cuando ambos están visibles.

**Filtros por estado.** El selector **Filtro por estado** reduce los agentes
mostrados a los que están en un estado concreto: **Ninguno** (todos), **Crítico**,
**Advertencia**, **Ok** u **Otros**.

**Actualización.** El selector **Actualizar** fija cada cuánto se refresca el
mapa (de 5 segundos a 2 horas, con 1 minuto por defecto). El refresco se hace por
AJAX, sin recargar la página.

Al hacer clic sobre un agente se despliega su información, y el nombre del agente
enlaza con su vista de agente. Si el usuario tiene permiso de gestión, la barra
incluye además el botón de engranaje para editar el mapa y el enlace al mapa
público, que abre el visor sin necesidad de iniciar sesión.

## Vista de agente y datos GIS

En la vista de agente (ver [2.21](../parte-2/2.21-configuracion-comun-de-los-agentes.md#las-pestanas-de-la-vista-del-agente)), la pestaña **Datos GIS** muestra el mapa por defecto y la
posición del agente. Con GIS activado en la consola, la barra de pestañas incluye
esa sección, que además de la posición en latitud, longitud y altitud presenta una
tabla con la información reportada por el agente en el periodo elegido (incluida
la descripción del lugar, resuelta por geoposicionamiento inverso) y el histórico
de posiciones.

![Vista GIS de un agente, con el mapa por defecto y el histórico de posiciones](../../assets/img/parte-05/gis-agente-vista.png)

En la administración del agente, la pestaña **Datos GIS** sirve para fijar la
posición a mano: se hace clic sobre el mapa o se rellenan los campos de latitud,
longitud y altitud del formulario inferior.
Al cambiar la posición manualmente, la consola activa sola la opción **Ignorar
nuevos datos GIS**, para que el siguiente paquete de datos no reajuste lo que se
acaba de fijar. Si no es eso lo que se quiere, hay que desactivarla antes de
pulsar **Actualizar**.

![Pestaña Datos GIS de la administración del agente, con el mapa y los campos de posición](../../assets/img/parte-05/gis-agente-datos.png)

El otro extremo de ese ajuste está en la gestión del agente, en la opción
**Actualizar nuevos datos GIS**. Cuando está activada, el servidor aplica la
información de posición que recibe; cuando está desactivada, mantiene la última
posición válida. Es la opción útil cuando un agente reporta una posición errónea o
cuando hay que dejarlo en una posición fija. Si se fija la posición a mano en la
pestaña **Datos GIS**, conviene revisar después esta opción: es el mismo ajuste
visto desde el otro lado.

!!! note "La pestaña Datos GIS se muestra aunque el GIS global esté apagado"
    La administración del agente fuerza el interruptor global para montar la
    pestaña **Datos GIS**, así que esa interfaz aparece aunque «Habilitar
    funcionalidades GIS» esté desactivado. El botón de la vista GIS del agente,
    en cambio, sí depende del interruptor global y no se muestra si está apagado.

## Referencia de parámetros

El detalle completo de cada token, con su contexto, está en [9.3 Referencia de configuración del
servidor](../parte-9/9.3-referencia-completa-de-configuracion-del-servidor.md) y
en [9.1 Referencia de configuración del
EndPoint](../parte-9/9.1-referencia-completa-de-configuracion-del-endpoint.md).

**Servidor (`pandora_server.conf`)**

| Parámetro | Valor por defecto | Qué hace |
|---|---|---|
| `activate_gis` | `0` | Activa (`1`) o desactiva (`0`) el procesado de información GIS en el servidor |
| `location_error` | `50` | Radio en metros por debajo del cual dos posiciones se consideran la misma |
| `recon_reverse_geolocation_file` | vacío | Fichero MaxMind GeoLiteCity para el geoposicionamiento inverso de los agentes descubiertos |
| `recon_location_scatter_radius` | `50` | Radio en metros del círculo en el que se dispersan al azar los agentes descubiertos |
| `google_maps_description` | `0` | Activa (`1`) el geoposicionamiento inverso con la API de Google Maps |
| `openstreetmaps_description` | `0` | Activa (`1`) el geoposicionamiento inverso con la API de OpenStreetMap |

**EndPoint (`pandora_agent.conf`)**

| Parámetro | Formato | Qué hace |
|---|---|---|
| `latitude` | Grados decimales | Latitud fija del dispositivo |
| `longitude` | Grados decimales | Longitud fija del dispositivo |
| `altitude` | Metros (opcional) | Altitud del dispositivo |
| `position_description` | Texto libre | Descripción legible del lugar |
| `gis_exec` | Ruta de un script | Script que devuelve `latitud,longitud,altitud` en una línea |
