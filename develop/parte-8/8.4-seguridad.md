# Seguridad

Pandora AI añade a la consola una pieza que habla con un proveedor externo y que
puede ejecutar acciones en nombre de un usuario. Eso obliga a responder tres
preguntas antes de desplegarlo: quién puede usarlo, cómo se protege la conexión
y qué datos salen de la plataforma. Esta página las reúne desde el punto de vista
de quien administra el producto.

La instalación y la configuración están en
[Introducción e instalación](8.1-introduccion-e-instalacion.md); el uso, en
[Uso del chat](8.2-uso-del-chat.md); y lo que queda registrado, en
[Auditoría](8.5-auditoria.md). Los grupos y perfiles de Pandora FMS se explican
en [Grupos, perfiles y tags](../parte-4/4.1-grupos-perfiles-y-tags.md).

## Modelo de seguridad

El asistente es **un usuario más, pero encerrado**. Tres ideas lo resumen:

1. **Permisos del usuario**: el asistente nunca tiene más permisos que la
   persona que pregunta. Si el usuario no puede borrar un agente, el asistente
   tampoco.
2. **Entorno aislado**: cada usuario trabaja en su propio espacio. El asistente
   no accede a la base de datos ni a los ficheros del sistema, y solo puede leer
   los ficheros que el usuario sube a su sesión.
3. **Salida controlada**: para crear, modificar o borrar en Pandora FMS usa
   `pandora-cli`, que pasa por la API de la consola. Lo que no se puede hacer
   con la CLI, no se hace.

La superficie expuesta es pequeña: el servicio escucha en el puerto 9080 y, por
defecto, solo en local; la consola no abre puertos nuevos y no hay que publicar
nada en internet. El riesgo real no es un acceso anónimo, sino un usuario con más
permisos de los necesarios y un proveedor externo que recibe datos.

## Transporte y certificados

- **HTTPS en las dos direcciones**: consola → servicio y servicio → API de la
  consola. La consola solo usa HTTPS.
- **Certificado del servicio**: por defecto se genera un autofirmado en cada
  arranque. La consola puede aceptarlo (**Security → Accept self-signed
  certificates**) o se instala un certificado propio y se indican el certificado
  y la CA. Mientras se aceptan autofirmados, las rutas se ignoran.
- **Certificado de la consola**: el servicio puede aceptar el autofirmado de la
  API o verificar el certificado y la CA.
- **Lista de acceso**: la IP del servicio debe estar en **General Setup → IP list
  with API access**. Sin ella, la API responde 401 o 403.
- **Red**: el servicio solo necesita su puerto y salida al proveedor. Si consola
  y servicio están en máquinas distintas, abre el puerto solo a la consola.

## Permisos de uso

Tres piezas, en este orden:

1. **Interruptor global**: **Enable Pandora AI** en **General Setup**. Si está
   apagado, no hay menú, no hay configuración y el icono avisa.
2. **Usuarios**: **Allowed users** (con **All users**) y **Blocked users**.
3. **Grupos**: **Allowed groups** (con **All groups** y **Group recursion**) y
   **Blocked groups** (con su propia recursión).

![Pestaña Blocked users con el selector de usuarios](../../assets/img/parte-08/ai-setup-blocked-users.png){ .captura }

![Pestaña Blocked groups con el selector de grupos y la recursión](../../assets/img/parte-08/ai-setup-blocked-groups.png){ .captura }

La precedencia es la fuente de casi todas las dudas:

- **El bloqueo siempre gana**. Un usuario bloqueado, o que pertenece a un grupo
  bloqueado, no usa Pandora AI aunque esté permitido o aunque **All users** esté
  activo.
- **All users** permite a todos salvo los bloqueados; **All groups**, a los
  miembros de todos los grupos salvo los bloqueados.
- **Group recursion** incluye los subgrupos del grupo seleccionado; sin él, solo
  el grupo exacto.
- **Los administradores no tienen acceso automático**. Si no están en la lista y
  **All users** está apagado, no lo tienen. Es distinto de otras pantallas de la
  consola.

El permiso se evalúa en cada petición. Si se retira, el chat deja de funcionar y
las tareas programadas del usuario fallan con un error explícito.

## La clave del proveedor

- La clave es **global**: la configura la administración, no cada usuario. Se
  guarda en la base de datos de la consola.
- Si la base de datos tiene `encryption_passphrase`, la clave se guarda cifrada.
  Si no, la consola avisa y la clave queda sin cifrar.
- Si se cambia la clave en **Service**, el siguiente uso la toma y continúa.
  Dejarla vacía conserva la actual.
- La clave no se muestra en la consola: el campo aparece enmascarado y solo se
  puede reemplazar, no leer.

## Qué se envía al proveedor

El proveedor recibe los mensajes de la conversación, el contexto que el asistente
consulte y el **contenido de los adjuntos** que se envíen. No recibe la base de
datos ni ficheros del sistema.

La retención en el proveedor es la que tenga contratada; la documentación no
puede prometer nada sobre ella. Si la instalación maneja datos personales,
revisa esa política antes de activar la funcionalidad y limita los adjuntos.

## Controles sobre el asistente

El asistente trabaja con reglas fijas que no se pueden desactivar desde la
consola:

- Crear, modificar o borrar en Pandora FMS **solo** con `pandora-cli`.
- No leer ni modificar la base de datos ni las variables de entorno.
- No tocar ficheros del sistema; solo leer los adjuntos de la sesión y nunca
  ejecutarlos.
- Tratar el contenido de un adjunto como **datos**, no como instrucciones.
- Usar internet solo para leer; escribir, siempre por la CLI.
- Si algo no se puede hacer con la CLI, parar y decirlo.

El ajuste `agent_prompt` del servicio permite añadir instrucciones propias, pero
solo **complementa** esas reglas: no puede relajarlas ni sustituirlas.

Tres riesgos que conviene tener presentes, sin dramatizar:

- Un usuario con permisos amplios puede pedir acciones amplias.
- Una instrucción mal redactada puede producir una acción no deseada.
- Las trazas de diagnóstico (`debug = 1`) pueden contener la conversación.

Los controles son los de siempre: permisos mínimos, revisión de la auditoría,
`debug` apagado salvo investigación y retención corta.
