# Automatización de tareas

Una tarea programada es una instrucción que se ejecuta sin nadie delante, en su
propio entorno, con la periodicidad elegida, y que avisa del resultado. Sirve
para lo que ya se sabe hacer y debe repetirse: un informe semanal, una revisión
de agentes, un resumen de eventos.

Esta página cubre solo las tareas programadas. El uso del chat está en
[Uso del chat](8.2-uso-del-chat.md); la instalación, en
[Introducción e instalación](8.1-introduccion-e-instalacion.md); los permisos,
en [Seguridad](8.4-seguridad.md); y el registro de las ejecuciones, en
[Auditoría](8.5-auditoria.md).

## Dónde se gestionan

- **Workspace → Pandora AI**: el usuario ve y gestiona **sus** tareas. Solo
  aparece si puede usar Pandora AI.
- **Management → Settings → System Settings → Pandora AI → Scheduled tasks**: el
  administrador ve las tareas de todos los usuarios y puede editarlas. No puede
  crear una tarea a nombre de otro usuario desde aquí.

## Crear una tarea

El formulario tiene tres pestañas.

![Pestaña General de una tarea programada: nombre, modelo, instrucción y activación](../../assets/img/parte-08/ai-scheduled-task-general.png){ .captura }

**General**:

| Campo | Qué hace |
|---|---|
| **Name** | Nombre de la tarea; se usa en la lista y en las notificaciones |
| **Model** | Modelo de la ejecución; si se deja vacío, se usa el de por defecto |
| **Prompt** | La instrucción completa. Es lo único que guía al asistente: cuanto más concreta, mejor |
| **Enabled** | Activa o desactiva la tarea sin borrarla |

![Pestaña Schedule con la frecuencia y la próxima ejecución](../../assets/img/parte-08/ai-scheduled-task-schedule.png){ .captura }

**Schedule**:

| Campo | Qué hace |
|---|---|
| **Frequency** | `Hourly`, `Daily`, `Weekly`, `Monthly` o `Yearly` |
| **Next execution** | Fecha y hora de la primera ejecución; a partir de ahí se calcula la siguiente |

![Pestaña Notifications con el aviso de éxito y el de error](../../assets/img/parte-08/ai-scheduled-task-notifications.png){ .captura }

**Notifications**:

| Campo | Valores | Qué hace |
|---|---|---|
| **Notify on success** | `Never`, `Only if the user asks in the prompt`, `Always` | Avisa cuando la tarea termina bien |
| **Notify on error** | Los mismos | Avisa cuando la tarea falla |

!!! note "Sobre «Only if the user asks in the prompt»"
    En esta versión solo el valor **Always** genera notificación. Si eliges
    «Only if the user asks in the prompt», la tarea se ejecuta pero no avisa.

## Notificaciones

Las notificaciones se envían por la fuente **Pandora AI** y usan los canales que
el usuario tenga configurados en **User notifications** (consola y correo). Si no
tiene ninguno activo, no se envía nada.

El aviso incluye el nombre de la tarea y el resultado, con un enlace a la lista
de tareas. Los fallos también quedan en la auditoría del sistema.

## Ejecución

Las tareas las lanza el **cron de la consola**. Si el cron no está activo, las
tareas no se ejecutan aunque estén habilitadas y su hora haya llegado.

Cada tarea se ejecuta en su propio entorno y el número simultáneo está limitado
por `scheduled_max_containers` (cuatro por defecto). Un usuario no ejecuta dos
tareas a la vez: la segunda espera a la siguiente pasada.

La ejecución es **no interactiva**:

- No puede preguntar ni usar formularios.
- Si falta un dato, un permiso o una acción, termina con un error claro.
- La respuesta se entrega en HTML, no en Markdown, porque se envía por correo y
  por la consola.

Si el usuario perdió el permiso o Pandora AI está desactivada, la tarea falla con
un error explícito. No se reintenta en bucle.

Cada ejecución deja una **sesión programada**, que se puede abrir desde la barra
lateral del chat con `/scheduled_sessions`. El historial de la tarea no se borra
al borrar la tarea: la conversación queda en la auditoría.

## La lista

![Lista de tareas programadas con la última ejecución, la próxima y el estado](../../assets/img/parte-08/ai-scheduled-tasks-list.png){ .captura }

| Columna | Qué muestra |
|---|---|
| **Name** | Nombre de la tarea |
| **User** | Propietario de la tarea; solo aparece en la vista de administración |
| **Last run** | Cuándo se ejecutó por última vez |
| **Next run** | Cuándo toca la siguiente |
| **Status** | `Never run`, `Running`, `Success` o `Error` |
| **Enabled** | Si está activa |
| **A.** | Ejecutar ahora, editar, borrar y habilitar o deshabilitar |

**Run now** encola la tarea para la siguiente pasada. Borrar la tarea no borra la
conversación auditada.

## Límites y buenas prácticas

- **Instrucciones concretas**: qué consultar, qué hacer si falta un dato y cómo
  debe ser la respuesta. Las tareas programadas no pueden preguntar.
- **Coste**: cada ejecución consume tokens; ajusta la frecuencia y el modelo, y
  revisa el consumo en [Auditoría](8.5-auditoria.md).
- **Datos sensibles**: no pongas credenciales ni datos personales en la
  instrucción; el prompt se audita.
- **Acciones destructivas**: la tarea ejecuta con los permisos de su propietario.
  Revisa la instrucción y usa cuentas con los permisos mínimos.
- **Chat o tarea**: el chat para explorar y decidir; la tarea para lo que ya se
  sabe hacer y debe repetirse.
- **Cuando algo falla**: mira el estado de la tarea, el último error y la
  auditoría; después, el log del servicio.
