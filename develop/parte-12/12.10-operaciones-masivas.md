# Operaciones masivas

Desplegar agentes, cambiar configuraciones y hacer limpiezas en lote, sin ir uno
por uno.

Son operaciones potentes, así que **haz una copia de seguridad antes de la
primera**.

## Desplegar agentes de forma masiva

Pandora FMS lo hace desde el **centro de despliegues del Discovery**, y para
usarlo hacen falta dos cosas preparadas:

1. **Un repositorio de agentes**: en **Configuración → Repositorio de EndPoints**
   (en inglés **Configuration → EndPoints repository**) se suben los
   instaladores, uno por sistema operativo.
2. **El almacén de credenciales**: en **Configuración → Almacén de credenciales**
   (en inglés **Configuration → Credential store**) se guardan los usuarios y
   contraseñas de las máquinas destino. Es el mismo almacén que usa Discovery.

Con eso, el despliegue recorre las máquinas, instala el agente de su sistema y lo
deja reportando. Es la diferencia entre preparar cien máquinas a mano y revisar el
resultado de cien instalaciones.

## Actualizar la configuración de todos los agentes

Hay dos casos y se resuelven de forma distinta:

- **Módulos, plugins y alertas**: se hace con **políticas**. Se aplican a los
  agentes del mismo sistema operativo y los módulos se escriben en su
  configuración sin tocarlos uno a uno.
- **Parámetros especiales del fichero del agente**: aquí hay que ir al servidor.
  Conviene **hacer copia primero** de dos directorios:
  `/var/spool/pandora/data_in/conf` (donde el servidor guarda la configuración de
  cada agente) y `/var/spool/pandora/data_in/md5` (las sumas de control). Con el
  respaldo hecho, se aplica el cambio masivo y se deja que los agentes lo
  recojan.

## Borrar los agentes que nunca han reportado

Se pueden localizar los candidatos por base de datos: son los agentes cuyos
módulos están **todos sin inicializar**. Primero ejecuta una consulta de solo
lectura para identificarlos. La base usa InnoDB y sus tablas están relacionadas:
no borres filas directamente de `tagente`.

```sql
SELECT id_agente, nombre, notinit_count, total_count
FROM tagente
WHERE notinit_count = total_count;
```

Esa condición cubre los dos casos típicos: el agente al que no se le creó ningún
módulo y el que los tiene todos en «no inicializado». Revisa la lista y elimina
los agentes desde las operaciones de agentes en la consola, para que el producto
limpie también las tablas relacionadas.

## Cambiar la IP de muchos módulos a la vez

Si un dispositivo cambia de dirección y lo monitorizan cientos de módulos, no se
tocan uno a uno. Se actualiza desde **Admin tools → DB interface** (*Herramientas
de administración → Interfaz de base de datos*):

```sql
UPDATE tagente_modulo SET ip_target = '10.0.0.1' WHERE ip_target = '10.0.0.2';
```

La dirección nueva va en `ip_target` y la antigua en el `WHERE`. Conviene
ejecutar primero un `SELECT` con el mismo `WHERE` para ver cuántos módulos se van
a tocar. Haz una copia de la base antes de ejecutar el `UPDATE`.

## Limpiar el `data_in` cuando se ha llenado de XML

Si el directorio acumula miles de ficheros, se procesan sin perder datos. Se
mueven los XML a un directorio temporal y se devuelven **por lotes**:

```bash
mkdir -p /tmp/xml
mv /var/spool/pandora/data_in/*data /tmp/xml
ls -rt /tmp/xml | grep data | head -20 | xargs -i% mv /tmp/xml/% /var/spool/pandora/data_in
```

El último comando devuelve 20 cada vez: se repite hasta vaciar el temporal,
dejando que el servidor los procese entre tanda y tanda. No borres los XML si
pueden contener datos que necesitas recuperar.

## Eliminar un agente de un servidor satélite

Un agente creado por un servidor satélite **no desaparece borrándolo solo en la
consola**: el satélite lo vuelve a crear. Hay que quitarlo en el origen:

1. Bórralo del fichero de hosts del satélite (por defecto
   `/etc/pandora/satellite_hosts.txt`, o el que indique su configuración en
   `host_file`).
2. Borra el fichero de configuración de ese agente en el directorio del satélite
   (por defecto `/etc/pandora/conf`, o el que tenga configurado en
   `agent_conf_dir`).

Después, en la consola, elimina el agente.

## Subir ficheros más grandes desde la consola

Cuando la consola rechaza un fichero (por ejemplo, al añadirlo a una colección),
hay dos límites que subir:

- **PHP**: el valor `upload_max_filesize` (y `post_max_size`) en `php.ini`, y
  reiniciar el servicio web.
- **La consola**: el ajuste **Collection size (Bytes)** en **Configuración →
  General** (token `collection_max_size`). Viene con un millón de bytes por
  defecto.

Si solo se cambia uno, el otro sigue cortando.
