# Consola web y licencias

Entrar en la consola y tenerla en condiciones: acceso, ajustes de seguridad y la licencia que habilita la plataforma.

La Consola web es la puerta de entrada a la plataforma. Aquí se reúnen los
problemas de acceso, visualización, seguridad y licencias.

## He perdido la contraseña de administrador

La consola no trae un «recuperar contraseña» por correo para el administrador,
así que se resuelve desde el servidor, con la herramienta de gestión:

```bash
/usr/bin/pandora_manage /etc/pandora/pandora_server.conf \
    --create_user admin_temporal CAMBIA_ESTA_CLAVE 1
```

Eso crea un usuario administrador temporal. Se entra con él, se cambia la
contraseña del usuario original y **se borra el usuario temporal**, para no dejar
una puerta abierta.

!!! warning "No dejes el usuario temporal"
    La ficha original proponía crearlo con la contraseña `none`. No lo hagas: pon
    una contraseña real y elimina la cuenta en cuanto termines.

## Cambiar la contraseña de un usuario desde la línea de comandos

Con el mismo `pandora_manage`, sin crear cuentas nuevas:

```bash
/usr/bin/pandora_manage /etc/pandora/pandora_server.conf \
    --update_user ID_USUARIO password CLAVE_NUEVA
```

El comando también sirve para otros campos del usuario: correo, teléfono, idioma,
tema (`id_skin`), nombre completo y si es administrador.

## La consola aparece en blanco o con errores de MySQL

Cuatro causas, por orden de frecuencia:

- **Faltan paquetes o extensiones PHP.** La consola necesita extensiones como
  `php-mysqlnd`, `php-gd`, `php-mbstring`, `php-xml`, `php-zip`, `php-ldap` y
  `php-snmp`. Si falta alguna, la página puede quedar en blanco o devolver un
  error 500. Se instalan y se reinicia Apache o PHP-FPM.
- **Una actualización o instalación a medias.** Algún fichero de la consola se
  quedó corrupto. Se reinstalan los paquetes de la consola en **la misma versión**
  que ya estaba instalada.
- **Problemas de conexión con MySQL.** El motor no está arrancado, no escucha en
  el host o puerto configurado, las credenciales de `include/config.php` no son
  válidas o el usuario no tiene permisos sobre la base. Se comprueba la conexión
  a mano con `mysql` y se revisa el error en el registro de PHP o Apache.
- **Faltan MRs del esquema.** Si además hay errores de MySQL, lo más probable es
  que la base de datos se quedó en un MR anterior. Se aplican los que falten.

Si con eso no se arregla, se reinstala la consola desde cero conservando
`include/config.php`, el contenido de `attachment` y las imágenes personalizadas.

## No puedo acceder y el disco está lleno

Cuando el disco se llena, MySQL no puede escribir, la consola no abre y los datos
nuevos dejan de procesarse. Se busca qué se lo ha comido:

- **Copias de seguridad** que se acumulan y nadie borra. Es lo primero que hay que
  mirar.
- **Registros** que no se están purgando.
- **Ficheros con un tamaño anómalo.** Se mueven o se borran, con cuidado.
- **La base de datos.** Los módulos de texto (`generic_data_string`) son los que
  más engordan: guardan cadenas largas que se repiten en cada intervalo.

## Las gráficas no muestran texto

Si la gráfica sale sin ejes ni valores, falta la fuente con la que se dibuja el
texto. La ruta se declara en la configuración de la consola, en el ajuste
**`fontpath`**. Hay que comprobar que la fuente existe en esa ruta y que el
usuario del servidor web puede leerla.

!!! note "Aviso"
    Las fichas antiguas hablaban de la variable `$config_homedir`. **Ese ajuste ya
    no existe**: si no aparecen textos en las gráficas, mira `fontpath`.

## La consola responde despacio

Hay dos sitios donde mirar, y se distinguen con el registro y con el consumo:

1. **El servidor web.** Si los procesos de Apache consumen el 100% de CPU o de
   memoria, el problema está ahí: faltan recursos, o `php.ini` se queda corto de
   memoria (`memory_limit`). Los errores de límite de PHP aparecen en el registro
   de Apache o en `pandora_console.log`.
2. **MySQL.** Si el servidor web va sobrado y la consola sigue lenta, el cuello de
   botella está en la base de datos. Ver
   [Servidor y base de datos](12.2-servidor-y-base-de-datos.md).

## Perdí el generador de códigos de la doble autenticación

La doble autenticación (2FA) se desactiva para un usuario desde el servidor:

```bash
/usr/bin/pandora_manage /etc/pandora/pandora_server.conf \
    --disable_double_auth '<usuario>'
```

Sirve tanto si eres tú quien ha perdido el generador como si eres el
administrador y te lo pide otra persona. Si lo que quieres es apagarla para toda
la consola, existe el ajuste **`double_auth_enabled`** en la tabla `tconfig`, pero
para una sola cuenta el comando es más limpio.

## Temas de la consola y copia de estilos

Los temas se cambian desde la **Consola web**, en las preferencias del usuario.
Antes de tocar iconos o estilos propios conviene hacer copia: el producto trae
**`styles_backup.sh`** en la carpeta de utilidades del servidor
(`pandora_server/util/`), que exporta los iconos y el CSS a
`pandora_console/styles_backup` en dos archivos comprimidos con fecha y hora.

## Poner la consola en HTTPS

La consola se sirve por HTTPS con un certificado del servidor web:

1. Ten preparados el certificado y su clave (`.crt` y `.key`). **No uses
   autofirmados**: ni son de fiar para el usuario ni evitan los avisos.
2. Configura Apache para escuchar en el 443 y apuntar a esos ficheros
   (`SSLCertificateFile` y `SSLCertificateKeyFile`).
3. Reinicia el servicio web.
4. Si quieres que **nadie** entre por HTTP, activa en **Administración →
   Configuración → General** el ajuste que fuerza el uso de HTTPS.

## No funciona la autenticación AD o LDAP

Pandora FMS admite las dos, y comparten casi toda la configuración. Si los
usuarios no entran, se revisa:

- **Servidor y puerto** del LDAP o del dominio.
- **La función de búsqueda**: *Local Command* usa el comando `ldapsearch` (tiene
  que estar instalado en el servidor de Pandora FMS); *PHP function* usa el motor
  propio de la consola. Lo normal es *PHP function*, y *Local Command* solo tiene
  sentido en entornos muy grandes.
- **El dominio base y las unidades organizativas / grupos**: aquí se equivoca
  todo el mundo. La ruta de búsqueda tiene que apuntar exactamente a donde están
  los usuarios.

## Zona horaria de la consola

La consola usa la zona del sistema; si no está definida, tira por la europea. Si
los datos te aparecen con otra hora, ajusta la **zona horaria en Administración →
Configuración → General** (ajuste `timezone`).

Las fichas antiguas proponían editar `include/config_process.php` y forzar
`date_default_timezone_set`. Sigue funcionando, pero es el plan B: mejor dejarlo
coherente con el sistema operativo.

## Notificaciones: gestionarlas y borrarlas

- **Borrarlas**: desde **Área de trabajo → Mensajes → Lista de mensajes**, donde
  se pueden eliminar todas.
- **Configurarlas**: en **Configuración → Configuración → Notificaciones** se
  activan o desactivan por tipo y se asignan a usuarios o grupos. Cada usuario
  tiene además su propia configuración de qué quiere recibir.

## Dónde se ven los fallos de PHP

Hay dos sitios, y conviene mirar los dos:

- **El registro del servidor web**: `error_log`, o `ssl_error_log` si la consola
  va por HTTPS. Comprueba en `/etc/php.ini` que el registro de errores está
  activo y que la ruta está definida.
- **El registro de la propia consola**: hay que habilitarlo en **Administración →
  Configuración → General → Habilitar log de consola**, y se escribe en
  `pandora_console/log/console.log`.

Para depurar temporalmente, se puede subir el reporte de PHP desde
`include/config.php` de la consola:

```php
error_reporting(E_ALL);
```

Cuando termines, vuelve a bajarlo: en producción no conviene dejar ese nivel.

## Prioridad de los campos personalizados en las alertas

Cuando el mismo campo (`_field1_` a `_field20_`) está definido en varios
sitios, el motor de alertas aplica este orden de precedencia:

| Tipo de alerta | Orden de precedencia |
|---|---|
| Alertas convencionales | acción > plantilla de alerta |
| Alertas SNMP | configuración de la alerta SNMP > acción > valores por defecto del comando |

En las alertas convencionales, lo que se defina en la **acción** sobreescribe a
lo que venga en la **plantilla**. En las alertas SNMP, la configuración de la
**alerta SNMP** tiene la máxima prioridad; si está vacía, se toma el valor de la
**acción**, y como último recurso los valores por defecto del **comando**.

## Módulos WUX que no se inicializan

Los módulos **WUX** (Web User Experience) ejecutan transacciones web en un
cliente web real mediante Selenium. Las comprobaciones periódicas las realiza el
servidor interno **WUX Server** de Pandora FMS. Si los módulos quedan sin
inicializar, se comprueba:

1. **El servidor WUX está activado en el servidor.** En
   `/etc/pandora/pandora_server.conf`, el token **`wuxserver`** debe estar a
   **`1`** (por defecto viene desactivado en `0`).
2. **Conectividad con Selenium.** El servidor de Pandora FMS debe alcanzar el
   host y puerto configurados en `wux_host` y `wux_port` (por defecto
   `localhost:4444`).
3. **El registro del servidor de Pandora FMS** (`pandora_server.log` y
   `pandora_server.error`) y el **registro del propio Selenium**, donde se
   detallan los fallos de sesión o de la transacción.

## «Consola y servidor en versión distinta»

Ese aviso aparece cuando la consola y el servidor no están en la misma versión.
Aunque la plataforma funcione, no es una situación sana: hay que alinearlas.

- La versión de la consola se ve en el **pie de página** de la consola.
- La del servidor, en **Servers → Manage servers** (*Servidores → Gestionar servidores*).

Lo correcto es actualizar **las dos** a la misma versión; el orden está en
[Actualizaciones](../parte-1/1.4-actualizaciones.md).

## Que el servidor se levante solo tras una caída

En las distribuciones modernas con systemd, el propio servicio
**`pandora_server.service`** incluye directiva de reinicio automático
(`Restart=always`) a través del supervisor del demonio. Para asegurar que el
servicio se inicia con el sistema operativo y se recupera si el proceso cae:

```bash
systemctl enable --now pandora_server
systemctl status pandora_server
```

En despliegues con alta disponibilidad multihost (clúster activo/pasivo),
Pandora FMS cuenta además con la herramienta de clúster **`pandora_ha`**, que
vigila el latido en base de datos de los nodos y gestiona la conmutación según el
runbook de alta disponibilidad.

## Qué licencia tengo

El tipo de licencia y su fecha de caducidad se consultan en la propia consola, en
**Management → Setup → License** (*Configuración → Licencia*). Esa pantalla es la
que manda: muestra el límite contratado, lo que hay en uso y qué modalidad está
activa.

Los modelos posibles (perpetua o suscripción, por agentes o por módulos) y qué
piezas necesitan licencia aparte están explicados en
[Licenciamiento](../parte-1/1.5-licenciamiento.md). Aquí no se habla de precios ni
de tramos comerciales.

## La licencia ha caducado: cómo se renueva

El proceso es el mismo que el de la primera instalación, con la clave nueva:

1. El proveedor envía la **AuthKey** del nuevo periodo.
2. En la consola, entra en **Management → Setup → License** y elige **Request new
   license**.
3. Introduce la **AuthKey** en el campo de clave de autenticación y pulsa la
   **validación en línea**.

La consola genera la licencia, la valida contra el servidor y la deja instalada.
Si la instalación no tiene salida a internet, el mismo diálogo permite activarla
a mano; el procedimiento completo está en
[Licenciamiento](../parte-1/1.5-licenciamiento.md).

## He actualizado y quiero volver atrás

**No hay marcha atrás soportada.** Una actualización no se deshace volviendo a
instalar los paquetes antiguos: si algo salió mal, lo que se hace es **restaurar
la copia de seguridad o el snapshot de la máquina**, que es justo para lo que se
pide antes de empezar (ver
[Actualizaciones](../parte-1/1.4-actualizaciones.md)).

Por eso la recomendación de siempre: snapshot antes de tocar, y la actualización
en una ventana con margen para volver al punto de partida.

!!! warning "Aviso"
    Reinstalar paquetes antiguos «por encima» deja la instalación en un estado
    que no está soportado. Si hay que volver atrás, restaura la copia o el
    snapshot completo, incluidos la base de datos y los ficheros de la consola.
