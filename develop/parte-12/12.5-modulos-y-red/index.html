    Módulos y red¶

    Los chequeos y el protocolo de red: módulos que no arrancan o no responden, ICMP, WMI, SNMP y traps.

    Un módulo guarda una sola métrica y su valor se interpreta por umbrales. Casi todos los problemas de esta sección son de configuración del propio módulo o de una comprobación que no llega a ejecutarse bien.

    No puedo cambiar el tipo de un módulo¶

    Es el comportamiento del producto: una vez creado, el tipo de un módulo no se puede cambiar. Si te has equivocado de tipo, hay que borrar el módulo y crearlo de nuevo, y con él se pierde su histórico. Por eso conviene acertar a la primera o probar la definición en un agente de pruebas antes de llevarla a producción.

    ¿Se pueden usar módulos locales en plantillas?¶

    No. Las plantillas de módulos son para componentes de red. Para aplicar módulos locales a muchos agentes a la vez están las políticas, que además llevan alertas y también admiten módulos de red.

    Los módulos de Ping (ICMP) no funcionan¶

    Se separa el problema de red del de procesamiento:

    Red. El equipo está apagado o sin conexión; hay un corte en el segmento; o un elemento intermedio (cortafuegos, proxy) bloquea el ICMP. Desde el servidor, ping o fping al destino dice si el problema es de red.

    Procesamiento. Si el intervalo del módulo es muy bajo, las ejecuciones se encolan y el módulo no llega a tiempo. También arrastra si el servidor está encolado en general. Mide antes de bajar intervalos: desde la versión 784 el ICMP admite hasta 15 segundos, pero eso tiene un coste en máquinas grandes.

    Un módulo ICMP está en crítico aunque hay conectividad¶

    Pandora FMS no usa el ping clásico: usa fping, que es más eficiente. El token icmp_checks del servidor decide cuántos pings lanza por módulo y viene a 1 por defecto, así que solo cuenta el primero. Si la red pierde el primer paquete de vez en cuando, el módulo se pone en crítico sin motivo.

    Súbelo a un valor mayor para que el resultado no dependa de un único intento.

    Los módulos WMI no funcionan¶

    WMI hay que habilitarlo en el equipo Windows, no solo en Pandora FMS:

    1. Abre Administración de equipos → Servicios y aplicaciones → Control WMI.
    2. En las propiedades del namespace (se puede empezar por root), en la pestaña de Seguridad, concede el permiso de Llamada remota (Remote Enable) a la cuenta con la que consultas.
    3. Permite el paso por el cortafuegos de Windows.

    En Pandora FMS, el cliente WMI por defecto es pandorawmic, configurable con el token wmi_client del servidor. Necesita credenciales de un usuario con permisos en el equipo consultado.

    WMI no funciona desde un servidor satélite¶

    Cuando el servidor satélite corre como usuario local en Windows, algunas consultas WMI remotas fallan por seguridad. La solución es ejecutar el servicio del satélite con una cuenta de administrador del dominio o del equipo. Se cambia en las propiedades del servicio, o con sc.exe config, y se reinicia.

    El chequeo web está en crítico y la web funciona¶

    Tres causas habituales:

    • El servidor de Pandora FMS no alcanza la URL: DNS, proxy o cortafuegos.
    • El contenido ha cambiado y ya no coincide con la cadena que busca el módulo (check_string). Un rediseño de la página rompe el módulo aunque el servicio esté perfecto.
    • La conexión se corta a mitad (proxy con autenticación, por ejemplo).

    Para ver qué pasa exactamente, se añade la depuración al propio módulo:

    task_begin
get https://www.example.com
cookie 1
resource 1
check_string <cadena_que_debe_aparecer>
debug /tmp/request.log
task_end

    Al ejecutarse de nuevo, el fichero indica el error con detalle.

    Las interfaces SNMP están activas pero la consola las muestra caídas¶

    Antes de tocar el módulo, confirma que el dato llega:

    • Consulta el estado desde el servidor con snmpget o con el explorador SNMP de la consola. Si ahí sale activa y en el módulo no, el problema está en el módulo.
    • Revisa la carga del servidor. Con pocos recursos, los chequeos SNMP se pierden y el estado que ves es el último que llegó, no el real.

    La macro _modulegraph_nh_ no funciona¶

    Esa macro inserta la gráfica del módulo en un correo de alerta, y para dibujarla la consola se pide la imagen a sí misma. Si sale rota, falta el acceso a la API. Hay que definir la contraseña de la API en la consola (Administración → Configuración → General) y descomentar console_api_pass en la configuración del servidor, con la misma contraseña.

    WMIC y PandoraWMIC¶

    WMIC es la interfaz de línea de comandos de WMI que trae Windows. Pandora FMS la usa solo para consultar (por ejemplo, PROCESS GET NAME devuelve los procesos en ejecución), nunca para cambiar nada en el equipo.

    PandoraWMIC es el cliente que usa el servidor por defecto (wmi_client pandorawmic), pensado para esas consultas de monitorización.

    Un plugin de servidor no se inicializa¶

    Los plugins de servidor se ejecutan en el propio servidor de Pandora FMS, tal como se configuran en Servidores → Plugins. Para depurarlo, se lanza a mano en la terminal con el mismo usuario con el que corre el servidor (por defecto root) y los mismos parámetros.

    La salida tiene que ser un solo dato, y del tipo que declaraste al crear el módulo (numérico o alfanumérico). Si el tipo no coincide, el módulo no arranca (la excepción es el tipo incremental, que muestra la salida tal cual). Además, el comando debe terminar sin errores: si el errorlevel no es 0, el servidor descarta el resultado.

    El agente envía datos pero no se ven en la consola¶

    Suele ser la hora. Si el reloj del equipo donde corre el agente está desfasado, las marcas temporales aparecen desplazadas respecto al servidor y los datos pueden ser difíciles de localizar en la vista o en las gráficas.

    Comprueba el desfase entre las dos máquinas y sincronízalas por NTP. Después, revisa el intervalo siguiente y consulta el registro del servidor si los datos siguen sin aparecer.

    Añadir una MIB a Pandora FMS¶

    Las MIB se cargan desde la propia Consola web. En el menú de monitorización de SNMP está la sección de carga de MIB (Monitoring → SNMP → MIB uploader). Desde ahí se suben todos los ficheros que hagan falta, uno detrás de otro. La MIB es un fichero de texto. Se puede abrir con cualquier editor para comprobar que es la del fabricante y el modelo correctos.

    Tras cargar la MIB, la consola sigue sin reconocer las OID¶

    Cargar la MIB en la consola no basta: el sistema operativo tiene que saber dónde está. Se comprueba qué directorios está mirando net-snmp:

    net-snmp-config --default-mibdirs
snmpget -Dparse-mibs 2>&1 | grep directory

    Si el directorio donde has dejado la MIB no aparece en esa lista, muévela a uno de los que sí aparecen. O añade el tuyo a la configuración de net-snmp.

    El asistente SNMP no encuentra las OID del dispositivo¶

    Antes de pelear con el asistente, pregunta al dispositivo directamente desde el servidor. Con snmpwalk se recorre lo que expone y con snmpget se pide una OID concreta:

    snmpwalk -v1 -c 'COMUNIDAD' 192.0.2.10
snmpget  -v1 -c 'COMUNIDAD' 192.0.2.10 1.3.6.1.2.1.43.5.1.1.1.1.0

    Sustituye COMUNIDAD y 192.0.2.10 por los valores de tu dispositivo.

    Si el dispositivo responde a estos comandos, el problema es de la MIB o del asistente. Si no responde, es de red o de la comunidad SNMP. Y da igual lo que hagas en la consola.

    No llegan los traps¶

    El primer sitio donde mirar es el registro de traps de Pandora FMS:

    tail -f /var/log/pandora/pandora_snmptrap.log

    Si aparece el mensaje «No access configuration - dropping trap», el demonio de traps tiene configurado su acceso pero no autoriza esa comunidad. Se arregla añadiendo la comunidad al fichero de configuración de snmptrapd y reiniciando:

    echo "authCommunity log <comunidad_configurada>" >> /etc/snmp/snmptrapd.conf
systemctl restart pandora_server

    La comunidad debe coincidir con la que envía el dispositivo. No uses public en producción salvo que esa sea realmente la comunidad configurada.

    Además, el servidor de consola SNMP de Pandora FMS viene desactivado por defecto: comprueba que en /etc/pandora/pandora_server.conf el token snmpconsole está a 1. Un servidor interno apagado no da error, solo no hace su trabajo.

    «couldn't open udp:162»¶

    El puerto 162 lo ocupa el snmptrapd del sistema operativo, así que Pandora FMS no puede escuchar. Se para el servicio de traps del sistema y se reinicia Pandora FMS. Si vuelve a pasar tras un reinicio, se deshabilita el del sistema:

    systemctl stop snmptrapd
systemctl disable snmptrapd
systemctl restart pandora_server

    En Debian y Ubuntu solo funcionan las OID numéricas¶

    Debian y Ubuntu traen el árbol de MIB desactivado, así que su SNMP solo entiende direcciones numéricas y la consola no resuelve los nombres. Se reconfigura en dos pasos. Primero, instalar el descargador de MIBs. Después, dejar limpio el fichero de configuración de SNMP (/etc/snmp/snmp.conf, sin líneas activas).

    apt-get install snmp-mibs-downloader

    Borrar traps antiguos¶

    Si lo que quieres es una limpieza puntual, se puede hacer desde Admin Tools → DB Interface con una sentencia sobre la tabla ttrap:

    SELECT COUNT(*) FROM ttrap WHERE timestamp < '<AAAA-MM-DD 00:00:00>';
DELETE FROM ttrap WHERE timestamp < '<AAAA-MM-DD 00:00:00>';

    Sustituye la fecha por la que corresponda y revisa el resultado del SELECT antes de ejecutar el DELETE.

    Para que no vuelva a acumularse, la consola tiene el ajuste «Nº max. de días antes de borrar traps SNMP» en Administración → Configuración → Rendimiento (token trap_purge). A partir de ahí, los traps que superan esa antigüedad se pasan al histórico y luego se purgan.
