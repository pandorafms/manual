    Instalación¶

    Instalar Pandora FMS es la parte fácil del proyecto. Lo difícil es decidir sobre qué se instala, qué se deja fuera y quién se acuerda de esto dentro de dos años. Este capítulo cubre la instalación del producto, sus requisitos y las decisiones que conviene tomar antes de ejecutar el primer comando, no después.

    Qué se va a instalar¶

    El instalador en línea de Pandora FMS monta en una sola máquina el servidor, la consola web, la base de datos y, opcionalmente, un EndPoint local para monitorizar el propio servidor. Es el entorno monolito y cubre la mayoría de los casos.

    Los componentes no tienen por qué vivir juntos. La instalación individual de cada pieza se hace a posteriori para adaptar la arquitectura: base de datos en un servidor dedicado, OpenSearch aparte, uno o varios satélites para redes remotas o varios nodos coordinados desde Command Center. Aquí se explica la instalación estándar; las variantes están en la sección de personalización de la instalación automática.

    Los componentes instalables de Pandora FMS son:

    • Servidor (pandora_server), con su base de datos y el servidor Tentacle.
    • Consola web (pandora_console).
    • EndPoint (pandora_agent y agentes asociados), en el equipo a monitorizar.
    • Satellite Server, servidor autónomo para redes remotas.
    • OpenSearch, motor de almacenamiento de logs, opcional.
    • Command Center (mf_server) y Cloud Server (cloud_server), para entornos distribuidos.

    Los requisitos completos de cada componente están más abajo, en Requisitos mínimos. Léelos antes de empezar; son la diferencia entre una instalación que aguanta años y una que da el primer susto a los tres meses.

    Requisitos previos¶

    Antes de lanzar la instalación en línea:

    Requisito Detalle
    Internet Acceso a internet y a los repositorios oficiales de la distribución (RHEL / Rocky Linux / Ubuntu Server).
    curl Instalado (viene por defecto en casi todas las distribuciones).
    Usuario root (o equivalente con sudo).
    Sistema operativo RHEL, Rocky Linux y AlmaLinux 9 o 10, o Ubuntu Server 22.04 o 24.04. Más detalle en Requisitos del servidor.
    Hardware Cumplir los requisitos mínimos de hardware.
    RHEL 8 Máquina licenciada y suscrita a los repositorios estándar.

    Instalación online del servidor¶

    Si la máquina tiene internet, este es el camino recomendado. El instalador en línea monta el entorno completo del servidor en un solo paso.

    curl -SsL https://pfms.me/deploy_pandora_one | PANDORA_LTS=1 bash

    La herramienta se solicita a través de la página de Pandora FMS y funciona con RHEL, Rocky Linux, AlmaLinux y Ubuntu Server. Red Hat es la opción recomendada; el resto está soportado con las versiones que marca la tabla de sistemas operativos.

    La ejecución anterior hace una instalación completa. El instalador admite además variables de entorno para personalizarla (contraseñas de base de datos, versión de MySQL y PHP, canal LTS o Feature Release, paquetes concretos, etc.). Están todas recogidas más abajo, en Personalización de la instalación automática.

    Instalación online del EndPoint¶

    El EndPoint es el programa que vive dentro del equipo monitorizado. No es obligatorio (existe monitorización remota), pero es la única forma de obtener el máximo detalle: procesos, inventario, logs locales.

    Linux¶

    El instalador en línea funciona con distribuciones Red Hat (RHEL, Fedora, Rocky), SUSE/OpenSUSE y Debian/Ubuntu. Siempre instala desde un TAR, nunca desde un RPM, y verifica que el paquete descargado sea un EndPoint auténtico antes de configurarlo contra tu servidor.

    Instalación mínima (agente GO, versión LTS):

    export PANDORA_SERVER_IP='10.0.0.1'
curl -sSL https://pfms.me/agent-deploy | bash

    El instalador admite variables de entorno para automatizar la instalación o elegir el paquete. Están todas recogidas más abajo, en Personalización de la instalación automática.

    Arquitecturas soportadas: x86_64 con binarios. En x86, armv7l y aarch64 el script pasa automáticamente a compilación desde fuentes (PERL_SOURCES). En otras arquitecturas el proceso se detiene.

    MS Windows¶

    El EndPoint se entrega como autoinstalador .exe. Para la instalación en línea, ejecuta PowerShell como administrador:

    Invoke-WebRequest -Uri https://marketplace.pandorafms.com/pandorafms/LTS/PandoraFMS_One_Agent_Windows-lts.x86_64.exe -OutFile ${env:tmp}\pandora-agent-windows.exe; & ${env:tmp}\pandora-agent-windows.exe /S --ip [IP_DEL_SERVIDOR] --group [GRUPO] --remote_config 1

    Y arranca el servicio:

    NET START PandoraFMSAgent

    Los detalles de la instalación manual y desatendida están en Instalación offline del EndPoint.

    Instalación del satélite¶

    El Satellite Server es un servidor headless (sin interfaz web) pensado para descubrir y monitorizar redes remotas a las que no llega el servidor de Pandora FMS y donde tampoco se pueden instalar EndPoints: elementos de red por SNMP/ICMP, servidores Windows por WMI y Linux por SNMP. Ejecuta hasta 500 chequeos por segundo, no necesita conexión a la base de datos de Pandora FMS y envía los datos como XML.

    Instalación en línea¶

    Sistemas operativos soportados: EL10 (RHEL 10 / Rocky Linux 10, opción recomendada), Ubuntu Server 22.04 y Raspberry Pi OS (Debian 12+, con el paquete específico para Raspberry).

    export PANDORA_SERVER_IP='<IP o FQDN del Pandora FMS Server>'
curl -Ls https://pfms.me/satellite-ent-deploy | bash

    El instalador admite variables de entorno (canal de versión, grupo por defecto, configuración remota, instalación del agente, etc.), recogidas más abajo en Personalización de la instalación automática.

    Compatibilidad

    El Satellite Server 785 no es compatible con versiones anteriores de Pandora FMS. Instálalo junto a un entorno 785 o superior, o tendrás funciones que aparecen pero no operan.

    Instalación de OpenSearch¶

    La recolección de logs es opcional, y para activarla se necesita una instancia de OpenSearch. No se instala por defecto con el servidor: es un despliegue aparte, y la recomendación es que viva en un servidor independiente del de Pandora FMS.

    curl -SsL https://pfms.me/pandorafms-opensearch-el | bash

    El instalador crea un nodo listo para usar, con HTTPS y autenticación por contraseña, y es compatible con EL8, EL9 y Ubuntu 22.04 Server. Admite variables de entorno para el nombre del clúster y la contraseña, recogidas más abajo en Personalización de la instalación automática.

    Comprobación de que el nodo responde:

    curl -X GET https://127.0.0.1:9200 -ku 'admin:<contraseña>'

    Cambia también esta contraseña. Aplica el mismo criterio que con la base de datos: lo que está publicado no protege nada.

    Requisitos mínimos¶

    Requisitos del servidor¶

    Hardware. Los valores son mínimos, calculados suponiendo que el 80 % de los módulos guardan histórico y un muestreo medio de cinco minutos, con servidor, consola y base de datos en la misma máquina:

    Hardware Pequeño (≤ 1.000 módulos) Mediano (≤ 10.000) Grande (≤ 30.000) Extra grande (≤ 80.000)
    CPU 2 núcleos a 2 GHz 4 núcleos a 2,5 GHz 6 núcleos a 3 GHz 10 núcleos a 3 GHz
    RAM 4 GB 8 GB 16 GB 32 GB
    Almacenamiento 15K rpm o SSD ≥ 300 MB/s 15K rpm o SSD ≥ 300 MB/s SSD ≥ 300 MB/s SSD ≥ 300 MB/s
    Disco 40 / 60 GB 60 / 150 GB 120 / 250 GB 250 / 400 GB

    Si se guarda información de más de un mes, hay que desplegar una base de datos de histórico.

    Virtualización

    En entornos virtuales, asigna a la máquina un disco independiente con espacio reservado y alta velocidad. Meter la base de datos en un volumen compartido y fino es la forma más fiable de conseguir un cuello de botella que nadie localizará hasta dentro de semanas.

    Por encima de 80.000 métricas, un solo nodo deja de tener sentido: toca monitorización distribuida con múltiples nodos (Command Center).

    Software.

    Software Requisitos
    Sistema operativo RHEL 10, Rocky Linux 10, RHEL 9 (recomendado), Rocky Linux 9 (recomendado), Ubuntu Server 22.04 y 24.04.
    Consola PHP 8.4 desde la versión 785; PHP 8.2 de la 776 a la 784; PHP 8 de la 760 a la 775; PHP 7.4 de la 759 a la 767; PHP 7.2 de la 729 a la 758.
    Base de datos Percona Server for MySQL 8 (recomendado, sobre todo por encima de 4.000 agentes), MySQL 8 o MySQL 8.4 desde la versión 785.
    Navegadores Chrome, Firefox, Opera y Edge. Para gráficas interactivas y mapas de red, Firefox o Chrome.
    systemd Necesario desde la versión 779. Viene instalado y habilitado en los SO soportados.

    EL10 y Ubuntu

    EL10 denota el conjunto de sistemas recomendados: Rocky Linux 10, AlmaLinux 10 y Red Hat 10. En Ubuntu Server no se soporta la instalación offline, así que no lo elijas para un servidor sin conexión. Para Command Center se recomienda evitar Ubuntu.

    Cada versión LTS de Pandora FMS soporta unas versiones concretas de sistema operativo; consúltese la política de soporte de versiones de OS antes de decidir.

    Permisos.

    Requisito Detalle
    Usuario de instalación El servidor se instala como root. En la instalación se crea un usuario pandora asignado al grupo root; después puede cambiarse, teniendo en cuenta que habrá que reconfigurar el servidor Tentacle. También existe la instalación con usuario no privilegiado, con procedimiento aparte.
    Consola Apache necesita permisos de lectura y ejecución sobre los ficheros de la consola; config.php debe tener permisos 600.
    Servidor Permisos de escritura en /var/spool/pandora/.

    Requisitos del EndPoint¶

    El EndPoint puede ejecutarse en cualquier equipo con el sistema operativo mínimo requerido:

    Componente Sistema operativo
    Pandora EndPoint 4.0 o posterior RHEL 10 / Rocky Linux 10; RHEL 6.x, 8 y 9; Fedora 34; CentOS 6.x, 7 y 8; AlmaLinux; SLES 11 SP1 o posterior; OpenSUSE 11.x o posterior; Debian 5.x o posterior; Ubuntu Server o Desktop 11 o posterior; Linux Mint; Elementary OS; Manjaro; HPUX B.11.11 o posterior con Perl 5.8; AIX 4.3.3 o posterior con Perl 5.8; AIX 7.1 y 7.2; BSD (NetBSD, OpenBSD, FreeBSD) con Perl 5.8; MacOS X 10.6 o posterior; Solaris 8 o posterior con Perl 5.8; Windows NT4, XP, 2000, 2003, 2008, 7, 8, 10, 11, 2012, Server 2016 y Server 2019.
    Pandora Android EndPoint 2.0 o posterior Android 6 o posterior.
    Pandora Embedded EndPoint 4.0 o posterior Dispositivos embedded; requiere compilación.

    En los sistemas tipo *nix se necesita systemd instalado e iniciado. En entornos UNIX, además:

    Requisito Detalle
    Perl 5.8 o posterior.
    Dependencias perl-YAML-Tiny-1.73-2, perl-Sys-Syslog y unzip.
    logrotate Configurado para el agente (bloque siguiente). 
    cat> /etc/logrotate.d/pandora_agent <<EO_LRA
/var/log/pandora/pandora_agent.log {
        su root apache
        weekly
        missingok
        size 300000
        rotate 3
        maxage 90
        compress
        notifempty
        copytruncate
}
EO_LRA
chmod 0644 /etc/logrotate.d/pandora_agent

    En Linux, el EndPoint se ejecuta como root para tener todas las funcionalidades; en Windows, con permisos de administrador.

    Requisitos del satélite¶

    Satélite Detalles
    Hardware (Windows) x64; mínimo 2 núcleos a 2 GHz (recomendado 4); mínimo 6 GB de RAM (recomendado 8); disco mínimo 5 GB (recomendado 10).
    Hardware (Linux) x64; mínimo 2 núcleos a 2 GHz (recomendado 4); mínimo 4 GB de RAM (recomendado 6); disco mínimo 5 GB (recomendado 10).
    Sistemas operativos Linux 64 bits; MS Windows 64 bits.
    Dependencias fping, nmap, perl, pandorawmic (versión NG 762 o posterior) y libnsl; snmp para SNMP.

    En Rocky Linux 8 o posterior hay que configurar antes el repositorio EPEL. En Windows, dependiendo de la versión del sistema, hay que instalar Microsoft Visual C++ Redistributable.

    Requisitos de OpenSearch¶

    Requisito Detalle
    Sistema operativo Rocky Linux 8 / RHEL 8 / Ubuntu 22.04 (recomendados).
    RAM Mínimo 4 GB (dev/testing); recomendado 8 GB por instancia. Hay que estimar según el volumen de datos.
    CPU Mínimo 4 núcleos.
    SWAP Desactivado en el nodo o nodos de OpenSearch.
    Almacenamiento 50 GB de disco de sistema y 100 GB para OpenSearch.
    Conectividad Desde el servidor y la consola de Pandora FMS a la API de OpenSearch (9200/TCP) y entre nodos de clúster (9300/TCP).

    Un solo nodo con estas características almacena hasta 1 GB de datos diarios durante 30 días. Para más resiliencia y capacidad, se configura un clúster (mínimo 3 nodos para garantizar la integridad de los datos) y se reparte la carga con un balanceador tipo Keepalived.

    Requisitos de SIEM¶

    Requisito Detalle
    OpenSearch Base de datos OpenSearch en una instancia dedicada.
    Recolección de logs Activada.
    Recursos del nodo Mínimo 4 núcleos, 8 GB de RAM y 100 GB de disco SSD.
    Instancia SIEM Recomendado un servidor dedicado para siemserver y siemevents.
    Licencia Con la funcionalidad SIEM habilitada.

    Cumplidos los requisitos, el SIEM se activa desde la consola en Management → Settings → System Settings → SIEM → Activate SIEM. Al guardar se crean las plantillas de normalización en OpenSearch y se habilitan siemserver y siemevents en los servidores correspondientes.

    Servidor y consola¶

    Valores para el instalador online¶

    La ejecución básica instala el entorno completo. Estas variables de entorno la personalizan (valores de RHEL y Rocky Linux):

    Variable Función Por defecto
    TZ Zona horaria de la máquina Europe/Madrid
    DBHOST Host de la base de datos 127.0.0.1
    DBNAME Nombre de la base a crear pandora
    DBUSER Usuario de la base pandora
    DBPASS Contraseña del usuario Pandor4!
    DBPORT Puerto de la base 3306
    DBROOTPASS Contraseña de root de la base Pandor4!
    SKIP_PRECHECK Saltar el chequeo de instalación previa 0
    SKIP_DATABASE_INSTALL No instalar la base (usar una externa) 0
    SKIP_KERNEL_OPTIMIZATIONS Saltar la optimización de kernel 0
    MYVER Versión de MySQL (80 o 84) 80
    PHPVER Versión de PHP (82 o 84) 84
    PANDORA_SERVER_PACKAGE URL del RPM del servidor última disponible
    PANDORA_CONSOLE_PACKAGE URL del RPM de la consola última disponible
    PANDORA_AGENT_PACKAGE URL del RPM del agente última disponible
    PANDORA_BETA Instalar beta (1) 0
    PANDORA_LTS Instalar rama LTS en lugar de Feature Release 1

    En Ubuntu Server la lista es parecida: no incluye las variables de paquete del servidor, la consola y el agente, y añade POOL_SIZE para fijar la memoria de MySQL (por defecto se calcula de forma automática).

    Ejemplo en EL10 con valores explícitos:

    env TZ='Europe/Madrid' \
    DBHOST='127.0.0.1' \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='CambieEstaClave' \
    DBPORT='3306' \
    DBROOTPASS='CambieEstaClaveRoot' \
    MYVER=84 \
    PHPVER=84 \
    SKIP_PRECHECK=0 \
    SKIP_DATABASE_INSTALL=0 \
    SKIP_KERNEL_OPTIMIZATIONS=0 \

    Cambia las contraseñas por defecto

    Pandor4! está escrita en la documentación pública. Es la primera que prueba cualquiera que sepa por dónde entra. Dejarla puesta no es un descuido, es dejar la puerta abierta y poner el felpudo.

    Valores de optimización del kernel¶

    El instalador en línea ajusta algunos parámetros del kernel. Con SKIP_KERNEL_OPTIMIZATIONS=1 no los toca, pero conviene saber qué se pierde: son ajustes pensados para que el servidor aguante muchas conexiones simultáneas sin que el sistema operativo se convierta en el cuello de botella.

    Parámetro Por defecto Fija Pandora Qué hace
    net.ipv4.tcp_syn_retries 5 3 Reintentos al enviar una petición de conexión TCP antes de darla por fallida.
    net.ipv4.tcp_synack_retries 5 3 Reintentos al recibir el acuse de recibo de una conexión TCP.
    net.ipv4.tcp_max_syn_backlog 1024 65536 Tamaño máximo de la cola de conexiones TCP pendientes de aceptar.
    net.core.wmem_max 124928 8388608 Buffer máximo de envío de datos por conexión de red.
    net.core.rmem_max 131071 8388608 Buffer máximo de recepción de datos por conexión de red.
    net.core.somaxconn 128 1024 Conexiones pendientes en la cola de escucha de sockets.
    net.core.optmem_max 20480 81920 Buffer máximo para opciones de socket.

    No los toques a mano salvo que sepas exactamente lo que haces. Deja SKIP_KERNEL_OPTIMIZATIONS=0 y que el instalador haga su trabajo.

    Instalación en una base de datos externa¶

    Si hay un servidor dedicado para la base de datos, el camino es: crear la base y el usuario, darle todos los permisos sobre esa base y instalar con SKIP_DATABASE_INSTALL=1 y los valores de conexión. Antes de instalar, prueba la conexión desde el futuro servidor de Pandora FMS. Descubrir el firewall a las dos de la mañana es evitable con cinco minutos de comprobación.

    env DBHOST='192.168.1.107' \
    DBNAME='pandora' \
    DBUSER='pandora' \
    DBPASS='CambieEstaClave' \
    DBPORT='3306' \
    SKIP_DATABASE_INSTALL=1 \
    bash -c "$(curl -fsSL https://pfms.me/deploy_pandora_one)"

    Restringe el usuario de la base de datos a la IP del servidor de Pandora FMS: si la contraseña se ve comprometida, que no sirva desde otro sitio.

    Instalación de base de datos externa para histórico¶

    Para desplegar una base de datos dedicada (incluido el histórico) existe un instalador en línea propio. Solo requiere curl y un sistema compatible:

    • EL9: Rocky Linux 9.x o RHEL 9.x.
    • EL10: Rocky Linux 10 o RHEL 10.
    • Ubuntu: 22.04.
    curl -fsSL https://pfms.me/db-deploy-el9 | bash

    En Ubuntu:

    curl -fsSL https://pfms.me/db-deploy-u2204 | bash

    Variables soportadas:

    Variable Descripción Por defecto

    MYVER Versión de MySQL (8.0 o 8.4) 84
    DBNAME Nombre de la base a crear pandora
    DBUSER Usuario de la base pandora
    DBPASS Contraseña del usuario Pandor4!
    DBROOTPASS Contraseña del usuario root Pandor4!
    SKIP_KERNEL_OPTIMIZATIONS Saltar optimizaciones de kernel 0

    MYVER=84 \

    DBUSER='pandora' \
    DBPASS='CambieEstaClave' \

    Instalación en una ruta diferente¶

    Para instalar el servidor en otra ruta, el instalador admite --destdir:

    ./pandora_server_installer --install --destdir <destdir>

    Después hay que configurar el arranque automático y el script de mantenimiento pandora_db en el cron:

    echo "\"<destdir>/usr/share/pandora_server/util/pandora_db\" \
 \"<destdir>/etc/pandora/pandora_server.conf\">/dev/null 2>&1"> /etc/cron.hourly/pandora_db

    Instalación con un usuario no privilegiado¶

    El instalador admite ejecutarse con un usuario sin privilegios:

    ./pandora_server_installer --install --no-root --destdir /opt/pandora

    Ese usuario debe tener permisos de escritura sobre la ruta indicada en --destdir.

    Valores para el instalador online¶

    Instalación en una ruta diferente¶

    El EndPoint puede instalarse íntegro en un directorio definido: en él quedan logs, configuración, binarios y páginas man.

    ./pandora_agent_installer --install /opt/pandora

    Instalación con un usuario no privilegiado¶

    También puede ejecutarse con un usuario distinto de root. Por ejemplo, con el usuario pandora:

    ./pandora_agent_installer --install /home/pandora pandora

    Al especificar un usuario personalizado, la instalación debe ir a una ubicación donde ese usuario tenga permisos de escritura. El usuario pandora viene desactivado por defecto: para usarlo hay que darle una shell válida en /etc/passwd.

    Instalación offline¶

    Para entornos sin conexión a internet. No está soportado en Ubuntu.

    Instalación offline del servidor¶

    Los sistemas compatibles son RHEL 9 / Rocky Linux 9 y RHEL 10 / Rocky Linux 10.

    Pasos:

    1. Disponer de una instancia con los requisitos de hardware y el sistema operativo soportado, limpia.
    2. Descargar el paquete offline para el sistema operativo desde el portal de soporte (disponible para versiones LTS y previas LTS).
    3. Subir el tarball al servidor.
    4. Descomprimirlo y ejecutar el instalador:
    tar xvzf <offline_package>.tar.gz
cd pandora_packages/
./pandora_deploy_enterprise_local_el9.sh

    En EL10 el script es pandora_deploy_enterprise_local_el10.sh. Cuando el proceso termina, se accede a la consola web con el usuario admin y la contraseña pandora.

    Instalación offline del satélite¶

    Instalación manual en Linux¶

    Instaladas las dependencias y descargado el paquete, se descomprime y se ejecuta el instalador:

    tar -xvzf pandorafms_satellite_server_X.XNG.XXX_x86_64.tar.gz
cd satellite_server/
./satellite_server_installer --install

    Después hay que editar /etc/pandora/satellite_server.conf y fijar el token server_ip con la dirección del Pandora FMS Server. El servicio se arranca con:

    systemctl start satellite_serverd

    El registro está en /var/log/satellite_server.log.

    Instalación en MS Windows¶

    El instalador (firmado desde la versión 762) incluye Nmap y Visual C++ Redistributable de MS Visual Studio 2015-2022. Se ejecuta con derechos de administrador, se introduce la licencia, se configura la dirección del servidor y las reglas de exploración, y se reinicia la máquina. Si las consultas WMI fallan, hay que ejecutar el servicio del Satellite Server con una cuenta de Administrador.

    Instalación offline del EndPoint¶

    El EndPoint se instala desde el paquete tarball, válido para cualquier Unix/Linux/macOS. No requiere compilación.

    tar xvzf pandorafms_one_agent_linux-latest.tar.gz
cd unix
./pandora_agent_installer --install
systemctl start pandora_agent_daemon

    Puede hacer falta instalar manualmente libnsl. Si se usan las fuentes (.src.tar.gz), hay dependencias adicionales de Perl, entre ellas YAML::Tiny y Thread::Semaphore. En FreeBSD y NetBSD la ubicación de ficheros y el script de arranque cambian: el agente queda en /usr/local/bin/pandora_agent, el script en /usr/local/etc/rc.d/pandora_agent, la configuración en /usr/local/etc/pandora/pandora_agent.conf y hay que añadir pandora_agent_enable="YES" a /etc/rc.conf.

    Tras la instalación hay que editar /etc/pandora/pandora_agent.conf para apuntar al servidor y, como recomendación, activar la configuración remota:

    sed -i "s/^remote_config.*$/remote_config 1/g" /etc/pandora/pandora_agent.conf
systemctl enable pandora_agent_daemon

    Windows desatendida¶

    El instalador de Windows soporta modo desatendido desde la versión 5.1 del EndPoint:

    "PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S

    Ruta personalizada:

    "PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S /D=C:\PFMS_agent

    Parámetros que se escriben en la configuración del EndPoint: --ip (server_ip), --group (group), --alias (agent_alias) y --remote_config (remote_config). Ejemplo:

    "PandoraFMS_One_Agent_Windows-lts.x86_64.exe" /S --ip 192.168.0.59 --group Applications --alias Mifunne --remote_config 1

    Verificación¶

    Terminada la instalación, abre la consola en http://<servidor>/pandora_console/ y confirma que carga la pantalla de acceso. El usuario inicial es admin con la contraseña pandora.

    Warning

    Cambia la contraseña en el primer acceso. Y si has instalado con usuario personalizado o ruta distinta, comprueba el arranque de los servicios antes de darte por satisfecho; el fallo que no se revisa hoy se convierte en incidencia el lunes.

    Desinstalación¶

    Los instaladores no se copian durante la instalación, así que no se puede recurrir a su --uninstall a posteriori. La desinstalación hay que hacerla a mano: estos son los ficheros y carpetas que deja cada componente y los comandos para retirarlos (como root). Si varios componentes conviven en la misma máquina, no borres los directorios compartidos hasta retirarlos todos.

    Servidor¶

    • Binarios en /usr/bin: pandora_server, pandora_exec, pandora_supervisor, pandora_db, pandora_ha, pandora_manage, pandora_revent, pandora_encrypt_db, braa, pandorafsnmp, pandorawmic, pandora_iot_server, pandora_netflow_server, tentacle_server, tentacle_client, clean_pandora_server, clean_tentacle_serverd y clean_tentacle_rmm.
    • Librerías y utilidades: /usr/share/pandora_server.
    • Servicios: /etc/systemd/system/pandora_server.service, pandora_ha.service, tentacle_serverd.service, tentacle_rmm.service, pandora_iot_server.service y pandora_netflow_server.service.
    • Tareas y rotación: /etc/cron.hourly/pandora_db y /etc/logrotate.d/pandora_server.
    • Configuración: /etc/pandora/pandora_server.conf, pandora_server.env, pandora_server_extra.env, /etc/pandora/conf.d y /etc/tentacle.
    • Datos, logs y PID: /var/spool/pandora, /var/log/pandora y /var/run/pandora_supervisor.pid.
    systemctl stop pandora_server pandora_ha tentacle_serverd tentacle_rmm \
  pandora_iot_server pandora_netflow_server
systemctl disable pandora_server pandora_ha tentacle_serverd tentacle_rmm \
  pandora_iot_server pandora_netflow_server
rm -f /etc/systemd/system/{pandora_server,pandora_ha,tentacle_serverd,tentacle_rmm,pandora_iot_server,pandora_netflow_server}.service
systemctl daemon-reload
rm -f /usr/bin/{pandora_server,pandora_exec,pandora_supervisor,pandora_db,pandora_ha,pandora_manage,pandora_revent,pandora_encrypt_db,braa,pandorafsnmp,pandorawmic,pandora_iot_server,pandora_netflow_server,tentacle_server,tentacle_client,clean_pandora_server,clean_tentacle_serverd,clean_tentacle_rmm}
rm -Rf /usr/share/pandora_server
rm -f /etc/cron.hourly/pandora_db /etc/logrotate.d/pandora_server

    Y, si no queda ningún otro componente, la configuración y los datos compartidos:

    rm -Rf /etc/pandora /etc/tentacle /var/spool/pandora /var/log/pandora

    Consola¶

    Depende de cómo se instaló:

    • RPM (RHEL / Rocky Linux): se retira con el gestor de paquetes.
    dnf remove pandorafms_console
    • Tarball (Ubuntu): se copió a /var/www/html/pandora_console y dejó su rotación de logs.
    rm -Rf /var/www/html/pandora_console
rm -f /etc/logrotate.d/pandora_console

    La consola comparte con el servidor el directorio /var/spool/pandora/data_in (collections, conf, md5, netflow): no lo borres si hay servidor. No toca la base de datos; eso va aparte.

    Base de datos¶

    La instalación crea la base pandora y el usuario pandora. Si MySQL o Percona solo daban servicio a Pandora FMS:

    systemctl stop mysqld
mysql -u root -p -e "DROP DATABASE pandora; DROP USER 'pandora'@'localhost';"
dnf remove 'Percona-Server*'        # RHEL/Rocky; en Ubuntu, apt remove percona-server-server o mysql-server
rm -Rf /var/lib/mysql /etc/my.cnf /etc/my.cnf.d

    Si la base está en otro servidor o alberga datos de otras aplicaciones, limita la operación a DROP DATABASE y DROP USER.

    Satélite¶

    • Binarios en /usr/bin: satellite_server, tentacle_client, pandorafsnmp, wmic, pandorawmic y clean_satellite_serverd.
    • Configuración: /etc/pandora/satellite_server.conf, satellite_server.env, satellite_server_extra.env, /etc/pandora/satellite_plugins y el directorio de agentes /etc/pandora/conf.
    • Arranque: /etc/init.d/satellite_serverd (con su enlace en /etc/rc.d) y /etc/systemd/system/satellite_serverd.service.
    • Rotación, logs y temporales: /etc/logrotate.d/pandora_satellite, /var/log/satellite_server.log y /var/spool/pandora/tmp/satellite_server.
    systemctl stop satellite_serverd
systemctl disable satellite_serverd
rm -f /etc/systemd/system/satellite_serverd.service
systemctl daemon-reload
rm -f /etc/init.d/satellite_serverd
rm -f /etc/rc.d/rc?.d/S90satellite_server
rm -f /usr/bin/{satellite_server,tentacle_client,pandorafsnmp,wmic,pandorawmic,clean_satellite_serverd}
rm -Rf /etc/pandora/satellite_plugins /etc/pandora/conf /var/spool/pandora/tmp/satellite_server
rm -f /etc/pandora/satellite_server.conf /etc/pandora/satellite_server.env /etc/pandora/satellite_server_extra.env
rm -f /etc/logrotate.d/pandora_satellite /var/log/satellite_server.log

    El directorio /opt/pandorafms/perl5 del satélite es compartido con otros componentes: bórralo solo si no queda ninguno instalado.

    EndPoint¶

    En Linux y Unix deja:

    • Binarios en /usr/bin: pandora_agent, pandora_agent_exec, pandora_revent, tentacle_client y clean_pandora_agent_daemon.
    • Home del agente: /usr/share/pandora_agent (plugins, collections, commands, ref).
    • Configuración: /etc/pandora/pandora_agent.conf y pandora_agent.env.
    • Arranque: /etc/systemd/system/pandora_agent_daemon.service (o el script de /etc/init.d).
    • Rotación, logs y páginas man: /etc/logrotate.d/pandora_agent, /var/log/pandora/pandora_agent.log, /usr/share/man/man1/pandora_agent.1.gz y tentacle_client.1.gz.
    systemctl stop pandora_agent_daemon
systemctl disable pandora_agent_daemon
rm -f /etc/systemd/system/pandora_agent_daemon.service
systemctl daemon-reload
rm -f /usr/bin/{pandora_agent,pandora_agent_exec,pandora_revent,tentacle_client,clean_pandora_agent_daemon}
rm -Rf /usr/share/pandora_agent
rm -f /etc/pandora/pandora_agent.conf /etc/pandora/pandora_agent.env
rm -f /etc/logrotate.d/pandora_agent /var/log/pandora/pandora_agent.log
rm -f /usr/share/man/man1/pandora_agent.1.gz /usr/share/man/man1/tentacle_client.1.gz

    Si hay servidor o satélite en la misma máquina, no borres /etc/pandora ni /var/spool/pandora completos.

    MS Windows sí incluye desinstalador. De forma desatendida:

    "%ProgramFiles%\pandora_agent\uninst.exe" /S

    O desde el binario del agente:

    pandoraagent.exe --uninstall
