    Referencia completa de configuración del servidor¶

    Referencia técnica en bruto de pandora_server.conf: todos los tokens que reconoce el servidor, con su valor por defecto real. Se consulta, no se lee de corrido; cualquier otro capítulo enlaza aquí cuando necesita referirse a un parámetro del servidor.

    Introducción¶

    pandora_server.conf es el único fichero de configuración del servidor Pandora FMS. Su ruta es configurable en la instalación; por defecto, /etc/pandora/pandora_server.conf. El formato es el habitual de la casa: un token por línea, valor tras un espacio, y # para comentar una línea entera o para dejar un token de ejemplo desactivado.

    Un cambio en el fichero no se aplica en caliente: hay que reiniciar el servicio.

    systemctl restart pandora_server

    La excepción es la configuración remota: con remote_config 1 (ver «Configuración remota, Tentacle y sincronización», más abajo), el fichero entero se puede editar desde la consola web. El servidor comprueba cada poco si hay cambios; cuando los encuentra, genera un evento de reinicio, recarga la configuración y se reinicia solo.

    Los tokens exclusivos de los Servidores satélite (pandora_satellite.conf) no están en esta referencia: tienen su propio capítulo, 6.2 · Servidores satélite, que enlaza aquí para lo que comparten con el servidor principal.

    El «valor por defecto» de cada tabla es el que aplica el propio servidor cuando el token no aparece en el fichero. La plantilla de ejemplo que trae el paquete (pandora_server.conf.new) no siempre coincide con ese valor: cuando difiere de forma relevante, la tabla lo indica de forma explícita, nunca como si fuera «el» valor por defecto.

    2. Activación de servidores y número de hilos¶

    Cada servidor interno tiene un interruptor (0/1) y, si aplica, un número de hilos propio. «Por defecto» es, como en el resto de este capítulo, el valor que asume el propio servidor cuando el token no aparece en el fichero; la plantilla de la instalación (pandora_server.conf.new) puede traer un valor distinto para ese mismo token. Por ejemplo, discoveryserver viene activado en la plantilla aunque el valor interno por defecto es 0, y a la inversa, snmpconsole viene desactivado en la plantilla aunque el valor interno por defecto es 1.

    Servidor Token de activación Por defecto Token de hilos Por defecto
    Datos (XML) dataserver 1 dataserver_threads 2
    Red (TCP, comandos remotos, WMI; ICMP y SNMP si el de alto rendimiento está desactivado) networkserver 1 network_threads 3
    Red de alto rendimiento (ICMP con fping y SNMP con pandorafsnmp, en lote) networkhpserver 1 networkhpserver_threads 4
    Consola SNMP snmpconsole 1 snmpconsole_threads 1
    SNMP (heredado: ya no arranca servidor propio; solo activa la comprobación de que snmptrapd sigue recibiendo traps) snmpserver 0 snmp_threads 3
    ICMP (heredado: sin efecto; lo ejecuta el servidor de red de alto rendimiento) icmpserver 0 icmp_threads 3
    WMI (heredado: sin efecto; lo ejecuta el servidor de red) wmiserver 1 wmi_threads 2
    Plugin (heredado: sin efecto; lo ejecuta el servidor Heavy) pluginserver 1 plugin_threads 2
    Discovery discoveryserver 0 discovery_threads 2
    Predicción (heredado: sin efecto; lo ejecuta el servidor de red) predictionserver 1 prediction_threads 1
    Exportación (heredado: sin efecto; lo ejecuta el servidor Heavy) exportserver 1 export_threads 1
    Inventario (heredado: sin efecto; lo ejecuta el servidor Heavy) inventoryserver 1 inventory_threads 2
    Web (heredado: sin efecto; lo ejecuta el servidor de red) webserver 1 web_threads 1

    Log (alertas de log) logserver 0 logserver_threads 1

    Syslog syslogserver 0 syslog_threads 4
    WUX (navegación sintética) wuxserver 0 sin hilos propios —
    RMM rmmserver 0 rmmserver_threads 1

    Netflow netflowserver 0 netflowserver_threads 1
    Recon (no es un servidor propio: interruptor alternativo del Discovery Server, basta con que reconserver o discoveryserver estén a 1; recon_threads sí tiene efecto, se usa el mayor entre este valor y discovery_threads) reconserver sin valor por defecto en el código (se comporta como desactivado si no aparece) recon_threads 2

    El porqué de este reparto (por qué desaparecieron tantos servidores propios y qué hace cada servidor real hoy) está en Compatibilidad y migración a la nueva arquitectura de servidores.

    13. Command Center¶

    pandora_server.conf no tiene un bloque de tokens propio para el Command Center: la relación entre un servidor y el Command Center se gestiona a nivel de consola (alta del nodo, sincronización de políticas) y de base de datos, no de fichero de configuración del servidor.

    Token Qué hace Valor por defecto
    node_metaconsole Marca si la base de datos a la que apunta este servidor es la de un nodo gestionado por un Command Center. No es una opción que se edite a mano en el fichero. 0

    Ver 6.3 · Command Center para el procedimiento de alta y gestión de nodos.
